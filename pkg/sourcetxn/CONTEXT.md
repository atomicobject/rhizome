# Source transactions

`sourcetxn` owns journaled vault source publication. Both ontology edits and validation repairs use this engine. It has no dependency on ontology, validate, or a concrete runtime.

Callers hold a real `indexlock.Lease` for the canonical vault. `Open` performs discovery, policy, quarantine classification and authorized recovery once before planning. `SourceEditor` refuses unsettled native namespace work and leaves durably settled terminal journals to their owner. `RepairOwner` owns repair publication and strict completion checks; `RuntimeRecoveryOwner` stabilizes source before runtime construction while preserving later edits to committed source. The constructor copies its hook schedule and read-only policy inputs.

The writer accepts relative changes and original/final snapshots. It derives absolute paths and returns opaque transaction and completion handles. `Publish`, `Abort`, `Verify` and `Complete` reject foreign, absent, closed or invalid-state handles. A successful publication cannot be rolled back through `Abort`. `Writer.Apply` is the ontology convenience path through the same coordinator. No exported phase API accepts a caller-constructed journal or prepared state. Reporting snapshots are detached copies and grant no mutation authority. Validation owns refresh and postcheck after publication; source-only intents have no callback obligations.

Failed live commits undo only their installed prefix and then release the full artifact set. Publication reports whether replacement occurred even when subsequent directory synchronization fails, so failure recovery includes every possibly published entry. If the generic commit marker may have been published, the writer instead stops for recovery without rollback; a possibly surviving terminal decision can never accompany a partially rolled-back source set. A rollback that cannot finish is a recovery-required failure, never a successful conflict outcome. Source and receipt parent directories are created only after every admission and original-source witness passes.

Repair journal v1 and native namespace v2 keep their existing wire fields, membership, artifact ownership, Git decisions, receipts, rollback preflight and terminal cleanup tombstones. Source-only intents add the optional `source` discriminator inside v1. Backup bytes are copied and synced before a single atomic replacement; source paths do not disappear between backup and installation. External file descriptors can still write concurrently after the final witness check. Arbitrary external writers cannot be serialized by Rhizome's lease.

Legacy `.rhizome/edit-journal/*.json` is recovery input only. Valid prepared all-new outcomes finish publication, partial outcomes roll back, and committed outcomes authorize cleanup while preserving later source edits. Recovery rechecks witnesses before each mutation and uses atomic replacement. No legacy source writer remains.

Unrecoverable repair or legacy evidence stays with its artifacts in place. Durable manifests under `.rhizome/source-quarantine` retain its diagnostic, affected paths and artifact locations. Common admission blocks those paths, including normalized Unicode aliases; unreadable or untrusted path authority blocks the whole vault. Read-only pending evidence exposes quarantine state. Recovery reclassifies surviving evidence against its actual witnesses on every `Open`; it does not treat quarantine as permanent proof of damage. Under the writer lease, recovery removes empty or temporary-manifest-only directories from interrupted unpublished preparation and reconciles quarantine records whose evidence and artifacts are gone. Unsafe surviving evidence requires review; no quarantine clear command is implied.

An ordinary prepared transaction with an unknown unowned artifact may release its source only when every original source and receipt witness matches, and it has no native namespace, Git or case-rename obligation. A durable `SOURCE_SETTLED` proof binds the exact serialized manifest bytes before that admission change, including fields unknown to this release. The journal and unknown artifact bytes remain diagnostic evidence. Every later publication, rollback and cleanup path treats that proof as having zero mutation authority, including after legitimate later edits. Invalid proofs retain a barrier over the recorded paths and are never overwritten by inferred replacement proofs. An identical retry whose journal name is retained by valid settled evidence receives a fresh attempt ID and preserves the earlier evidence. Ambiguous sources or unresolved native ownership stay blocked.

The test suite retains legacy recovery/tamper fixtures and drives the surviving repair execution hooks through journal publication, every source install and every cleanup boundary. Windows publication uses write-through moves; file witnesses reject hard links using the platform's actual link count.
