## pkg/notemeta

Canonical raw-note fact indexing for provider-projected vault notes.

- **Entry points**: `Indexer.EnsureIndexed` / `SyncPaths` build durable note metadata rows; `Indexer.BuildPathDelta` derives the complete incremental source delta without writing; `Indexer.BuildPublishedMetadataDelta` publishes one full-index ownership-routed set without rediscovery; `Indexer.DiscoverDirtyPaths` performs one note-only comparison scan; `Indexer.LoadNoteSourceSnapshots` and `Indexer.BuildNoteSourceSnapshots` expose provider-current canonical inputs. Production composition must inject and validate an `Indexer`; no package fallback constructs a runtime. `BuildNoteSourceFacts` is the intentional non-provider exception: it owns a direct filesystem reader (no caller/cache seam) and omits eager link resolution for consumers that own one sealed structured-link scan.
- **Source contract**: `NoteSourceSnapshot` carries vault-relative path, format identity, copied raw bytes, decoded content when valid, projection provenance, diagnostics, document base, fragment targets, search regions, hash, mtime, title, raw properties, tags, aliases, and normally resolved links. Raw source and derived evidence remain separate. `BuildNoteSourceFacts` is the explicit compatibility exception: its `Links` remain empty.
- **Full snapshot coherence**: `EnsureIndexed` captures contents once for both freshness and projection. Direct file stats and provider projection run only on rebuild; unchanged state retains its generation without either. Snapshot hashes derive from the projected sources. Indexer version 12 rebuilds older generations that could publish a hash from different bytes than their rows.
- **Persistence provenance**: Intel v65 stores generic ordered projection diagnostics, search regions, and fragment targets alongside the existing source identity and stale/current/fatal state. Snapshot and delta publication replace all collections in the same write transaction. The fatal summary columns are derived compatibility data; `note_projection_diagnostics` is the diagnostic truth source. Provider-aware reads reject stale/fatal/mismatched rows without deleting raw identity.
- **Ownership-transition freshness**: the cross-domain transition store deletes `note_metadata_state` when it changes source ownership, so legacy XOR freshness cannot no-op over cleared derived rows. It deletes or replaces every touched path in that same transaction. Exact navigation may therefore use retained `current` projections for untouched requested paths while broad inventory remains globally gated. Provider-aware orchestration must publish metadata before acknowledging structural convergence. `CapturePublishedBaseline` preserves pre-transition database rows, aliases, paths, and hashes for scoped publication even when the control removes prior state.
- **Published full-index inputs**: Every projectable, ownership-selected note reaches `BuildPublishedMetadataDelta` through explicit canonical paths and optionally sealed authored sources from the ownership handoff. Descriptor-only providers retain source-root identity and stale projection state without publishing derived metadata, graph, search, or ontology evidence. A current complete published state returns no delta and keeps its existing `LoadedAt`, so downstream ontology readiness stays on the same generation. There is no state-only publication API.
- **Producer contract**: construct snapshots with vault-root-relative paths. Anchor ingestion accepts only this source contract; it no longer recomputes snapshots from raw path/content arguments.
- **Key invariant**: note-file freshness and raw provider facts, including diagnostics, unresolved links, aliases, fragment targets, and search regions, live here. URI references use their closed provider-parsed input and optional document base; they do not enter Markdown resolution. Normal `Indexer` snapshot and delta derivation consume the selected projection only. Dirty discovery compares authored source identity without projecting. Bootstrap tombstones materialized stale rows even when readiness is false; path additions, deletions, and alias-set changes rederive affected inbound links.
- **Graph read contract**: `LoadPersistedGraphSnapshot` maps indexed note/tag/link rows directly into `obsidian.GraphSnapshot`, the shared input for graph algorithms and backlink derivation. `LoadReadyPersistedGraphSnapshot` is the bounded variant for callers that intentionally trust persisted readiness; it does not prove live note freshness and must not enumerate/read notes. Do not synthesize Markdown to adapt persisted graph rows back into `NoteReader`.

- **Scoped sealed publication**: `BuildPublishedPathMetadataDeltaFromPreparation` consumes sealed changed sources and the opaque pre-transition baseline without an authored-source reader. Unchanged topology restores captured incoming link facts from unchanged sources and uses the captured path/alias inventory because the global SQL lookup barrier is intentionally pending; additions, deletions, aliases, provider drift, and bootstrap explicitly request complete publication.

- **Incremental alias resolution**: reuse one persisted alias snapshot for topology comparison and delta cache population; bulk-build the complete candidate and alias-owner union while retaining duplicate claimant ambiguity.

- Nested metadata objects retain empty string keys through canonical projection and detached legacy frontmatter conversion. Only root field names must be nonempty; indexer version 11 forces reindexing for the broadened acceptance.
