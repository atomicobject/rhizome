# Diagnostics files

`pkg/diagnostics` owns bounded operational evidence under a vault's `.rhizome/diagnostics`. It depends on file primitives, not indexing, runtime bootstrap, SQLite, or user configuration. Callers own operation meaning, safe operational facts, and the final report after their work and cleanup drain.

## Contract

- `Open` creates a recorder with a random process identity. `NewOperation`, `WithOperation`, `WithRecorder`, and `Propagate` carry operation and trace identity without importing another context's cancellation or unrelated values.
- `Event`, `Logger`, and `StdlogWriter` persist structured events. WARN and ERROR mirror directly to the configured stderr writer, even when persistence is disabled or its level filter excludes them. `EventQuiet` suppresses only that event's console mirror when a protocol response owns its error output; persisted severity and separate storage warnings remain intact. `SetStderr` changes the console destination under the recorder lock during a runtime output handoff and returns an idempotent restore function. No diagnostic output goes to stdout. Sink failures never recurse through logging.
- `PublishReport` returns an advisory storage error. Applications preserve their actual operation outcome and report storage failure separately. A report must name a completed outcome: success, error, canceled, preempted, or skipped. Skipped capabilities retain a reason such as disabled or not requested.
- `LoadOptions` decodes only the `diagnostics` subtree of repository `.rhizome/config.yml`. Exported `Config` supports strict repository config readers. It never reads user configuration, provider keys, or initializes indexes. Defaults are seven days, 64 MiB of recognized artifact bytes, 4 MiB per runtime event segment, 64 KiB per CLI event segment, 32 KiB per event record, and 1 MiB per report. `enabled: false` disables persistence and remains effective when another diagnostics setting is invalid. `level` filters persisted events.

## Files and lifetime

Events use `events/<UTC-date>-<process-id>-<segment>-<reserved-capacity>.jsonl`. Every process exclusively owns its segment and holds an OS lock until it closes or dies. Segment capacity is admitted under the cross-process `.guard` lock before creation. Quota scans count locked segments at their entire reserved capacity, so appends require no directory scan or shared guard. Event admissions leave two report-sized copies and two artifact slots available for atomic latest-report publication. A full segment or changed UTC date causes rotation.

Clean close syncs the segment and acquires the guard, then unlocks, closes, and renames it to a zero-capacity filename. That marker identifies immutable history, whose actual size and retention time are read from file metadata without opening it or probing an ownership lock. Closing before the rename also supports Windows handles that do not share deletion. Positive-capacity names, including legacy closed segments and crashed writers, still receive ownership probes; an unlocked segment counts only its actual bytes. A busy guard can postpone finalization without preventing close or crash reclamation. No reservation ledger or directory cache is required. Admission scans remain bounded and sort history only when quota pressure needs oldest-first eviction.

Reports use `reports/<UTC-finish-time>-<operation-id>.json`. Publication writes a uniquely named temporary file with mode 0600, syncs and closes it, then atomically replaces the destination through `fileio.Replace`. The guard serializes publication and pruning. Terminal report publication and segment admission retry a busy guard for at most two seconds, independently of caller cancellation, so ordinary competing processes retain start and terminal evidence. Already admitted event appends remain free of the shared guard. Duplicate history destinations are rejected before pruning or changing latest. A new latest index report publishes atomically before its history copy. Replacing an existing latest reserves one additional artifact slot and the greater of the new report size or twice that size minus the old latest size, covering both temporary-copy peaks without retaining the replaced copy during history publication. A first latest reserves two copies and two slots; an older completion publishes history only. If history publication fails after latest succeeds, the advisory error is returned while the new latest remains readable, including by operation ID. Atomic namespace publication is guaranteed; full power-loss durability of directory entries is platform dependent.

`latest-index.json` is a complete protected report copy of the latest finished full-index attempt, including failures or cancellation. Watcher/projection/request reports cannot replace it. A completion with an older finish time cannot overwrite a newer report. Ordinary history may disappear while this copy stays readable, including through `ReadReport` by its operation ID.

Retention removes recognized, unlocked history whose modification time is strictly older than the current clock minus the configured number of calendar days. Pruning runs on segment admission and report publication. The latest report and locked segments are exempt. Byte or artifact-count pressure can evict unlocked history sooner. The count limit is 4096 artifacts; metadata scans stop after 16384 directory entries and at most 8192 recognized artifacts. Unknown files, nonregular entries, and symlinks are preserved and excluded from the managed budget. Legacy log files are untouched. The byte cap covers recognized logical file content, not filesystem allocation overhead or foreign files. Concurrent writers use the same configured cap; lowering it cannot retroactively shrink locked reservations or the protected latest report, and new admissions fail until enough space becomes reclaimable.

If a guard is busy, a disk write fails, or a quota cannot be met, the caller's work continues. Events are dropped and a direct stderr warning is limited to once per minute per recorder. The next successful event carries the accumulated drop count. Report errors remain explicit. Closing syncs and closes the segment; WARN/ERROR and recognized operation/index/job/runtime terminal events sync immediately. Abrupt termination may leave an unterminated final JSONL line, which readers report without discarding earlier valid evidence. Abandoned recognized publication temporaries are removed under the guard.

## Bounds and source safety

Messages, identities, attribute count, attribute strings, retained slog attributes, event serialization, report input, and metadata scans have fixed bounds. There is no asynchronous queue. Attributes accept bounded scalars only, with recognized credential/payload keys redacted. Metrics JSON is byte bounded, rejects nesting beyond 32 levels, and preserves producer-owned arrays, maps, numeric aggregates, and order. Recognized sensitive keys and credential strings are redacted. The typed metrics producer owns its own cardinality and sample bounds. Callers must emit curated operational facts and error categories; redaction cannot make arbitrary source text, provider response bodies, configuration dumps, credentials, or prompts safe to record. The generic standard-log adapter preserves bounded legacy text, so integrations needing stricter privacy should use their policy adapter.

## Offline readers

`ReadLatest`, `ReadReport`, `ReadReports`, and `ReadEvents` require only the vault path and files. They never start a runtime or open a database. JSON schema version is one. Readers skip unknown files and symlinks, report malformed/unsupported records, and use deletion-sharing `fileio.OpenRead` on Windows. Missing histories return empty results with explicit unknown-coverage warnings.

History reads default to 100 returned records and 4 MiB of examined bytes, capped at 1000 records and 16 MiB. Reports are returned newest first. Event files are examined by newest modification time with a deterministic filename tie, reading a bounded tail of each snapshot. Each file receives the remaining byte budget divided by remaining candidate files, with a 256 KiB minimum tail allowance capped by remaining bytes. Small files carry unused bytes forward. This preserves room for nearby processes and avoids shrinking dense-history tails below a useful record window. Earlier files are not revisited, so some budget may remain unused and older files may remain unexamined. Selected events are returned in chronological order. An artificial byte-budget boundary discards its initial partial record and reports truncation, while actual malformed or unfinished records still report corruption. Byte budgets bound examined tails; omitted file regions remain unknown coverage. Coverage gives examined file/byte counts, the time range of decoded records, warnings, and truncation. It does not claim capture completeness. A requested start earlier than examined evidence explicitly reports that earlier coverage is unknown. Latest is independent of history filters and retention windows. Windows ownership locks use an explicitly unlocked sentinel byte beyond all file data, so they do not deny live readers access to event bytes.

## Verification

Focused tests exercise operation identity, disabled persistence with visible warnings, retention and latest preservation, quota reservations, unknown files and symlinks, corruption/partial records, filter/read bounds, sensitive attributes, large typed metrics, concurrent recorder close, and subprocess writers sharing one budget. Synchronized subprocess tests retain every start and report from twelve short commands against fresh, 2,300-file, and 4,000-file histories, without caller retries. CLI reservation coverage keeps two runtime and fourteen CLI recorders active while preserving 2 MiB of retained history. `BenchmarkEventPersistence` compares disabled and enabled low-volume event persistence on the same record; retained-history benchmarks measure admission and publication against fixed closed-segment fixtures.
