# Update test ownership

- ResolveInvocation owns executable location and pin gating. BuildUpdatePlan owns target selection. Run owns prepare, commit order, and truthful partial results.
- Update feed and manifest overrides use the invocation's `config.Env` carried in context. An explicit `Options.WorkDir` keeps its authority; when omitted, `Run` uses that environment's working directory and fails if it is unavailable. A supplied empty environment never falls back to host configuration. OS app-launch tools retain their process-owned environment; do not serialize arbitrary lookup functions into child processes.
- Exercise trust checks with HTTP and archive fixtures. Keep process tests for delegation, standard streams, PID, and exit behavior at the command boundary.
- Keep failure injection where production code owns the observable ordering. Do not replace it with a fake that supplies the expected sequence.
- ResolveInvocation follows executable symlinks through `pkg/app/appbundle` before classifying an app-owned global installation. A detected bundle with unreadable metadata fails closed, so neither a bundled executable nor its command-line symlink becomes a replacement target.
- Repository replacement targets must stay outside app bundles and must not name the app-owned invoking entry or `/usr/local/bin/rzm`, including when the bridge invokes the bundled binary directly. Resolve target parent directories, including existing ancestors of missing directories, without following the final symlink; replacing a separate repository-local symlink is safe because rename preserves its referent.
- BuildUpdatePlan omits file-replacement global targets for application bundles. Default and latest modes run the app-owned global step separately, including outside pinned repositories; pinned and set-version modes never hand off. Release apps read `RZM_DESKTOP_UPDATE_FEED` (default GitHub `latest.json`), compare it with `CFBundleShortVersionString`, launch `open -n -a <bundle> --args --install-update`, and wait at most five minutes for a newer on-disk version. Dev apps report `make desktop-install-dev` instead.
- Application and repository outcomes are independent: an app failure must not suppress repository installation or its pin prompt, and a repository failure must retain the app outcome. Failed app hand-offs return a global target with `BinaryUpdated: false` and the release download URL; completed app changes use the ordinary global result summary. The app owns download verification and replacement inside its bundle.
- CompareVersions accepts exact major/minor/patch versions with an optional leading `v` and semantic prerelease ordering. Unparsable versions are not comparable. Keep comparator tests and the fake-bundle symlink matrix beside the implementation; seams must keep tests from launching a real app or waiting five minutes.
