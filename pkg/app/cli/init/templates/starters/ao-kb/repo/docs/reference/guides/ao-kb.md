# AO KB knowledge workspace

The optional `ao-kb` starter presents an existing AO KB's Markdown knowledge in Rhizome and compiles the selected product's model into read-only bindings. The AO KB root must be the vault root, at schemaVersion 8. It installs Assertion, Source, Concept, Artifact, and ConflictRegistry/ConflictEntry types in the Knowledge group, a workspace with Attention, Concepts, Assertions, and Knowledge trace, assertion and source presentations, claim-to-source, reverse-impact, concept-evidence, and artifact-evidence recipes, and the binding compiler. The selected model is indexed read-only, with native evidence links and per-file sync observations.

## Setup

Run from the vault root, using the repository's Rhizome launcher in place of `rzm`. The `ao-kb-setup` skill follows the same sequence.

1. `rzm init --add-addon ao-kb` for an existing Rhizome repository, or `rzm init --addons ao-kb` on first init. Init installs static assets, the binding compiler, and `.rhizome/source-ownership.yml` before anything is compiled or indexed, so AO's files are protected from the start. It runs no project-specific compiler. `rzm init --check` checks managed files only.
2. Module actions run only in a trusted repository: run `rzm trust` once in the repository. Without it, `node .rhizome/modules/ao-kb/scripts/check.mjs` prints the same check. The Knowledge views use one other action, `ao-kb/read-evidence`, only to read a raw source file or `.kb/index/kb-weights.json` when the file is gitignored; without trust such a passage shows as unresolved and the saved analysis as unavailable, never as a clean result.
3. `rzm ao-kb check` (also `rzm module ao-kb check`) is read-only and needs Node. It returns JSON with `starterInstalled`, `bindingsReady`, `indexReady`, and named checks whose status is `ok`, `warning`, `error`, `pending`, or `unsupported`. Knowledge rows cover the AO root (`.kb/config/vault.md`; schemaVersion 8 is the inspected baseline, and older versions must upgrade AO KB first), product mode, toolkit stamp, note includes, source ownership, knowledge bindings, sequence-shaped frontmatter connections, and saved analysis. Model rows come from the compiler's own check: dependencies (`uv` on PATH supplies Python and AO's pinned kb-site package), model bindings, model index, and whether every compiled source is declared AO-owned. Successful execution alone does not mean setup is ready.
4. Include AO Markdown under `assertions/**`, `sources/**`, `concepts/**`, and `artifacts/**`, plus the exact `.kb/curation/_conflicts.md`: discovery skips hidden directories unless an include names the path, so a broad `**/*.md` does not reach the registry. Append missing paths and keep unrelated rules. The check reads simple include lists and reports uncertainty for other YAML forms. Raw `sources/_raw/**` files support evidence display but are never typed Source records.
5. Make sure source ownership is `ok` before refreshing. Add any AO-authored location outside the standard layout to `.rhizome/source-ownership.yml`.
6. `rzm ao-kb refresh-bindings --product <slug>` for a KB with product roots (the product is required and persisted in `.rhizome/modules/ao-kb/bindings/selection.json`), or `rzm ao-kb refresh-bindings --single true` for a single-product KB. Later refreshes reuse the selection; `--toolkit <absolute path to packages/kb-site>` selects a local AO checkout at the pinned revision. Node first generates `.rhizome/modules/ao-kb/ontology/ao-knowledge.generated.graphql`; the Python model stage writes `ontology/ao-model.generated.graphql`, generated node views, and `bindings/manifest.json`, which may be committed as derived artifacts, and never changes AO files. A failed knowledge stage keeps its previous generation. A failed model stage keeps the current knowledge admission and previous model generation, reporting model setup incomplete. Rerun the check: model bindings and model source ownership must be `ok`.
7. Add the exact model source paths listed in the manifest to note includes, preserving existing rules. If includes change, refresh again so the configuration fingerprint matches. Run `node .rhizome/modules/ao-kb/bindings/cli.mjs index`, which runs real indexing and verifies model record counts, then `rzm agent ontology-query --query '{ assertion(first: 1) { title } }'`. An empty response is expected only for an empty KB. The final check must report both bindings and index ready.

Report **starter installed**, **bindings ready**, and **index ready** separately. Use the check's computed `bindingsReady`, not the saved manifest's status, which only records the last successful refresh. Neither managed-file checks nor prerequisites alone certify a usable projection.

## Release boundaries

`.rhizome/source-ownership.yml` declares AO KB's standard layout AO-owned: `.kb/`, `assertions/`, `sources/`, `concepts/`, `artifacts/`, `decisions.md`, `_moc.md`, `MOCs/`, `_improvements/`, and the same paths under every `products/<slug>/` root, whether or not that product is selected. Rhizome refuses native edits to those files, including field edits, body edits, moves, link repairs, and edits staged before the declaration changed, and its editor shows the declared reason. This is an application boundary, not a file permission: AO skills and external editors still change the files, and Rhizome does not claim their edits passed AO validation. Add any other AO-authored location your KB uses; never add unrelated notes. Re-running init keeps your edits. Removing the add-on keeps the declaration; delete it explicitly to end the protection. Change knowledge through AO's `/ao-kb:process`, `/ao-kb:curate`, and `/ao-kb:suggest` skills. The setup skill never invokes AO ingestion, curation, generation, or publishing.

Static knowledge types remain installed so views validate before setup. Before the first refresh, multi-product knowledge typing is unscoped and check reports incomplete setup with `rzm ao-kb refresh-bindings --product <slug>`. Generated admission then scopes knowledge and model evidence to that product. AO keeps knowledge at account `<type>/<slug>/`, or `artifacts/<phase>/<slug>/` and `artifacts/<slug>/`, rather than under product roots. Registered product folders determine scope; other notes select products through `products: [alpha]` or `["*"]`. Missing/null/empty-string `products` means shared, while `products: []` reaches no product. Unselected notes remain available to ordinary source search without satisfying selected AO evidence IDs.

Install `uv` on PATH for the model adapter. Knowledge admission needs Node alone. Ordinary note/row edits need normal indexing; configuration/metamodel/selection changes require refresh. Every check reruns the adapter offline to detect source compatibility errors separately from stale configuration. Prefix matchers cannot reproduce AO's `placed()` depth restriction for nested assertions/concepts. Keep those notes directly under their documented type or product folder. Adding or renaming an artifact phase folder changes admission scope and requires refresh; check reports `ao_artifact_phases_stale` with the changed folder set.

The optional toolkit stamp is `.kb/config/manifest.json`'s `toolkit` block (`version`, optional `commit`, `via`, `at`). It records the AO plugin that last scaffolded or synced the KB, not the version of every file or compatibility with the latest toolkit. Missing stamps are reported as unknown template age. The inspected AO toolkit baseline is commit `e9dce951`.

Saved AO analysis is read from `.kb/index/kb-weights.json` and displayed with `meta.asOf`. Missing or invalid analysis is unavailable; presence does not certify freshness, truth, or a clean KB. Rhizome does not recompute AO judgments.

## Re-init, removal, and ejection

Re-run `rzm init` to receive managed updates. Unedited managed files update; edited files are preserved and reported for reconciliation. Re-running unchanged init leaves managed bytes unchanged. Existing AO records and AO skills remain owned by AO.

`rzm init --remove-addon ao-kb` follows normal starter removal: unedited installed assets are removed and edited assets are preserved. `rzm init --eject ao-kb` keeps installed files and ends their management; `rzm init --restore ao-kb` resumes it. Generated schemas, views, manifests and source ownership are outside init's managed-file inventory and remain through ejection and add-on removal; review these explicitly when removing a projection. Neither operation migrates or deletes AO-authored knowledge. Re-run the checks and indexing after any binding update.

For generated view contracts, pinned compatibility limits, staged publication and recovery, read `.rhizome/modules/ao-kb/bindings/README.md`.

If the first index persists configuration defaults, `ao_index_inputs_changed` names `.rhizome/config.yml` and no receipt is issued. Review that change, refresh bindings, then run the index wrapper again. A later authored edit expires the receipt while compatible bindings remain ready; normal indexing refreshes those values.
