# AO KB setup

Use the repository's Rhizome launcher for every command below. Run from the vault root, which must be the AO KB root (the account root for a multi-product KB). Keep AO knowledge and model authoring with `/ao-kb:process`, `/ao-kb:curate`, and `/ao-kb:suggest`. Never run AO ingestion, curation, generation, or publishing during setup.

1. **Install.** `rzm init --add-addon ao-kb`, or `rzm init --addons ao-kb` on first init. Init installs static assets, the binding compiler, and `.rhizome/source-ownership.yml`, which declares AO KB's standard layout AO-owned (the root and every `products/<slug>/` root) before anything is compiled or indexed. It runs no project-specific compiler. `rzm init --check` checks managed files only.
2. **Trust.** Module actions run only in a trusted repository. If `rzm ao-kb check` is refused as untrusted, ask the user to run `rzm trust` in the repository; it is interactive, so never run it for them. Until then, `node .rhizome/modules/ao-kb/scripts/check.mjs` prints the same check.
3. **Check.** `rzm ao-kb check` reports named rows. Knowledge: AO root `.kb/config/vault.md`, schemaVersion 8 (older is unsupported: upgrade AO KB first), product mode, toolkit stamp, note includes, source ownership, knowledge bindings, sequence-shaped frontmatter connections, and saved analysis. Model: compiler dependencies (`uv` on PATH supplies Python and AO's pinned kb-site package), model bindings, model index, and model source ownership. A fresh installation reports incomplete bindings and the exact refresh command. Resolve root/version/ownership errors before refresh; install uv on PATH for the model stage.
4. **Includes.** Note includes must cover `assertions/**`, `sources/**`, `concepts/**`, and `artifacts/**`, plus the exact `.kb/curation/_conflicts.md`: discovery skips hidden directories unless an include names the path. Append only what is missing and keep unrelated rules.
5. **Ownership before refresh.** Source ownership must be `ok`. If the KB keeps AO-authored files outside the standard layout, add those paths to `.rhizome/source-ownership.yml` now; never add unrelated notes. Rhizome refuses native edits to owned files; AO skills and external editors still change them. Deleting the declaration is the only way to end the protection.
6. **Refresh bindings.** `rzm ao-kb refresh-bindings --product <slug>` for a multi-product KB (the product is required and persisted), or `rzm ao-kb refresh-bindings --single true` for a single-product KB. Later refreshes reuse the selection. `--toolkit <absolute path to packages/kb-site>` selects a local AO checkout at the pinned revision. Knowledge admission publishes independently through Node. A model dependency or compatibility failure keeps the current knowledge scope and previous model generation, and reports model setup incomplete. Then rerun the check: model bindings must be `ok` and model source ownership must be `ok` before indexing. The compiler refuses unowned compiled paths before publishing model bindings. Add those AO paths to the declaration and refresh. Preserve unrelated note includes and add the exact model source paths listed in the manifest. If includes change, refresh again before indexing.
7. **Index.** `node .rhizome/modules/ao-kb/bindings/cli.mjs index` runs real indexing and verifies model record counts. If the first index reports `ao_index_inputs_changed` because it persisted configuration defaults, review `.rhizome/config.yml`, refresh bindings, and run the wrapper again; no receipt is issued for changed inputs. Then prove the knowledge projection with `rzm agent ontology-query --query '{ assertion(first: 1) { title } }'`.

Report three states separately, with evidence: **starter installed** (`init --check` and the check's `starterInstalled`), **bindings ready** (`bindingsReady` from the check, never the saved manifest alone), and **index ready** (the check's verified receipt plus a typed knowledge query). Include source ownership, the selected product, and saved analysis's `meta.asOf` or unavailable state. Neither `init --check` nor the check action alone proves a usable projection.

In a multi-product account, static knowledge typing is unscoped until the first successful admission refresh. AO knowledge stays in account `<type>/<slug>/` and `artifacts/<phase>/<slug>/`; shared type-root notes follow `products` selection. Unselected knowledge remains searchable as ordinary notes. Ordinary authored edits need normal indexing; metamodel/config/selection changes require binding refresh.

For direct CLI instructions and lifecycle behavior, read `docs/reference/guides/ao-kb.md`.
