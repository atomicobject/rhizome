# Requirements

Keep requirements atomic. One note captures one obligation, capability, constraint, data rule, workflow expectation, quality expectation, or compliance expectation. Link exact source evidence and the smallest domain or delivery notes the requirement constrains.

Extraction creates a `candidate`; acceptance requires an authorized human decision. Provenance, confidence, structural links, and semantic similarity support review but do not constitute acceptance. An `implemented` status requires evidence for the full obligation and an authorized lifecycle update. Preserve rejected and superseded history, conflicts, and partial delivery.
