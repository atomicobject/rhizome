# Requirement sources

Use requirement sources for evidence inputs. Record stable source identity, kind, locator, provenance, review state, extraction date, and source date or version when known.

When a source changes, preserve the prior version/date and the exact cited evidence that justified earlier requirements. Add the new evidence and identify affected requirements and delivery targets. An updated link alone is insufficient history. If the earlier content is unavailable, record that evidence gap. If delivered code disagrees, record the mismatch before deciding whether the source, requirement, spec, or implementation is wrong.
