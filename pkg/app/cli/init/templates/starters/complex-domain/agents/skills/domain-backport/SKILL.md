# Domain Backport

Reconcile delivery evidence into the domain and requirements layer during `agentic-engineering reconcile`. Agentic Engineering owns normative spec decisions, deviations, and effort completion.

Load the shared retrieval and evidence guidance through the `complex-domain` router. Begin from the alignment finding and approved scope/deviation. Use `spec-domain-context-pack`, `changed-domain-impact-pack`, and focused `requirement-trace-pack` calls only for affected targets.

- Repair authorized domain/requirement links and locators supported by delivery evidence.
- Mark a Requirement `implemented` only when evidence demonstrates its full atomic obligation and the lifecycle update is authorized. Partial story or criterion delivery remains partial.
- Preserve source identity, prior versions, cited evidence, rejected/superseded history, and remaining gaps.
- When code and cited source disagree, record the mismatch and evidence before deciding whether the implementation, spec, requirement, or source is wrong. Code alone does not make a source stale.
- Apply only authorized acceptance, rejection, supersession, priority, or confidence changes.
- Record unresolved gaps or decisions as `ActionItem` entries without inventing owners.
- Send normative product or policy changes through Agentic Engineering reconciliation and repeated workflow friction through compounding.

Report each finding, affected target, applied update, supporting evidence, remaining gap, and retrieval qualification. Validate the notes and links actually changed; do not run a blanket validation suite for read-only or partial reconciliation.
