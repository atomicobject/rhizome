# Spec From Domain

Supply upstream constraints to `agentic-engineering specify`; the resulting spec remains the delivery contract.

Load the shared retrieval and evidence guidance through the `complex-domain` router. Use `domain-context-pack` or `requirement-trace-pack` for known notes and `spec-domain-context-pack` for an existing spec. For topic-only work, run bounded `domain-inventory-pack` queries for the relevant types before optional `domain-topic-survey` candidate ranking.

Summarize these inputs before drafting:

- accepted requirements that constrain scope, with source/provenance qualifications;
- candidate requirements as context rather than delivery commitments;
- process rules, workflow variants, feature areas, contexts, and domain types that bound behavior;
- unresolved conflicts, stale evidence, missing coverage, and accountable action items.

Link the spec to the smallest durable upstream notes. Confirm incoming requirement candidates from `spec-domain-context-pack` through the requirement's typed `specs` relation before counting authored coverage. Keep authored links, readable targets, and evidence that delivery satisfies an obligation separate.

A resolved but unlinked anchor is a coverage finding. An unresolved anchor, degraded retrieval, or capped inventory is a qualification. Pass constraints and qualifications into `agentic-engineering specify`; do not promote candidates or silently expand accepted scope. Validate only mutations made by the specification workflow.
