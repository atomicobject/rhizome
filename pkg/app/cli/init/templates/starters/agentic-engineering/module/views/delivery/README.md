# Delivery experience

The pure `lib/groups.ts` registry owns membership, labels, count units, and Shape, Build, Settle orientation. Shaping specs and Ready stories overlap. Planned and Active efforts use recorded status. Delivery history retains complete and archived status. Current contracts and Record review are supporting views. A checked checklist does not change an effort's status or establish acceptance.

Counts name specs, stories, efforts, or observations. Partial reads qualify counts and preserve visible errors. They cannot establish that omitted records or selections are absent.

The resume brief keeps governing metadata, explicit frozen source, authored frozen occurrences, entry mentions, and a separate log snapshot distinct. Occurrences retain authored order, repeated targets, and unresolved raw references. A criterion selection includes only that criterion. A selected story includes its full criteria. Missing, duplicate, broken, unsupported, and unreadable evidence remains visible. An HTML source opens through its canonical original presentation and is never interpreted as Markdown or injected into the page.

`promptFor` owns prompt construction and exact canonical scope. Selection starts empty. Eligible visible rows can be selected together. Selection does not approve or freeze a slice. Shaping and Current contracts route through specify; Ready stories through effort and plan; Planned through classify; Active through implement; History and Record review through finish or reconcile. Copy reports clipboard errors and leaves a selectable preview.

Pages use the host's contexts, parameters, navigation, readiness and read lifecycle. Stage links use standalone context. The nonidentity story parameter focuses an inline disclosure. The panel uses the same map, searches loaded canonical records, and records actual visits. The four existing native collection definitions remain available.

Home inventories omit narrative content and defer checklist evidence. Selected effort prompts load only the selected contexts. The spec page loads effort relationships on request, keeping its own contract readable first. That explicit relationship read inspects every loaded effort source and qualifies the result if any authority is missing.

Status and Execution Notes use exact declared inline or linked work-log sections. Closure checklist counts use the public renderer's GFM grammar. They exclude checkbox examples inside code. Original sources remain available through progressive disclosures and canonical navigation. Recent stores only canonical visit identities per repository and browser window; displayed titles and states come from current reads.
