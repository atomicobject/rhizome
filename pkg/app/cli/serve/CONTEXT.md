## Vault runtime process, below Cobra

Owns everything `rzm serve` / `rzm start` / `rzm stop` do once flags are parsed (SPEC-0104). `cmd/serve.go` and `cmd/stop.go` are thin adapters; the lifecycle, readiness gates, control-API assembly, and stop policy live here.

- **Entry points**: `Run(ctx, Options)` is the runtime process; `Stop(ctx, StopOptions)` is `rzm stop [--all]`; `BuildRuntimeControl` assembles the loopback control surface; `ReadinessCoordinator` owns the startup gates; `RecoverInterruptedWrites` waits cancellably for the index lease and stabilizes unfinished writes before readers or background work start. Native namespace stabilization runs before ontology recovery, restores prepared required files, synchronizes terminal markers and releases only proved-owned Git exclusion. Settled native journals remain for current-footprint convergence. Completed generic repair journals remain for strict repair recovery; later edits do not block startup, which warns with validation guidance.
- **Startup order is the contract**: elect (inside `NewLiveRuntime`) → register the elected token and PID before owner-only recovery → build the control surface → construct the web server → bind the listener → publish the manifest under the intent gate. A process that loses election prints the winner and returns `ErrAlreadyRunning`, which `cmd` maps to exit code 3; it never binds a port or touches the winner's manifest, lock, or log. Detached children inherit their parent's pending token; an explicit attached start creates its token after election.
- **Shutdown order is the contract too**: the manifest is removed before the election lock is released, and only by the PID that owns it. Shutdown cancels and drains HTTP handlers, readiness workers, and serve-owned callbacks before `rt.Close()` drains runtime work and releases the lock. The stopped message is printed only after cleanup completes.
- **Stop discovery**: the global registry lists elected owners and pending detached children. Stop cancels the observed token, so recovery blocked on another writer can exit before publication; it does not cancel a successor's different token. It waits within its grace period for a live owner or spawn lease to resolve and reports incomplete shutdown if ownership remains. It never guesses the mode or kills an unpublished owner. A published but unresponsive headless owner gets the full grace period before force termination; an attached owner is never force-killed.
- **Modes**: attached runs in the user's terminal, may open a browser, and never idle-exits. Headless redirects the process's stdout, stderr, and `log` output into `.rhizome/diagnostics/runtime-output.log` (Go-output capture caps each file at 5 MiB, with one rotation to `runtime-output.log.1`; inherited native crash writes are bounded on the next open), never opens a browser, and exits after `runtime.idleTimeout` with no client activity and an idle lane. Both exit when the vault root disappears.
- **Idle activity** is `RuntimeControl.Touch`: the web layer calls it for every authorized control request and every open SSE heartbeat. A busy or queued lane also counts as activity, so indexing is never interrupted by the idle timer.
- **Lane-owned hooks**: `ControlHooks` carries the index-job and agent-operation callbacks that other lanes register from `cmd`; a nil hook leaves its route answering "not enabled" rather than failing startup.
- **`ProcessBuildID()` is computed once per process.** Rebuilding the binary on disk must not change what a running runtime claims to be.
- **Validation admission**: readiness owns invalidation before SSE broadcast and before a web server exists. Queued refreshes and startup work capture cancellable admission contexts before waiting; invalidation cancels them and fences the durable generation under the same short admission lock. Every validation request waits for the boot index attempt, including an explicit index that displaces it, before it can seed metadata or ontology projections. Validation executes outside that admission lock; its projection runs on the indexing lane and requeues after preemption. Validation checks run after the lane releases the index lock. Manual refresh requests use the runtime lifetime. Transient `refreshPending` remains true across debounce, startup waiting, execution, and queued replacements; completion, cancellation, or shutdown clears it and notifies browsers. Failed reconciliation queues no new run, while later requests can recover through the live projection.
- **Boundary**: manifest, probe, ensure, and route constants belong to `pkg/app/runtime`; election, capabilities, and the indexing lane belong to `pkg/app/bootstrap`; HTTP handlers belong to `pkg/app/web`. This package composes them and owns no wire format of its own.

- **Diagnostics ownership**: reuse the command recorder, or open a bounded recorder for embedded `Run` callers. Bootstrap and HTTP receive that same context. Structured startup/election/listen/shutdown, capability and recovery events stay separate from the bounded raw crash/startup fallback. Standard-log leases restore the original global writer after their last owner returns; daily log ownership has been removed. Old user logs are preserved.

Runtime shutdown drains request handlers, background work, stores, and the election heartbeat before `BeforeOwnershipRelease` finalizes runtime and command diagnostics and closes the headless output capture. All structured recorder writes and elected Go-output capture finish before election ownership is released. The inherited native fallback can still receive process-exit or pre-capture command error prose afterward; it follows the raw-output retention limits above. Attached terminal completion output remains after release. Owner-barrier failures and panics finalize their true error outcome while still releasing the election lock.
