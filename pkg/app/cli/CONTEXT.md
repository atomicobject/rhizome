## pkg/app/cli

CLI action implementations for user-facing commands. `cmd/` parses flags and delegates into `pkg/app/*` packages (`cli`, `indexing`, `codeintel`, etc.) for orchestration/business logic.

- **Offline diagnostics**: `diagnostics.Read` resolves an explicit directory without configuration, reads bounded plain-file evidence through `pkg/diagnostics`, and preserves coverage warnings. It never constructs a recorder, opens the main index, starts a runtime, or generates its own logs. Latest-index reads are independent of retained-history cutoffs; measured index summaries do not infer anomalies or add overlapping spans.
- **Entry points**: `ListFiles`, `RenameNote`, `RenameHeading`, `BuildFileContextText`, `BuildVaultContextText`, `BuildCodeAnchorListItems`, `QueryRecipeService`, `CurrentUserService`, `AllocateNextID`, `ParseRecipeInputsJSON`; validation aliases/renderers delegate to `pkg/app/validationrun` and preserve the additive identifier-reconciliation envelope.
- **Key invariant**: accepts `VaultDefinition` + `NoteReader`; business logic lives here, not in `cmd/`. Parameter objects that can consume persisted metadata or refresh ontology also receive the caller-composed `notemeta.Indexer`; without it, read-only graph/context paths stay live-source-only rather than constructing an implicit provider runtime.
- **Identifier freshness**: `AllocateNextID` uses the schema and store returned by one refreshed ontology runtime. Caller schema admission preserves existing errors but does not choose the allocation pool. A successful optional authoring-guide refresh uses that same schema for field instructions, skeletons and suggestions. The initial schema gates lookup eligibility and supplies rendering fallback when refresh is unavailable.
- **Mutation preflight**: `RenameNote`, `MoveNotes`, and `RenameHeading` require an explicit metadata indexer and reject registered formats without the requested executable mutation capability before parsing or writing. Note moves admit every regular source and target, canonical parent path, collision, and physical identity before creating directories or moving files. Duplicate, overlapping, and ancestor/descendant targets fail the entire batch; similar filename prefixes remain valid. Case-only basename transitions retain the actual source entry spelling for Git and filesystem moves, with canonical target parents and the requested target leaf spelling; authored and canonical source paths remain alternatives of one logical rewrite. Authorized overwrite uses `git mv -f` or `fileio.Replace` without deleting the destination first. Attachment-to-attachment moves remain supported. Required renames and backlink writes publish through the native validation transaction.
- **Namespace publication**: `RenameNote` and `MoveNotes` supply one read-only plan from original bytes, hash/mode witnesses, and final-path eligibility. Compose shared backlink hosts, exclude overwritten bodies, retain request-order counts and non-Markdown skips, and reinsert moved sources previously hidden by a pruned folder. Walk entries retain their own leaf names for eligibility and reporting; eligible leaf symlinks fail preflight, while non-Markdown or excluded aliases remain outside required rewrites. The validation engine owns recovery, Git participation, atomic publication, and convergence through the explicit caller-composed projection refresher. Current and recovered decisions remain separate; only committed current outcomes fill legacy success fields from this invocation. Full display diagnostics remain in the private planner; the recovery summary stores fixed move/link counts, so valid large requests retain their complete output without exhausting the journal limit. Optional current coderef writes borrow the same lease after required convergence and cleanup, retain best-effort counts, and never replay recovered work. URI execution waits for successful engine return with no recovery pending.
- **Writer admission**: ordinary CLI writers check the shared native namespace envelope after acquiring the canonical writer lease and before reading mutation inputs. Prepared or unsettled native publication must be recovered through its validate owner first.
- **Heading publication**: apply recovers interrupted edits before taking the writer lease and capturing sources. It composes the heading and inbound rewrites per file, then submits one existing edit session with immutable original-byte witnesses under the held lease. Unreadable potential backlinks stop apply; conflicts fail the action, unchanged content reports `Applied=false`, and committed cleanup warnings retain `Applied=true` in the existing result message.
- **Heading self-links**: fragment-only wikilinks resolve against the scanned source note. Preview and apply refuse requested file symlink aliases before canonicalization, retaining the edit session's existing unsupported-alias boundary. In-vault parent-directory aliases remain supported. The requested note uses one canonical inventory path for its heading, original bytes, link matches, and staged writes. Case variants must identify the same physical file, while distinct case-sensitive notes remain separate. Rename retains the authored empty note target and alias, and preserves protected code spans and local links in other notes. Preview and apply share these matches and counts for heading text and block-ID upgrades.
- **Serve readiness**: `serve.ReadinessCoordinator` owns the startup gates, pre-runtime publication handoff, warm-model probes, follower publication polls, complete-model observation, and validation refresh below the Cobra adapter. Followers poll shared note and complete-model publication before waiting for local search and code phases. The complete-model poll stops on promotion. The provider-aware note scan switches to leader observation, exponentially backs off to two seconds, and hands responsibility to the background indexer after the leader's code phase completes. All polls stop on cancellation. `cmd/serve.go` composes the runtime and delegates.
- **Target-scoped code context**: untargeted code-profile vault context ranks repository docs broadly. Supplying `Files` skips that repository-wide inventory because bundled file context already loads root, ancestor, and requested submodule docs. Supplying only `ContextFiles` also skips the broad inventory and remains intentionally note-scoped: it preserves each requested note's summary/graph context without implying code-target ancestor-doc behavior.
- **Start scopes are explicit**: ordinary `agent start` branches before rich input/note/graph/ontology work and renders bounded root/ancestor/target guidance. Vault/ontology/context-note/graph selectors use `indexed_bootstrap`; standalone `vault-context` retains its rich live contract.
- **Indexed bootstrap is read-only and bounded**: SQL scopes persisted selected-note metadata, code→note, rationale, resolved-edge, aggregate graph-summary, and authored-type ontology data before deterministic provider-free ranking and item/byte packing. Freshness uses schema/indexer/scope/ontology proofs, not elapsed time; missing/stale/incompatible state returns structured `rzm index` remediation and never falls back to discovery or repair.
- **Agent file context is index-first**: the one-shot read-only route first proves the current indexer version and scope hash, then verifies SHA-256 index metadata for each explicitly requested regular code or note file before using requested-file coderef whitelists, requested/incident note graph rows, and targeted ontology traversal. Directories are never crawled for freshness. Missing, stale, or incompatible state disables all indexed enrichment and returns structured remediation alongside bounded filesystem guidance. The current-index path may rescan an explicitly requested source file to preserve coderef occurrence fidelity, but it must not inventory notes, materialize the whole graph, project ontology, refresh anchor scopes, or fall back to live repair.
- **Context delivery follows final text**: file/vault packing holds pending session reservations through target trims, header and indexed-warning assembly, and bundled output. Exact retained piece text and renderer byte ends authorize fingerprints only for complete emitted containers, including those preserved before appended warnings. Partial containers and successful compression retain raw retry eligibility. Compression receives the request context; cancellation and omissions release owned reservations. Fully emitted deterministic contexts still dedupe.
- **Root graph repair stays target-scoped**: `graph file-context --ensure-link-targets=plan|apply` scans only explicitly requested configured code files, using canonical include/exclude rules and note aliases. This supplies live repair candidates without repository-wide discovery. `default` and `never` do not invoke this scan.
- **Validation rendering**: JSON stays machine-valid; human/GitHub output reports the deterministic identifier plan summary and all six timing stages. Repair plan/execution follow-ups remain JSON evidence, human review items, and GitHub warnings without changing issue/error/action counts or exit status. Scratch-CI blocked guidance never claims `rzm index` will make the isolated run pass.

- **Ensure-link apply**: local graph file-context composes the indexing-owned apply coordinator with the explicit metadata indexer, live store, and uncached source reader. Indexed read-only contexts reject apply. Durable metadata/ontology convergence precedes refreshed node results.
