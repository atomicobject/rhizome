# Agent code package

This package implements [SPEC-0092](../../../docs/specs/technical/persistent-agent-code-mode.md). `Surface` and `Describe` project code contracts from the existing `agentapi` catalog. `Generate` publishes an immutable, selected ESM client under a caller-chosen directory, and `Serve` is the bounded JSON-RPC stdio host used by `rzm agent code serve`.

Selection accepts exact catalog names or their generated JavaScript methods and always returns canonical names. `code describe --schema input|output` omits the other schema while retaining shared guidance and declaring `schemaSelection`; the default remains both complete schemas. `contractHash` identifies the full selected contracts independently of this display projection. Generation and execution always use complete contracts.

[SPEC-0094](../../../docs/specs/technical/managed-agent-code-execution.md) adds `Execute`: a bounded Node invocation receives JavaScript with a managed `rzm` namespace and returns the selected JSON value. It reuses the generated module in memory, owns the client/server lifetime for one execution, and creates no task artifacts. Discovery includes exact JavaScript method names. Session IDs may span executions; JavaScript state and child processes do not. Node runs with the caller's permissions; execution is not a security sandbox. Script errors, deadlines, serialization and output failures are explicit, and interrupted writes retain uncertainty rather than implying rollback.

Execution tracks pending calls and completed unobserved failures. Completed successes and observed outcomes leave the tracker, so discarded payloads can be collected while a script continues. Observation after settlement clears retained failure evidence. Accepted calls settle before client cleanup, and the first still-unobserved failure is selected in invocation order with its original outcome or cause details.

[SPEC-0096](../../../docs/specs/technical/code-mode-evidence-guidance.md) adds shared `invocation` and `outcome` metadata once per selected `Describe` response. Describe format 2 covers field semantics, conditional requirements, per-call options, resolved outcomes, and thrown failures. These fields participate in the contract hash and generated artifact version 3; compact `Surface` format 1 remains unchanged. The client and discovery share the default call-timeout constant. Session dedupe tracks payload delivery before script projection; targeted rereads can use `files` with `dedupe: false`.

The generated client runs one absolute `rzm agent code serve` process with argument arrays, `shell: false`, the explicit vault as its working directory, and `RZM_SKIP_REPO_DELEGATE=1`. It initializes once with the selected contract hash, exposes camel-cased methods for every selected operation, and returns domain `CallOutcome` values without retrying operations. `readWrite` explicitly adds `--read-write`; operation-specific apply authority remains server-side. The client dispatches eight calls concurrently by default (configurable 1..32); the host bounds active calls at 32. `agentapi.CodeResources` uses a context-aware reader/writer lock for the shared vault: audited existing-index reads share access, live runtime refreshes and mutations take exclusive access, and provider/ignore calls are independent. Dependent calls must be awaited explicitly. Whole-script deadlines default to 30 seconds and allow up to 24 hours; per-call deadlines remain at most five minutes. Cancellation and timeouts send request-scoped JSON-RPC cancellation, and `close` shuts down then reaps the owned process within a bounded grace period.

The host accepts newline-delimited JSON-RPC 2.0 only. It bounds frames and the queue, requires initialize before calls, rejects unselected operations, and preserves callback outcomes as results. Protocol, lifecycle, timeout, cancellation, and handler failures use stable JSON-RPC error data codes. The host validates catalog inputs; the callback maps domain failures to `CallOutcome`, so the transport never fabricates CLI output or replays writes.

Generated artifacts contain contracts and client code only. Runtime executable paths, vault paths, session IDs, credentials, and note contents are supplied at use time and are not part of the artifact hash or persisted manifest.

`evaluate` is a shared operation backed by `pkg/typesafe`. Its catalog declares discriminated question and answer variants, so generated TypeScript clients preserve narrowing by `type`. Live describe explains independent questions, probability semantics, usage, and credentials. Evaluation uses the shared handler and an empty one-shot runtime plan; it does not initialize indexes or deduplicate evidence.

`evaluate_batch` uses the native client worker pool, with per-item correlation, usage, attempts and explicit succeeded/failed/not_started/uncertain outcomes. `check_paths` uses the existing ignore matcher, including nested git rules and Rhizome exclusions, without initializing indexes. The scripts in `scripts/repo-audit` own their checkpoints and preserve uncertain work instead of replaying it.

[SPEC-0104](../../../docs/specs/technical/vault-runtime-coordination.md) moves where catalog operations run. This package stays transport-only: `Serve` still hands every call to the invoker its command supplies. That invoker (in `cmd`) ensures the vault runtime at connection start and forwards catalog operations to `POST /api/v1/agent/ops/{name}` with the connection's read-write flag and session id, so a script sees the live index and pays no per-call bootstrap. Local-only operations keep executing in this process, and the runtime refuses one that arrives anyway as `code_mode_local_only`. When no runtime can be used the invoker executes in-process as before for the rest of the connection and reports that fallback once, on the first call that would have been forwarded. The runtime returns its configuration generation inside the outcome diagnostic; the host removes it and raises the existing `code_mode_configuration_changed` outcome when it moves, so the generated client sees one wire shape regardless of execution host.

- **Namespace mutation output limits**: preserve the existing diagnostic's whitelisted current decision, transaction ID, receipt path, and recovery-pending state when the full reply exceeds the frame limit. Bound the status to 8 KiB and recovered identities to eight entries, retain the actual outcome/exit code, and report recovered count and truncation. Keep the full summary in the ordinary payload and reuse existing cancellation/deadline outcome retention.
