# pkg/app/tasks

Scheduled tasks ([[scheduled-tasks|SPEC-0127]]); user guide: `docs/reference/guides/scheduled-tasks-guide.md`.

- **Entry points:** `OpenRepo` (repository identity by Git common directory), `Open` (composes a `Service` from a repository path, harness drivers, settings loader, and trust check; `cmd` and the web routes both use it), `New`/`Service` with `RunDue`, `Run`, `RunDraft`, `PlanStart`/`MarkStarted`/`UndoStart`, `Status`, `Inbox`, the item actions, `PrecheckRun`/`RecordLaunchError`, and the history reads `LiveState`, `Runs`, `RunDetail`. `cmd/tasks.go` is the thin Cobra front; `pkg/app/cli/serve` starts `rzm tasks run-due` on an interval.
- **Scheduled definitions come from the primary ref.** `LoadDefinitions` reads `.rhizome/tasks/*.yml` and `.rhizome/modules/<module>/tasks/*.yml` through `git ls-tree`/`git show` at one resolved commit, flat files first; the working tree never changes scheduling. `localTasks` separately discovers the selected checkout and compares source bytes, reporting new, differs, same, or invalid local versions without hiding a valid scheduled task. A file that fails to parse is a `Problem`, not an error. Parsing lives in `pkg/vault/taskdef`, which `rzm validate tasks` also uses on the working tree.
- **Tests capture local source.** `RunDraft` verifies common Git repository identity, captures effective working-tree contents through a private Git index into a detached snapshot, and parses the captured task. Command checks and agent work use the snapshot; code-mode checks use captured script bytes with the selected checkout's existing index and refuse automatic indexing. Tests create no inbox item, task branch, output commit, or task tag. `RZM_TASK_TEST=1` and a fresh absolute `RZM_TASK_DATA_DIR` reach checks and harness children; compounding routes all private state there without migration.
- **Two locks.** `run.lock` serializes every check and background run for the repository, held from resolving the ref through publishing results; passes that find it held skip. Tests hold the same lock, so they may delay a scheduled pass without changing its due state. `state.lock` guards short read-modify-writes of `state.json`, so inbox commands never wait for a run.
- **Clock.** `person` tasks use the local history; `team` tasks also use the latest commit on the primary ref whose message has the line `Rhizome-Task: <id>` (`git log --grep`, whole line, so squash bodies count).
- **Processes.** Checks run through `pkg/app/procrun`, shared with module actions: as session leaders under a `pkg/proctree` tracker, with the login shell's PATH and 1 MiB of stdout, which records descendants by PID and start time; when a check ends or times out, everything it started is killed, and `WaitDelay` keeps a descendant holding the output pipes from holding the run lock. Prompt runs go through `pkg/harness`, whose transport does the same on `Close`.
- **Background runs never push.** `work` makes `rzm/<task>/<date>` (suffixed when taken) and a worktree under the state folder, runs the prompt, then `commitWork` commits everything with the agent's message and the tag, adding an empty tagged commit when the agent committed everything itself. No changes: the worktree and branch are removed.
- **Qualified ids.** A module task's id is `<module>/<file name>` (`taskdef`). Every file-system name built from an id goes through `taskdef.PathKey` (`/` → `_`, which ids never contain): the data folder and `worktreeName`, which is also the `claude --worktree` name. Pull-request matching (`isTaskBranch`) requires the date suffix after `rzm/<task>/`, so flat task `a` never matches `rzm/a/b/<date>`.
- **Retries rerun the check.** `Run` runs the task's check again first, so a failed check never reaches agent work and the prompt gets fresh context. When the check says nothing is needed, an item holding a failed attempt's worktree stays needs attention so the work can still be reviewed or discarded.
- **Due items re-check.** In `RunDue`, an open item blocks its task except needs attention (waits for cadence) and due: when the task is due again, `recheck` runs its check once more. Nothing needed closes the item as done with a `not-needed` record; still needed refreshes `Summary` and `Context` in place with a `notified` record, keeping `Snoozed` and `Commit` (merge detection reads it). It never adds an item or starts work; a failed check goes through `fail` with the item's id.
- **Prompts.** `InteractivePrompt` (Start, `--print`) and `CopyablePrompt` (`CopyPrompt`, `GET /api/tasks/items/{id}/prompt`) share `writePromptBody`; only Start's has the `git switch -c` step. `CopyPrompt` serves any open task item and changes nothing.
- **Failures.** A failed check reuses the task's earlier failure notice when it holds no worktree; failed prompt runs record the tokens they used.
- **Runs.** Each run gets an ID (`YYYYMMDDTHHMMSSZ-<8 hex>`, validated before any path join) before its check, and a folder `runs/<id>/` with `check.log` (stderr through `checkLog`, which caps at 1 MB and never fails the check) and `events.jsonl` when agent work ran (`AgentRequest.Transcript`). `State.Running` is set under run.lock at the start (stage `check`, then `agent`); `Record` clears it only for the same ID. Every execution path (`RunDue`, `Run`, `RunDraft`) first records a leftover `Running` as one `interrupted` run (`finalizeInterrupted`), and ends with `retain`. Records carry their own item, branch, worktree, base commit, and changed files; `Item.Run` names the attempt that owns the item's worktree, so `fail` copies only its own attempt's worktree.
- **Transcripts.** `transcript.go` writes `events.jsonl` in the `agentchat.Event` shape (via `agentchat.EventFromHarness`): text and reasoning deltas merge into whole blocks, `updated` phases of commands, tools, and file changes are dropped, Text and Input are bounded (`harness.BoundedRaw`), the file stops at 10 MB with a `transcript-truncated` line, and `final-message` plus the last `token-usage` are always written. A completed block that corrects one already written is appended again with the same `id`, so readers keep the last line per id. `HarnessAgent` treats a `retrying` error as not fatal and a failed or declined `turn-completed` as fatal.
- **Retention.** Per task: 20 records with a transcript plus 100 others, and the newest 20 transcripts and check logs; empty folders, and unreferenced folders older than 7 days by their ID, are deleted. Token totals live in UTC day buckets (`State.Tokens`, 30 days), seeded once from history. Tests use `Running` and separate `State.Tests` history, without advancing `History`, `Last`, or `Tokens`. Retention keeps ten test records per task and source checkout, with at most the latest changed worktree for each. History reads filter completed tests to the selected checkout while keeping the repository-wide active run visible.
- **Launch errors.** `Run` failures before the run starts satisfy `NotStarted`; `rzm tasks run <item>` saves them as `Item.LaunchError`, which `Item.set` clears on the next state change. `PrecheckRun` returns the same errors without running anything. `PrecheckTest` resolves a discovered local ID with the same repository/trust/lock checks; `RecordTestLaunchError` retains detached launch failures in test history. `LiveState.Stale` reads the run.lock holder through `indexlock` (dead PID or a different runtime identity); it runs no git.
- **Trust.** Nothing runs unless `Options.Trusted` accepts the main checkout; `cmd` passes `repositorytrust`. `Untrusted` applies the same check for other repository code, such as module actions in `pkg/app/actions`.
