# pkg/app/tasks

Scheduled tasks ([[scheduled-tasks|SPEC-0127]]); user guide: `docs/reference/guides/scheduled-tasks-guide.md`.

- **Entry points:** `OpenRepo` (repository identity by Git common directory), `Open` (composes a `Service` from a repository path, harness drivers, settings loader, and trust check; `cmd` and the web routes both use it), `New`/`Service` with `RunDue`, `Run`, `RunDraft`, `PlanStart`/`MarkStarted`/`UndoStart`, `Status`, `Inbox`, the item actions, `PrecheckRun`/`RecordLaunchError`, and the history reads `LiveState`, `Runs`, `RunDetail`. `cmd/tasks.go` is the thin Cobra front; `pkg/app/cli/serve` starts `rzm tasks run-due` on an interval.
- **Definitions come from the primary ref only.** `LoadDefinitions` reads `.rhizome/tasks/*.yml` through `git ls-tree`/`git show` at one resolved commit; the working tree never matters. A file that fails to parse is a `Problem`, not an error. Parsing lives in `pkg/vault/taskdef`, which `rzm validate tasks` also uses on the working tree.
- **Two locks.** `run.lock` serializes every check and background run for the repository, held from resolving the ref through publishing results; passes that find it held skip. `state.lock` guards short read-modify-writes of `state.json`, so inbox commands never wait for a run.
- **Clock.** `person` tasks use the local history; `team` tasks also use the latest commit on the primary ref whose message has the line `Rhizome-Task: <id>` (`git log --grep`, whole line, so squash bodies count).
- **Processes.** Checks run as session leaders under a `pkg/proctree` tracker, which records descendants by PID and start time; when a check ends or times out, everything it started is killed, and `WaitDelay` keeps a descendant holding the output pipes from holding the run lock. Prompt runs go through `pkg/harness`, whose transport does the same on `Close`.
- **Background runs never push.** `work` makes `rzm/<task>/<date>` (suffixed when taken) and a worktree under the state folder, runs the prompt, then `commitWork` commits everything with the agent's message and the tag, adding an empty tagged commit when the agent committed everything itself. No changes: the worktree and branch are removed.
- **Retries rerun the check.** `Run` runs the task's check again first, so a failed check never reaches agent work and the prompt gets fresh context. When the check says nothing is needed, an item holding a failed attempt's worktree stays needs attention so the work can still be reviewed or discarded.
- **Failures.** A failed check reuses the task's earlier failure notice when it holds no worktree; failed prompt runs record the tokens they used.
- **Runs.** Each run gets an ID (`YYYYMMDDTHHMMSSZ-<8 hex>`, validated before any path join) before its check, and a folder `runs/<id>/` with `check.log` (stderr through `checkLog`, which caps at 1 MB and never fails the check) and `events.jsonl` when agent work ran (`AgentRequest.Transcript`). `State.Running` is set under run.lock at the start (stage `check`, then `agent`); `Record` clears it only for the same ID. Every execution path (`RunDue`, `Run`, `RunDraft`) first records a leftover `Running` as one `interrupted` run (`finalizeInterrupted`), and ends with `retain`. Records carry their own item, branch, worktree, base commit, and changed files; `Item.Run` names the attempt that owns the item's worktree, so `fail` copies only its own attempt's worktree.
- **Transcripts.** `transcript.go` writes `events.jsonl` in the `agentchat.Event` shape (via `agentchat.EventFromHarness`): text and reasoning deltas merge into whole blocks, `updated` phases of commands, tools, and file changes are dropped, Text and Input are bounded (`harness.BoundedRaw`), the file stops at 10 MB with a `transcript-truncated` line, and `final-message` plus the last `token-usage` are always written. A completed block that corrects one already written is appended again with the same `id`, so readers keep the last line per id. `HarnessAgent` treats a `retrying` error as not fatal and a failed or declined `turn-completed` as fatal.
- **Retention.** Per task: 20 records with a transcript plus 100 others, and the newest 20 transcripts and check logs; empty folders, and unreferenced folders older than 7 days by their ID, are deleted. Token totals live in UTC day buckets (`State.Tokens`, 30 days), seeded once from history. Drafts mint IDs and folders but are never `Running`, recorded, or counted.
- **Launch errors.** `Run` failures before the run starts satisfy `NotStarted`; `rzm tasks run <item>` saves them as `Item.LaunchError`, which `Item.set` clears on the next state change. `PrecheckRun` returns the same errors without running anything. `LiveState.Stale` reads the run.lock holder through `indexlock` (dead PID or a different runtime identity); it runs no git.
- **Trust.** Nothing runs unless `Options.Trusted` accepts the main checkout; `cmd` passes `repositorytrust`.
