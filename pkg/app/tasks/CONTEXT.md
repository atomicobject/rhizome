# pkg/app/tasks

Scheduled tasks ([[scheduled-tasks|SPEC-0127]]); user guide: `docs/reference/guides/scheduled-tasks-guide.md`.

- **Entry points:** `OpenRepo` (repository identity by Git common directory), `Open` (composes a `Service` from a repository path, harness drivers, settings loader, trust check, and the user-configuration `Env`; `cmd` and the web routes both use it), `New`/`Service` with `RunDue`, `RunDueHost`, `NextDueAt`, `Run`, `RunDraft`, `PlanStart`/`MarkStarted`/`UndoStart`, `Status`, `Inbox`, the item actions, `PrecheckRun`/`RecordLaunchError`, the history reads `LiveState`, `Runs`, `RunDetail`, and the Desktop host's `HostStatus`, `RunLockHeld`, `PauseUntil`, and `Stop`. `cmd/tasks.go` is the thin Cobra front; the runtime starts `rzm tasks run-due --host` (`cmd/tasks_run_due.go`) with its output appended to `task-state/run-due.log`, trimmed to its last 1 MB (`OpenRunDueLog`).
- **Scheduled definitions come from the primary ref.** `LoadDefinitions` reads `.rhizome/tasks/*.yml` and `.rhizome/modules/<module>/tasks/*.yml` through `git ls-tree`/`git show` at one resolved commit, flat files first; the working tree never changes scheduling. `localTasks` separately discovers the selected checkout and compares source bytes, reporting new, differs, same, or invalid local versions without hiding a valid scheduled task. A file that fails to parse is a `Problem`, not an error. Parsing lives in `pkg/vault/taskdef`, which `rzm validate tasks` also uses on the working tree.
- **Tests capture local source.** `RunDraft` verifies common Git repository identity, captures effective working-tree contents through a private Git index into a detached snapshot, and parses the captured task. Runner-owned Git index and checkout operations disable repository hooks without changing Git configuration. Command checks and agent work use the snapshot; code-mode checks use captured script bytes with the selected checkout's existing index and refuse automatic indexing. Code-mode test children set `RZM_RUNTIME_AUTOSTART=0`, so an offline index does not cause runtime startup and indexing catch-up. Tests create no inbox item, task branch, output commit, or task tag. `RZM_TASK_TEST=1` and a fresh absolute `RZM_TASK_DATA_DIR` reach checks and harness children; compounding routes all private state there without migration.
- **Two locks.** `run.lock` serializes every check and background run for the repository, held from resolving the ref through publishing results; passes that find it held skip. Tests hold the same lock, so they may delay a scheduled pass without changing its due state. `state.lock` guards short read-modify-writes of `state.json`, so inbox commands never wait for a run.
- **Clock.** `person` tasks use the local history; `team` tasks also use the latest commit on the primary ref whose message has the line `Rhizome-Task: <id>` (`git log --grep`, whole line, so squash bodies count). `Clock.Next` returns a `Due` (due now, when, deadline, zone). `every` counts from the last run's finish (`At`), unchanged. A `schedule` (`taskdef.Schedule`, slots as minutes of the day per entry) is due when the latest slot at or before now is after the last run's start (`StartedAt`, else `At`) and within the entry's `late`; only the latest slot per entry counts, so missed slots collapse. `slotTime` moves a time inside a daylight-saving gap to the gap's end via `ZoneBounds`; a time in a repeated hour is one slot at its first occurrence (`time.Date` alone picks either occurrence, depending on the zone), so a run that started at either occurrence satisfies it. Zone order: the entry's `timezone`, the person's `tasks.timezone`, then `time.Local` (named from `TZ` or `/etc/localtime`).
- **Dispatch.** `RunDue` loads the local primary ref first and decides due-ness with no network (`dueNow`). Only when something is due, or settling items is due (`settleDue`), does it fetch (`fetchPrimary`: remote-tracking refs only, `+refs/heads/<b>:refs/remotes/<r>/<b>`, 60 s, `GIT_TERMINAL_PROMPT=0`; `redactURLCredentials` strips URL userinfo, query strings, fragments, and `token=`/`access_token=`/`x-access-token:` values from the error before it is stored) and reload; a failed fetch leaves the last fetched ref in use and is stored as `State.Fetch`. Due tasks run nearest deadline first (a slot's end of `late`, an `every` task's due time), each re-decided with a fresh now before it runs. `RunDueHost` runs nothing unless `MachineSettings().Repository.RunHere`, reads it again before each task and stops the pass when it is off, and records an untrusted repository once as `PassError{Code: "untrusted"}`. `NextDueAt` is the host's cheap 30-second question: the earliest due time across unblocked tasks, false when runHere is off, paused until resumed, or untrusted already reported; a timed pause moves it to `PausedUntil`.
- **Per-machine settings.** `repoconfig.TasksUserConfig` (`tasks:` in the user configuration) holds `timezone`, `notify`, and `repositories` keyed by Git common directory (`runHere`, `checkout`, `push`, `dailyTokenCap`, `tasks.<id>.{harness,model,effort}`). `MachineSettings`, `SetRunHere`, `SetHostCheckout`, and `Hosts` read and write it through `repoconfig` under the configuration file lock. A `Service` with a zero `Options.Env` has no settings (tests): tasks do not run there and writes fail. `HarnessAgent.TaskSettings` overrides the chat agent's harness, model, and effort for `AgentRequest.Task` only. `push`, `dailyTokenCap`, and `notify` are stored for later phases and not yet used.
- **Skip codes.** `TaskStatus.BlockedBy` uses the `Blocked*` constants. This package sets `untrusted`, `not-run-here`, `paused` (repository-wide, in that order) and the task's own `off` or `open-item` (`taskDue`). `no-host`, `wrong-branch`, `requires`, and `fetch-failed` are reserved for the runtime host and landing; a failed fetch never blocks a task here because the pass falls back to the last fetched ref. `State.PausedUntil` ends a pause on its own (`PausedAt`); the next pass clears it.
- **Processes.** Checks run through `pkg/app/procrun`, shared with module actions: as session leaders under a `pkg/proctree` tracker, with the login shell's PATH and 1 MiB of stdout, which records descendants by PID and start time; when a check ends or times out, everything it started is killed, and `WaitDelay` keeps a descendant holding the output pipes from holding the run lock. Prompt runs go through `pkg/harness`, whose transport does the same on `Close`.
- **Background runs never push.** `work` makes `rzm/<task>/<date>` (suffixed when taken) and a worktree under the state folder, runs the prompt, then `commitWork` commits everything with the agent's message and the tag, adding an empty tagged commit when the agent committed everything itself. No changes: the worktree and branch are removed.
- **Qualified ids.** A module task's id is `<module>/<file name>` (`taskdef`). Every file-system name built from an id goes through `taskdef.PathKey` (`/` → `_`, which ids never contain): the data folder and `worktreeName`, which is also the `claude --worktree` name. Pull-request matching (`isTaskBranch`) requires the date suffix after `rzm/<task>/`, so flat task `a` never matches `rzm/a/b/<date>`.
- **Requirements first (SPEC-0127 US11).** Every run path (`runTask`, `recheck`, `Run`, `RunDraft`) calls `missingRequirements` before the check: `requires.commands` through `loginpath.Look` (`rzm` always passes), then, only for a task declaring `requires.mcp` or `deny`, the prompt's harness through `harnessResolver` (`HarnessAgent.Harness`). `deny` needs Claude (`enforcesDeny`); MCP servers come from `harness.MCPLister`, run in the main checkout, and must be listed as usable. A failure goes through `fail`, `failRecheck`, or `finishTest` with `attempt.missing`, saved as `RunRecord.Missing`. `requirementsBlocked` reads that record, so status can report `blockedBy: "requires"` without spawning a CLI; never call `missingRequirements` from status.
- **Task sessions.** `HarnessAgent` starts full-access sessions with `UserMCPConfig` (the person's own MCP servers) and `DisallowedTools` from `AgentRequest.Deny`.
- **Doctor.** `Doctor` (`doctor.go`, `rzm tasks doctor`) reports repository checks (trust, primary ref and last fetch, an optional `git push --dry-run` of the commit the remote already has, run with `core.hooksPath` at an empty folder and skipped (`Skipped`) in an untrusted repository, Obsidian Git timers in the host checkout) and per-task checks (commands, harness sign-in, deny, MCP servers), probing each harness's status and MCP list once. `codex mcp list` starts no server, so a usable Codex server is reported as configured, never as reachable. It changes no state. The caller passes the push setting and host checkout.
- **Retries rerun the check.** `Run` runs the task's check again first, so a failed check never reaches agent work and the prompt gets fresh context. When the check says nothing is needed, an item holding a failed attempt's worktree stays needs attention so the work can still be reviewed or discarded.
- **Due items re-check.** In `RunDue`, an open item blocks its task except needs attention (waits for cadence) and due: when the task is due again, `recheck` runs its check once more. Nothing needed closes the item as done with a `not-needed` record; still needed refreshes `Summary` and `Context` in place with a `notified` record, keeping `Snoozed` and `Commit` (merge detection reads it). It never adds an item or starts work; a failed check goes through `fail` with the item's id.
- **Prompts.** `InteractivePrompt` (Start, `--print`) and `CopyablePrompt` (`CopyPrompt`, `GET /api/tasks/items/{id}/prompt`) share `writePromptBody`; only Start's has the `git switch -c` step. `CopyPrompt` serves any open task item and changes nothing.
- **Failures.** A failed check reuses the task's earlier failure notice when it holds no worktree; failed prompt runs record the tokens they used.
- **Runs.** Each run gets an ID (`YYYYMMDDTHHMMSSZ-<8 hex>`, validated before any path join) before its check, and a folder `runs/<id>/` with `check.log` (stderr through `checkLog`, which caps at 1 MB and never fails the check) and `events.jsonl` when agent work ran (`AgentRequest.Transcript`). `State.Running` is set under run.lock at the start (stage `check`, then `agent`); `Record` clears it only for the same ID. Every execution path (`RunDue`, `Run`, `RunDraft`) first records a leftover `Running` as one `interrupted` run (`finalizeInterrupted`), and ends with `retain`. Records carry their own item, branch, worktree, base commit, and changed files; `Item.Run` names the attempt that owns the item's worktree, so `fail` copies only its own attempt's worktree.
- **Transcripts.** `transcript.go` writes `events.jsonl` in the `agentchat.Event` shape (via `agentchat.EventFromHarness`): text and reasoning deltas merge into whole blocks, `updated` phases of commands, tools, and file changes are dropped, Text and Input are bounded (`harness.BoundedRaw`), the file stops at 10 MB with a `transcript-truncated` line, and `final-message` plus the last `token-usage` are always written. A completed block that corrects one already written is appended again with the same `id`, so readers keep the last line per id. `HarnessAgent` treats a `retrying` error as not fatal and a failed or declined `turn-completed` as fatal.
- **Retention.** Per task: 20 records with a transcript plus 100 others, and the newest 20 transcripts and check logs; empty folders, and unreferenced folders older than 7 days by their ID, are deleted. Token totals live in UTC day buckets (`State.Tokens`, 30 days), seeded once from history. Tests use `Running` and separate `State.Tests` history, without advancing `History`, `Last`, or `Tokens`. Retention keeps ten test records per task and source checkout, with at most the latest changed worktree for each. History reads filter completed tests to the selected checkout while keeping the repository-wide active run visible.
- **Launch errors.** `Run` failures before the run starts satisfy `NotStarted`; `rzm tasks run <item>` saves them as `Item.LaunchError`, which `Item.set` clears on the next state change. `PrecheckRun` returns the same errors without running anything. `PrecheckTest` resolves a discovered local ID with the same repository/trust/lock checks; `RecordTestLaunchError` retains detached launch failures in test history. `LiveState.Stale` reads the run.lock holder through `indexlock` (dead PID or a different runtime identity); it runs no git.
- **Trust.** Nothing runs unless `Options.Trusted` accepts the main checkout; `cmd` passes `repositorytrust`. `repositorytrust.DenialReason` checks the resolved checkout. Module actions (`pkg/app/actions`) and repository views (`pkg/app/web`) check the folder `rzm trust` records with `Store.Trusted`, which accepts a linked worktree only through its validated main checkout.

Command-check stdout must be exactly one typed JSON object followed only by whitespace. After the object, the decoder must reach EOF; a trailing closer, garbage or second value fails the check before agent work starts.

- **Hosting** ([[vault-runtime-coordination#^SPEC-0104-US7|SPEC-0104 US7]]). `NextDueAt` and `HostStatus` share `dueInputs`, which resolves the primary ref every call and caches definitions and tags per commit, so the runtime's 30-second check and the host stream run two git commands while the ref stays put; neither fetches or writes. `NextDueAt` skips what `RunDue` skips (off, an open item other than due or needs attention, untrusted, an open-ended pause) so a due time always leads to a run; a never-run task is due from `Seen` (zero before a pass saw it), never from now, so the due time holds still, and a timed pause moves the time to `PausedUntil`. Only a pass closes merged items and records interrupted runs, so `settleAt` makes a pass due when a task item is ready or started, or, with no live run.lock holder, an item is running or `Running` is set: `State.LastPass` (set by every pass's bookkeeping) plus 15 minutes, or at once before any pass. That pass fetches; its blocked tasks still run nothing. `PausedAt` is the one pause check: `PausedUntil` lifts a pause on its own, and `SetPaused` clears it. `HostStatus` reports `running` only while a live process holds run.lock, counts visible items that are not running as `attention`, takes `lastFailure` from tasks whose latest run failed or from `PassError`, and gives each due, ready, or needs-attention item a notice (`failed` when the item's latest run failed).
- **Stop.** `Stop` reads the run.lock holder through `indexlock`, refuses a lock held by its own process, sets `State.Stopping` to the running run's ID, sends SIGTERM to the holder's process group when it leads one (else to the holder), and after the wait kills the holder and, through `proctree`, everything it started. It then takes run.lock and calls `finalizeInterrupted`. `State.Record` turns the marked run's record into `stopped`, whichever process records it first, so the run is recorded once; `finalizeInterrupted` clears any leftover marker. Windows returns an unsupported error.
