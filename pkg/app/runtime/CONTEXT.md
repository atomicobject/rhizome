## Vault runtime discovery, manifest, and client contract

Owns how a vault runtime (`rzm serve`, attached or headless) publishes itself and how clients find, verify, start, and drive it (SPEC-0104).

- **Entry points**: `WriteManifest`/`ReadManifest`/`RemoveManifestIfOwner`, `WriteLastPort`/`ReadLastPort` (port preference that outlives the manifest), `LiveManifest` (manifest + probe), `Probe`, `Ensure` (find or spawn), `CreateSpawnIntent`/`ElectIntent`/`CancelIntent`/`PublishManifestWithIntent` (cross-process startup and stop fence), `EnsureIndexJob`/`SubmitIndexJob`/`StreamIndexJob`/`CancelIndexJob` (the `rzm index` control-API client), `RequestShutdown`/`WaitForExit`/`TerminateHeadless` (stop a runtime), `Client.NewRequest`, `Registry` (global instance list), route and timing constants in `control.go`.
- **Key invariants**: a manifest is trusted only after `Probe` answers with the same run id and PID; the manifest is mode 0600 because it carries the control token; only the owning PID removes it; `LockPath` is the election lock and `SpawnLockPath` the client spawn lease; `BuildID` folds executable size and mtime in so development builds are distinguishable. `Ensure` never spawns while a manifest's PID is alive and listening or a live election owner is awaiting publication or draining, spawns only while holding the lease, replaces a headless build mismatch but never an attached one, and warns instead of looping when the same build is replaced twice. It records a tokenized pending intent before spawning, then passes that token to the child. Stop cancellation and manifest publication serialize through a per-vault intent gate, so a delayed child cannot publish after stop. Elected intents use a canonical lookup path captured for the runtime lifetime, so watcher and cleanup lookups survive disappearance of the original alias. Intent records remain discoverable across a dead spawning parent until a child or stop resolves them. Registry pruning removes dead PIDs but keeps live owners even if a heartbeat is old. Spawn is always `<executable> serve --headless --vault <vault root>` with `RZM_SKIP_REPO_DELEGATE=1`, detached per platform in `spawn_unix.go`/`spawn_windows.go`, released after `Start`. A closed listener means unavailable; a live election owner still prevents a competing spawn. Waiting callers poll for publication or ownership release. Nonwaiting reader callers return immediately when an owner is already starting, with no client until publication.
- **Boundary**: no runtime lifecycle logic lives here; `pkg/app/bootstrap` elects and runs, `pkg/app/web` serves the control routes, `cmd` wires them (`cmd/runtime_ensure.go`, `cmd/index_runtime.go`).

`StartIntentFor(ctx, vaultPath)` and `ListIntents(ctx)` read pending startup records under the same per-vault intent gate as updates. This prevents polling readers from blocking cancellation's file replacement on Windows. Internal reads inside a mutation reuse its gate. Discovery callers preserve their startup or stop deadlines while waiting. `ListIntents` returns already discovered intents alongside a scan error; stop-all processes known targets and reports incomplete discovery.

Runtime manifests, registry entries, and port preferences read through `pkg/fileio` and publish through its shared replacement primitive. It owns Windows deletion sharing, extended paths, and POSIX replacement, also used by repo config. Runtime writers still own temporary-file cleanup and private permissions; a failed replacement preserves the published discovery file.

- **Diagnostics**: `Ensure` records one correlated decision report with spawn, attachment, replacement, probe, unresponsive and lease-wait counts. `Client.NewRequest` propagates validated opaque diagnostic identities independently of the bearer token. Headless startup output uses `.rhizome/diagnostics/runtime-output.log`; Windows keeps null inherited descriptors so elected rotation remains possible. Legacy logs are preserved but no longer written.
