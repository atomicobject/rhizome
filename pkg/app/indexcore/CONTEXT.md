## Shared structural publication

Owns the actual structural work used by complete batch indexing and scoped live refresh. Both adapters hold the same vault indexing lease across `Discover` and `Publish`; this package neither acquires the lease nor invokes an embedding provider.

- `Discover` validates the explicit metadata indexer, captures database metadata before destructive ownership transitions, and discovers exclusive owners. A nil path scope means complete discovery; a nonnil empty scope is a no-op. Pending ownership or inactive derived debt forces complete recovery. Existing derived obligations are captured independently of their retry deadline so batch adapters cannot replace and acknowledge unfinished work.
- `Publish` persists inactive derived obligations before any structural write, expands ownership dependencies to a fixed point, prepares sealed provider projections, and consumes the same bounded parallel code and Markdown ingestion. The context may carry batch semantic streaming hooks.
- Structural ingest drains before metadata publication. Metadata drains before relationship/anchor finalization and ontology reads. `BindWriterHandlers` supplies the same typed queued controls to both adapters.
- Definition and note-anchor changes may affect unchanged code owners. A global code obligation fences dependency changes when the structural planner cannot expose a bounded closure before publication. Complete metadata fallback similarly marks global obligations before replacing derived structural rows.
- Final structural writes drain before exact derived generations become active. The returned ownership generation can then be acknowledged under the held lease. Provider or graph failures retain their independent durable obligations without requiring structural rediscovery.
- Scoped metadata uses the opaque pre-transition baseline. Ordinary edits reuse persisted paths, aliases, rows, and XOR hashes without reading untouched authored sources. Alias topology, additions, deletions, provider changes, and bootstrap state can fall back to complete publication.
- Contextual metrics measure shared discovery, structural publication, code/Markdown ingestion, ontology sync, and dependency finalization for both adapters. Recovery and scoped/complete planning counts describe observed work; reconciliation acknowledgement is measured only after the writer commits its exact generation. No per-source diagnostic disk writes or source/error text enter metrics.
