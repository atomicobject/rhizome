## pkg/app/mcp

Shared JSON tool handlers for agent-facing APIs. Wraps `pkg/app/cli` actions with structured request/response payloads.

- **Entry points**: `FilesTool`, `VaultContextTool`, `SemanticQueryTool`, `CodeSymbolTool`, `CodeReferencesTool`, `CodeSymbolContextTool`, `ExternalReferencesTool`, etc. `Config.NoteMetadata` carries the command-scoped provider-aware indexer into handlers that refresh metadata or ontology; handlers must reject a missing indexer before opening a durable store or starting that refresh.
- **Code execution**: `rzm agent code execute` runs JavaScript with a managed `rzm` namespace and returns selected results. It reuses `pkg/app/agentcode`'s in-memory client and persistent stdio service, owning setup and cleanup for the submitted script. Catalog contracts cover the operational agent CLI and local note move. Each call composes fresh resources and reuses shared handlers or local application services, preserving domain outcomes, write authority and readiness. Execution is a local CLI host control, not a new MCP handler or a security sandbox; existing operation parity remains shared.
- **Tool inventory**: `pkg/app/agentapi/catalog.go` is the authoritative tool identity, surface, mutation, and handler-factory catalog. `CapabilitiesTool` receives that inventory through `Config.ToolInventory`; it does not maintain a parallel name list. `pkg/app/oneshotruntime` separately inventories executable one-shot fronts and their composition/access policy; it must not add generic readiness to `ToolDescriptor`.
- `VaultContextTool` now supports `graphSummary` to force graph communities/orphans when ontology-first summaries are available.
- Compound `agent start` keeps ordinary code requests minimal and routes explicit rich selectors through bounded unified-index reads. It never initializes live note/coderef discovery or repairs index state; missing/stale/incompatible enrichment is an additive structured warning while minimal guidance remains usable. Standalone tools retain their normal rich live freshness path.
- `FileContextTool` rejects `ensureLinkTargets=apply` unless the caller explicitly supplies a read-write MCP config. The one-shot agent explicitly selects bounded indexed file/note/coderef reads and returns the shared `indexedEnrichment` status/warning envelope after proving indexer-version, scope, and explicit regular-file content-hash freshness; directory requests do not trigger a freshness crawl. Ordinary and read-write MCP callers retain the live path and omit that envelope. Read-only agent/indexed runtimes must never promote a request into index mutation, consume stale indexed evidence, refresh anchor scopes, or silently bootstrap live graph/ontology work. Session dedupe is the narrow exception: MCP uses a separate existing-only writer for reservations/commits while all context reads remain on the query-only Intel handle.
- Code symbol tools are read-only proof-oriented code navigation over indexed `intel_code_anchors` and `intel_edges`: use them when an agent needs definitions, callers, callees, ambiguity candidates, or compact symbol-centered context instead of broad semantic orientation.
- `ExternalReferencesTool` is the only agent/MCP projection of pathless external targets. It accepts either an exact canonical handle or exact ecosystem/module plus a deterministic symbol prefix, returns ambiguity instead of fuzzy guessing, applies local-definition precedence within one SQLite read snapshot, and bounds calls/types/members/imports independently. It is uncached and does not widen Explorer, search, default graph, chunks, embeddings, or definition surfaces.
- `SemanticQueryTool` is the single agent search surface: retrieval + answer-packet shaping (`summary`, `mustRead`, `coverage`, `confidence`, `nextQueries`) on top of raw matches. Calls without an upstream deadline use the shared 8s search ceiling. The one-shot agent command requires a current unified index, uses the caller-managed read-only Intel store and provider-only query embedders, and never falls back to a live repository crawl or a second write-capable store open; directory note seeds use a limited indexed prefix query and graph fallback uses the ready persisted raw-note snapshot. Missing/incompatible state returns structured `rzm index` remediation. Scope, path-prefix, owning-note-type, test, and exact-symbol controls become `search.Filters` and apply inside the engine before ranking, answer selection, pagination, or packing; the handler calls `unifiedsearch.Execute` once and hydrates only the returned page. Continuation is the application's single v2 cursor, encoded with bounded lossless zlib compression (existing uncompressed v2 tokens remain readable): it fixes the initial candidate bound, checks the composite generation before and after retrieval, binds the ordered source digest, and retains at most 16 exact query-vector results with at most 4,096 dimensions each so provider variation cannot duplicate or skip later pages. Callers resend the same queries, seeds, mode, and controls with the token; there is no `offset` argument. Obsolete versions require refresh. Agent CLI uses `--path-prefix` and `--note-type`; code/MCP callers use `pathPrefix` (or `folder`) and `noteType`. `compact=true` leaves diagnostics and pagination top-level while one source array owns selected bodies and answer roles refer to stable source refs. Selected bodies/previews share a synchronized physical-read cache and up to eight I/O workers; no unselected candidate is prefetched. Long-lived MCP runtimes retain their live capability path. Opt-in `timings=true` / CLI `--timings` adds the same-run `diagnostics` envelope: stable request/bootstrap phase availability, measured operation counts, provider calls, search stage/retriever timings, and remaining deadline margin. Unobserved phases and counters are explicitly unavailable rather than reported as measured zero; spans may overlap and must not be summed as wall time. `lanes` is execution diagnostics for major retrieval families (note/code vector, intel FTS, rationale FTS, symbol, refs, graph, ontology, call edges, tests) and reports `ran`, `empty`, `timed_out`, `degraded`, or `skipped` without changing ranking. Planner execution and source ordering come from the shared `pkg/app/searchengine` path used by CLI and HTTP search; MCP grouping and hydration preserve that order and choose only presentation detail. Ontology-aware matches may carry additive canonical `nodeRef` and `linkTarget` evidence; answer assembly consumes these fields and does not run retrieval or live ontology projection.
- **Semantic session dedupe**: Detailed and compact semantic responses defer session sent-state until final encoding. Each canonical source reserves one final representation decision through the existing atomic batch reservation/commit protocol. A single body retains its ordinary fingerprint; multiple distinct surviving bodies use a deterministic fingerprint of their represented set. Selected distinct siblings defer individual history filtering to that final group decision, so repeated groups converge after subset requests. Concurrent calls cannot emit the same body and merged-away, budget-omitted or further-truncated bodies remain eligible on later calls. If dedupe qualifications exceed the final budget, reservations are released without recording delivery. Multi-query packets retain lane qualifications and role references for their merged sources. Detailed publication uses only body fields surviving final JSON trimming; stubs, previews, and clipped packed-text prefixes cannot authorize a full or excerpt fingerprint. Private renderer ranges remove a competing owner's bodies from both detailed fields and packed text, including after answer/header assembly and text clipping. Failed encoding or cancellation releases owned reservations through the existing bounded recovery path.
- Code symbol tools are read-only proof-oriented code navigation over indexed `intel_code_anchors` and `intel_edges`: use them when an agent needs definitions, callers, callees, or ambiguity candidates instead of broad semantic orientation. One-shot `code-symbol`, `code-references`, `code-rationale`, and `graph-path` receive one caller-managed existing read-only index through their typed operation plan. Their handlers must not call `OpenIntelStoreBestEffort`; a request plan may also forbid fallback opens for optional live-note enrichment. Ordinary long-lived MCP callers retain the fallback policy. `code-symbol-context` remains request-derived because its source-snippet parity is not frozen.
- `ReportTool` includes `code_similarity` for path-scoped similar-function / overlapping-type triage and `rationale_attention` for deterministic comment-review queues. `rationale_attention` emits reason codes and exact snippets only; agents should research or ask humans before turning findings into new rationale comments.
- **Mutation cancellation**: direct heading rename passes the request context into the shared CLI writer lease, so a canceled MCP request stops waiting without changing source files.
- **Key invariant**: callers stay responsive; all slow init is async via `LiveRuntime`. MCP and web read fresh `runtimeview.Snapshot` values per call. Readiness is handler-managed and phase-specific; dispatch never applies a generic wait.
- **Validation remains a local agent CLI surface**: use `rzm agent validate [default|all|audit|<check>]` for structured validation. The optional selector is singular and positional; explicit checks never silently skip. Results expose `effectiveChecks`, every `completed` / `not_applicable` / `blocked` outcome, exact preparation/remediation commands, and exit 0/1/2. The `identifiers` result adds complete note/embedded pool reconciliation, deterministic plan/conflict evidence, and six timing stages under `identifierReconciliation`; Git provenance stays zero for collision-free inventories and otherwise covers only collision claimants. Preserve this envelope rather than flattening it into prose. Source-bound repair follow-ups remain non-failing JSON evidence and GitHub warnings, not actions or findings. Repairs use `rzm agent validate fix [selector]` to plan and add `--apply` explicitly; exact guidance preserves the original selector and vault/scope flags, and agent execution never prompts. Scratch CI does not consume the live code index: blocked code checks direct agents to run locally or remove them from CI composition, not to index code for scratch. Do not add a parallel MCP validation handler.

### Two-layer async init

1. **`LiveRuntime`** (in `pkg/app/bootstrap`): Handles vault resolution, leader election, capability phases (Search → Semantic → Code → Leader work)
2. **`runtimeview.View`**: non-blocking per-call snapshot plus search/semantic/code-specific waits

Tools await capabilities via `WaitFor*` methods or degrade gracefully if unavailable.

- **Ensure-link apply**: read-write `node_link` and `file_context` route explicit apply through the indexing-owned source-and-projection coordinator. They require a configured metadata indexer and live source authority. Plan/never remain read-only; partial publication errors remain visible.

### Jev evaluation

`EvaluateTool` decodes supplied state and mixed named questions into the native `pkg/typesafe` request. It resolves an explicit `TYPESAFE_API_KEY` from environment/global configuration before the Atomic bundle. No index or note runtime is required. It preserves answer discriminators, model, token usage, request ID, cancellation, and structured HTTP failure metadata. Upstream error bodies and credentials are not included in the tool error. The agent CLI, code mode, and optional MCP allowlist reuse this handler.

`EvaluateBatchTool` applies the same typed client to independent states with stable item IDs and partial outcomes. Its budget ends before the outer transport deadline where possible. Aggregate usage covers validated successes only. `CheckPathsTool` uses one unified ignore matcher per call, returning ordered normalized decisions, matching rules and per-entry path errors; it rejects outward symlinks, including missing descendants. Ignore decisions are not note-selection decisions. Both handlers have empty one-shot runtime plans.

- **Diagnostic execution boundary**: catalog handler factories use `ObserveTool`; terminal events distinguish transport errors, structured `IsError`, cancellation, and handler panic. Events include safe readiness and result-count metadata, with no request arguments or result text. Frequent tool executions do not create report files. Informational events stay off protocol output.
