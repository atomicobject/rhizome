## Unified indexing orchestration

Owns `rzm index` batch orchestration: config, locking, bounded semantic streaming, follow-up sync, validation, and maintenance. `pkg/app/indexcore` owns shared structural operations, while `pkg/app/indexwriter` owns the durable queue.

- **Entry points**: `RunUnifiedCore`, `RefreshValidationProjection`, `TryAcquireIndexLock`.
- **Key invariants**: carry an explicit `notemeta.Indexer` into validation projection and never select a format provider in indexing; seal every projectable note through the same provider publication pass while sending only Markdown to structural and anchor ingestion; publish provider search regions into the shared lexical index in the metadata transaction; keep one queued SQLite writer lane; keep final correctness barriers explicit; treat `--rebuild` as operator authorization to clobber the unified DB plus WAL/SHM sidecars after acquiring the index lock, recreate every domain during explicit rebuilds, and never clobber during ordinary indexing; batch counts and ingest share the system-note selection contract, so exact `CONTEXT.md` bypasses ordinary note includes/excludes while hard ignore/infrastructure boundaries still win; ordinary validation projection publishes provider-derived metadata/links/fragment targets before ontology and never advances code/chunk/embedding/graph freshness; held-lease post-apply refresh reingests exact changed note anchor declarations and marks `code_anchors` fresh only for committed code-anchor repairs or note-path ownership changes, never unrelated content writes; code-anchor evidence combines project-code count/generation with a deterministic note-selector/glob/ownership fingerprint whose scan stays inside note-anchor tables; untouched domains expose persisted evidence or `unavailable`; successful unified indexing preserves configured code enablement and stamps the authoritative local scope hash so its advertised validation prerequisite becomes usable; use `semanticruntime` lanes for provider work; primary-chunk freshness follows source/schema/provider fingerprints; keep timing labels truthful.
- **Semantic lifetime**: unified semantic resources own every provider they construct, close partial setup on every failure, and drain runtime nodes/stores before optional provider cache closers. Shared lanes still borrow providers.
- **Ownership boundary**: `pkg/app/noteownership` owns the one-pass candidate snapshot, source-only transition preparation, and exact-generation reconciliation tracker. Both drivers consume that snapshot through the same structural core and typed queued controls. Queued writer batches may overlap provider work. Sync publishes each ontology delta and its catalog in one transaction; standalone ontology node writes still drain after deltas so catalog-owned rows cannot be truncated by a trailing full rebuild. Initial streaming producers and queued body writes finish before the final ontology catalog refresh, which may delete their chunk parents. Their drain closes producers and flushes accepted writes before reporting caller cancellation, joining cancellation with any queue error instead of skipping the durability barrier. Ownership replacement and exact-generation reconciliation acknowledgement are specific synchronous writer controls: they drain the captured submit barrier before their one store call and are never generic closures or idle-flushed batches.
- **Code persistence boundary**: external evidence is part of queued `CodeIndexWork`, not a side writer. The code flush owns durable refs followed by set-wise natural-key external association replacement in one transaction; both threshold/idle drains and explicit barriers use that same path.
- **Validation boundary**: ordinary product orchestration preflights pending repair journals, then repeats that barrier through `BeforeMutation` while normal refresh owns the canonical lock and before any projection store opens. The lock-already-held core stays package-private. `ValidationProjectionPostApplyRefresher` borrows EFF-0047's exact opaque `pkg/validate.IndexLockLease`, proves the canonical vault root, maps committed repair and rename endpoints to strict exact paths, and transfers the prepared runtime owner without acquiring or releasing the lock. Consumers close that owner once after prepared checks rather than re-indexing through `EnsureFreshRuntime`. Scratch projection owns a process-local temporary DB and cleanup; it never consumes the live code index.

- **Ensure-link mutation**: `ApplyNodeLinkTargets` preflights the explicit metadata indexer, vault, paths, schema, and live store, then holds the canonical index lock across block-ID insertion and the existing queued exact metadata/ontology projection. It retains the opened store through convergence, retries already-linkable paths, reports source-committed failures, and never publishes a full read generation.

Validation publication has its own freshness state. Structural ownership is acknowledged after shared structural finalization and durable derived obligations, before optional provider completion. The semantic watcher retains hub inputs independently of read-side cache refreshes.

- Complete code debt replays a fresh complete-owner semantic plan after structural context, streaming publication, and ontology follow-up have drained. Current chunk hashes reuse successful early work; delayed prior debt forces replay even when sources are unchanged. Graph recovery likewise ignores the retry deadline when an explicit batch run repairs an existing obligation.

- Active note and ontology debt triggers full current projected-source replay regardless of retry deadline, including raw-note compatibility and stale note-store cleanup. Ontology semantic work uses provider source snapshots, preserving root-only HTML evidence.

- **Persistent diagnostics**: lane admissions and in-process commands install bounded collectors independently of console `--timings`. The shared core records its complete lifetime through deferred drain, writer flush/close and streaming durability barriers, pending-generation recovery, and explicit call-edge/scope recompute reasons. Safe events are aggregate; source bodies, provider response bodies, and per-file disk appends are excluded. Snapshot coverage states when retained samples or intervals omit later detail.
