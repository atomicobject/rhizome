## Request-scoped NodeRef read facade

`noderead.Scope` batches ontology reads for graph, query, search, semantic indexing, and web read paths. Prefer it over ad hoc note-path SQL plus projection loops when a caller needs many nodes, embedded refs, locators, relation counts, neighborhoods, or graph facts.

- **Entry points**: `Scope.Execute`, `Scope.Hydrate`, `Scope.Resolve`, `Scope.TypeInstances`, `Scope.Traverse`, `Scope.Neighborhood`, `Scope.Expand`, `Scope.Walk`, `Scope.RelationCounts`, `Scope.Graph`, `Scope.GraphFacts`, `Scope.CodeGraphLinks`, `Scope.Projection`, `Scope.IndexedFieldValues` / `Scope.IndexedRecordFieldValues` (committed indexed field rows, including link target refs, for projections or hydrated records such as note roots, in batched reads; overlay-touched notes omitted). Consumers match an authored link value to its row with `IndexedLinkRow` (field name and value text) so a value edited since indexing never inherits its predecessor's target.
- **Walk ownership**: `Scope.Walk` is the sole path-oriented ontology walk implementation. It adapts the batched `Scope.Expand` result to the stable CLI walk shape; do not add traversal loops under `pkg/ontology` or in individual surfaces.
- **Expansion identity and bounds**: `Expand` preserves requested source groups while canonicalizing the initial frontier. Ownership, deduplication, and seen sets use full ref identity; public groups use the existing result keys and only unambiguous locator aliases. The minimum positive `FirstTotal`, `MaxEdges`, and edge budget bounds each emitted row, including shared-frontier evidence repeated for different roots. Target hydration stays unique and per-root node limits retain their existing meaning.
- **Plan execution**: `Scope.Execute` accepts roots, field selections, relation selections, hydration profile, limits/budget, and diagnostics. It runs relation work breadth-first by depth, coalesces compatible same-depth specs, hydrates unique targets once, and returns per-call diagnostic deltas.
- **Field hydration**: summary fields use indexed metadata/properties/tags plus indexed ontology type rows, including path-matched types without authored `type` frontmatter. Content and note-level section fields opt into content/workspace hydration. Do not add file reads to summary hydration paths. `ResolveRequest.IndexOnly` rejects catalog-missing fragments instead of projecting source.
- **Provider root hydration**: root records carry format, raw and derived representation labels, and executable capabilities. `Service.NoteFormats` is required to project a non-Markdown workspace root; provider-current rows without executable runtime authority remain readable as indexed summaries but never enter a guessed parser.
- **Host state**: snapshot reads load metadata only for requested hosts. Application composition may supply `Service.ExactNoteMetadataRows` after checking provider freshness and current note ownership, plus exact property/tag loaders for those admitted paths; otherwise the exported Store contract keeps global metadata readiness. During startup reconciliation, application composition materializes those exact metadata, property, and tag facts from one SQLite read transaction and supplies immutable loaders for the request. Missing metadata is a scope-local miss, not a reason to inventory the vault. Projection enrichment batches the requested hosts' types/assessments; ordinary summary reads stay on metadata/properties/tags. Embedded cache entries distinguish summary from content capability, including negative results.
- **Identity resolution**: `ResolveRequest.OmitLocators` omits locator fields and link-fix diagnostics for ref/record consumers while retaining canonical resolution and ambiguity. Positional unanchored item refs carrying structural identity use one batched host-catalog lookup for a unique fingerprint match and otherwise verify against current projected content. Explicit ensure-plan/apply overrides omission; default Resolve behavior stays complete.
- Public `#struct:` and `#node:` selectors resolve through batched host-catalog reads. `IndexOnly` misses and ambiguity remain unresolved. Resolve returns the hydrated canonical ref with its record after a staged item moves.
- **Preview overlay contract**: `ScopeOptions.ReadOverlay` is the only edit-session hook in this package. Callers restore/preview sessions elsewhere, then pass touched-note markdown into noderead. With an overlay, `Hydrate` and `TypeInstances` project touched notes from preview content, merge touched rows with committed rows by canonical `NodeRef`, and apply final filter/sort/page after the merge. Query recipes and views stay read-only selectors.
- **Overlay limits**: overlay type-list reads may overfetch committed rows before the final merge so a staged edit can move rows across filters/pages. Keep this bounded and explicit; expand predicate support deliberately instead of adding ad hoc operators in callers. Staged scalar rows evaluate `exists`, `eq`, `in`, `gt`, `gte`, `lt`, and `lte` with the shared `pushdown/scalars.go` rules, preserving SQL operand typing and textual fallback; `exists` requires nonempty normalized text; an operator the overlay cannot evaluate excludes the staged row rather than passing it. The all-notes scope applies staged titles, types, deletions, and additions the same way.
- **Merged sort values**: the post-merge sort prepares each candidate's typed scalar keys once from indexed rows, privately captured projection values/presence, or the field's declared metadata source. Authored null/empty bindings retain the indexed blank text sort presence without becoming nonempty `exists` matches. DateTime comparison keeps canonical indexed text and authored offsets. Builtin path/notePath values preserve exact path casing for predicates and sorts. The comparator performs no extraction, store reads, or projection. Committed note records carry raw metadata only, so never compare them by raw frontmatter key or inline props.
- **Merged sort ordering**: `NullsLast` keeps missing values last in either direction. Without it, match SQLite's native placement: missing values first ascending and last descending. Direction applies to present values; list fields select their minimum ascending and maximum descending, and equal values retain SQL's note-path, numeric source-offset, and catalog node-ID tie order. Full canonical refs continue to own merge/cache identity.
- **Note ref canonicalization**: a note ref's locator is the ref itself, so `Neighborhood` (and relation counts) canonicalize only embedded refs through locators. Building a note locator lists every vault file; never do it to canonicalize note roots.
- **Locator keys**: NOTE source locators use the bare note path even when catalog refs carry structural fingerprints or node IDs. This public locator spelling does not replace the complete canonical refs used in hydration/cache keys.
- **Key invariants**: cache keys must preserve canonical `NodeRef`; catalog rows are the fast path for embedded identity; projection fallback is bounded and request/job scoped; empty misses are cached so broad callers do not requery; traversal cache entries should be reusable by lower limits when an unbounded batch is already known; create a fresh scope per concurrent request/job.
- **Fallback read boundary**: `_FallbackNote` / `_FallbackSection` rows resolve and hydrate for search/navigation, but remain hidden from public type-list reads unless a diagnostic path explicitly asks for internal catalog evidence.
- **Graph contract**: `Scope.Graph` owns profile merge over indexed ontology rows and fallback doc/code rows. Preserve embedded endpoint scope, ontology-over-wikilink precedence, graph-profile semantics, `IncludeCodeEdges`/`IncludeCalls` opt-in, and diagnostics per [[ontology-indexed-read-model-contract]].
- **Graph precedence cost**: assemble typed edges before fallback document edges and record their exact endpoint pairs within the request. Suppression ignores pair direction, but typed relations retain their direction, name, provenance, and accumulated weight. Do not scan the growing edge collection for each candidate; `GraphFacts` needs the full candidate set before its final filters and limits.

- **Explicit apply**: `Scope.Resolve` and `Scope.LocatorsWithEnsure` share one apply dispatch through `Service.ApplyLinkTargets`, which delegates the whole source edit and durable metadata/ontology convergence to the live writer owner. Missing capability and preview scopes reject apply. Every explicit embedded apply runs convergence, including retries with no remaining fix actions; every attempt drops all request caches and invalidates shared derived state. CatalogStore is read-only. Graph, GraphFacts, and note-path builders capture the scope cache generation before unlocked work and publish only if it still matches; apply invalidation advances that generation. Overlapping reads may finish, but cannot restore pre-apply entries for later reads.

- Explicit relative wikilinks resolve against the referring note before canonical hydration. Missing relative targets remain unresolved, even when another directory contains the same basename.

- **Canceled reads are retryable operation failures**: preserve cancellation and deadline errors before publishing projection/ref misses, source-snapshot errors, or unresolved locators. Check the context after lower readers return, including readers that produce diagnostics. A source child deadline also remains a typed operation error while the caller context stays live. Ordinary per-host error tolerance and real-miss memoization remain unchanged.

- **Scope shape**: `OntologyShape` reads the committed `readmodel.ShapeStore` snapshot without hydration or overlays. It excludes embedded schema roles, deduplicates note pairs, classifies broad `Note` fields as plain links, and derives interface lifecycle/gaps from the interface profile. Parts select members, links, or folder aggregates; rebuilding marks unpublished or mismatched index state.
