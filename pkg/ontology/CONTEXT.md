## Ontology projection, edit, and indexed read contracts

Compiles GraphQL SDL into typed Markdown contracts, projects source-preserving `NodeRef` views, and hosts ontology edit replay. Provider-current Markdown remains source of truth; edits must patch targeted spans instead of re-rendering whole notes.

- **Entry points**: `LoadSchema`, `BuildRootDocumentSnapshot`, `ProjectNode`, `ProjectDocumentNodesFromSnapshot`, `BuildIndexFromNoteSources`, `SyncPaths`, `SyncPublishedPaths`, `PublishedRuntimeWithStore`, `BuildNodeWorkspace`, `NewEditSession`, `EditSession.PreviewWithRefLineage`.
- **Provider root boundary**: `RootDocumentSnapshot` seals raw source, provider identity and projection evidence, root metadata, diagnostics, and search regions. `MarkdownStructure` exists only for Markdown and is produced by the genuine `BuildDocumentSnapshot`; HTML and other root-only formats retain one note root without fabricated sections or Markdown spans.
- **Resolver lifetime**: catalog construction, structural-edge traversal, and embedded validation each reuse one projection resolver for child and global-source discovery. Keep that resolver local to its operation and preserve canonical traversal order, semantic parents, fallback behavior, and derived identities.
- **Unanchored source identity**: list and checkbox structural fingerprints derive from owned normalized content plus semantic parent, shape, and markers. They survive unrelated edits above the item. Identical unanchored content is ambiguous and must fail closed; mint a block ID when a durable link is needed.
- **Build convergence**: full and incremental indexed builds use their injected `notemeta.Indexer` to load provider-current `NoteSourceSnapshot` inputs, then share one provider-neutral root projector. Markdown alone adds a genuine `DocumentSnapshot` for structural projection. Incremental sync promotes any current path with missing, stale, or corrupt assessment/state evidence into forced recomputation so partial read models self-heal without a full rebuild.
- **Scalar assessment ownership**: `AssessScalarFieldValues` applies the existing compiled-field rules to extracted values and actual authored presence without source or store reads. Indexing owns extraction; query overlays supply their current staged values. Requiredness, singular/list cardinality, enum/type checks, and derivable-identity exemptions stay shared, while presentation retains the raw authored values.
- **Projectable metadata boundary**: `ProjectableMetadataPaths` selects only current rows with an executable format projector. Every such source receives one typed or fallback root; only Markdown receives structural children.
- **Source-edit inventory**: `ProjectDocumentNodesFromSnapshot` returns the note root plus every structural and Markdown source node once, in deterministic source order, with full-`NodeRef` identity. `FieldBinding.ValueRangesExact` is the write-safety gate: plain source shapes provide `Values`/`ValueRanges` 1:1; ambiguous YAML remains readable but must not be patched from approximate ranges.
- **Read boundary**: use `pkg/ontology/noderead` for batched hydration, type lists, locators, traversal, graph facts, and card-owner reads. One scope is safe within one request/job; independent concurrent work gets its own scope.
- **Indexed graph**: sync owns `ontology_nodes`/`ontology_edges`; sqlite exposes `readmodel.GraphStore`; `noderead` merges endpoint identity, profiles, doc/code fallback, and diagnostics per [[ontology-indexed-read-model-contract]].
- **Atomic publication**: sync carries the node catalog inside `OntologyDelta.ReadModels`; full rebuild clears and replacement rows commit together. The direct full-index path uses the same store transaction. Failed publication preserves the previous catalog, and validation retains its semantic-preserving writer.
- **Indexed fields**: sync also owns `ontology_node_field_values` and link-field dependency rows. Build them from `NodeProjection.Fields`, replace them atomically with catalog rows for touched paths, and use them for typed predicates/sort/summary hydration rather than reparsing markdown.
- **Dependency convergence**: metadata-expanded changed paths are load candidates, not evidence that each source's bytes changed. Keep graph/relation neighbors and typed-link dependency sources in the forced recompute set even when they are also candidates. Unchanged direct sources without a dependency obligation retain fingerprint skipping; deleted paths never enter projection work. Materialization v13 repairs older stale targets and findings once during ordinary freshness refresh.
- **Published-source boundary**: coordinators that already durably published and acknowledged note metadata use `SyncPublishedPaths`; it must not invoke metadata `Ensure`, re-enumerate, or republish notes. General callers retain `SyncPaths` metadata-freshness behavior; both use explicit `notemeta.Indexer` composition.
- **Published runtime boundary**: after the same writer barrier, `PublishedRuntimeWithStore` is the read-only readiness gate for validation and serving. It loads the schema and verifies stored schema, notes, materialization, and complete read-model evidence without discovering files, reading sources, projecting, or repairing state.
- **Authored Note base**: schema authors may declare `interface Note` for shared optional note fields. `Note` fields must be nullable; the compiler injects them into every file-backed note type, and GraphQL exposes them through universal `NoteNode` reads for typed and otherwise-untyped notes. Domain-specific interfaces remain explicit opt-in.
- **Section admission**: type-role and relation-target checks classify Section ancestry from the complete parsed SDL with cycle protection. Compilation order cannot admit Section-derived `@link` or `@neighbors` targets; concrete Section containment, universal `Note` links, and embedded reverse sources retain their existing contracts.
- **Display metadata**: type-level `@display` owns navigation labels and grouping. Field-level `@display` owns compact summary role, the parent role that links a record to its parent of the same tree, importance, and hover visibility; these hints inherit through interfaces and remain presentation-only.
- **Default and fallback policy**: a single concrete file-backed type may declare `@node(default: true)` with no `paths`/`matches`; it resolves otherwise-untyped notes as authored semantics. `_FallbackNote` and `_FallbackSection` still give unresolved notes/sections internal node/search identity and stay hidden from public type reads.
- **Identifier strategy boundary**: compiled `IdentifierFormat.StrategyContract` is the sole strategy dispatch point and owns pure request validation, allocation, parse/format, reservation-family, and replacement behavior. `pkg/ontology/idalloc` owns repository/type lookup, pools immutable reservation inventory by the compiled `<prefix><separator>` namespace, and adapts strategy results to external diagnostics. Note roots retain raw preferred-source/frontmatter alias reads; nonderived embedded owners use canonical node-scoped fields, keyed by node identity and reported by source locator. Distinct owners in one note remain distinct, and failed reads cannot imply an available identifier.
- **Edit invariants**: every target path is canonicalized before grouping or publication. Replay keeps verified original source documents, rebases unrelated drift, and conflicts on changes to the edited field, missing nodes, collection membership, duplicate IDs, duplicate-heading ambiguity, same-parent reorder drift, or span ownership violations. Field edits preserve unset, empty scalar, and empty list as distinct values and validate changed values against the compiled schema. `PreviewWithRefLineage` is authority only for a ref already resolved against that exact locked preview; it maps uniquely surviving field-edit output back to its staged ref, rejects ambiguous identity, and never carries identity across deletion or replacement. `AddSectionField` inserts beneath the exact structural parent in compiled-schema sibling order; repair code never appends a guessed heading at EOF.
- **Note-root replay identity**: replay addresses a note root by its path. A root's structural fingerprint covers every section offset, so any earlier staged edit to the note changes it; `validateResolvedProjectionRef` therefore does not compare root fingerprints. Section and embedded refs still verify structural identity and conflict on drift.
- **Inline bodies**: `NodeBodyBlock.RendersInline` decides which sections carry editable narrative bodies: declared `INLINE` sections and headings that no schema field declares. The REST workspace graph and GraphQL workspace bodies share it, and an undeclared heading's body nests under the section that contains it.
- **Selector expressions and ambiguity**: `@node(matches:)` expressions split on uppercase `AND`/`OR`/`NOT` even with fewer than two colons; lowercase words stay part of a literal path. When several types match, `mostSpecificCandidate` picks one only by strict selector dominance; negated clauses are not comparable, and ties stay `type_ambiguous`.
- **Edit publication**: edit sessions own typed replay, preview, and conflict evidence. Browser publication adapts the reviewed complete-source replacements into the validate repair engine, which owns recovery, the canonical vault lease, source preconditions, mode preservation, exact refresh, postchecks, and the durable request receipt. Provider-aware root edits preserve unrelated provider metadata and accept only root metadata operations for formats without structural mutation support. Direct `EditSession.Commit` rejects provider-root-only writes so they cannot bypass the shared writer.
- **Namespace admission**: after the global writer lease is held, direct edits and edit recovery refuse prepared or unsettled native namespace evidence before per-note locks or writes. `CheckNoPendingEditJournals` is read-only under the native owner’s already-held lease.
- **Edit journal recovery**: committed ontology journals own verified artifact cleanup only and preserve later source edits, replacements, and deletion. All artifact paths, parent confinement, regular-file content witnesses, and required receipt evidence are preflighted before mutation; receipts remain intact and the journal is removed last. Prepared source witnesses still gate rollback, and inferred complete publication is marked committed before cleanup. Missing terminal source directories are absent cleanup paths, never a reason to chase moved artifacts.
- **Field capabilities**: `BuildNodeWorkspace` publishes one owner-specific `NodeFieldCapability` per projected field plus the exact source revision used to read it. The capability carries effective display importance, including the NORMAL default. Consumers must choose controls, presentation order, and write operations from that capability; they must not join metadata by field name across root and nested owners.

- **Catalog completeness**: assessment JSON stores the canonical emitted `catalogNodeCount` and `catalogNodeDigest` (including explicit emptiness); readiness compares both with current catalog rows and keeps timestamp/field checks. Blank notes retain fallback roots in full and incremental builds. Missing evidence or a mismatched catalog is incomplete and forces repair, including during unrelated incremental edits. `PublishedCatalogPaths` additionally matches the selected provider-current source hash and schema before navigation admission. Materialization v8 refreshes older derived state once, including exact non-Markdown authored-link resolution; v10 re-derives plain-text H1 titles and v11 re-resolves types after the selector operator fix.
