## Read-only ontology query execution

Builds GraphQL-shaped query results from compiled SDL, indexed note metadata, ontology edges, markdown projection, and synthetic runtime roots. Keep this as a bounded read layer: note roots need path/find/property/semantic bounds, runtime roots must stay read-only/provider-backed, and relation scheduling compiles through `noderead.Scope.Execute` rather than becoming a second indexing runtime.

- **Entry points**: `BuildExecutableSchema`, `Prepare`, `Execute`.
- **Bounded identity reads**: target resolution keeps catalog and ambiguity handling inside `noderead.Scope.Resolve`, opting out of unused locator rendering. The shared scope owns provider-current fallback and known misses; query loaders must not repeat fallback with a whole-vault snapshot.
- **Path availability during reconciliation**: an operation containing only singular note-owned `node` / `note` roots may use application-supplied exact metadata, properties, and tags after provider and ownership checks when every nested selection is backed by raw-note projection. Fragmented `node` refs require the complete model because section and embedded-node resolution uses the ontology catalog and projection. `__typename`, `resolvedType`, `ref.typeName`, and type-conditioned fragments also require the complete type model even when their selected fields are raw-note-backed. The application supplies exact facts through immutable loaders materialized from one SQLite read transaction, so one request cannot mix publication generations. Workspace, neighborhood, local-graph, built-in relation, authored node/link, and section selections require complete readiness. Broad, mixed, identifier, code, runtime, semantic, validation, and introspection operations retain complete readiness; callers without the optional exact-row dependency retain globally gated Store reads.
- **Projection-owned children**: field bindings and global-source refs emitted from the current `DocumentSnapshot` may use bound projection, which verifies range and structural identity together so identical unanchored children remain listable. External, catalog, copied, and replayed refs stay on ordinary resolution and preserve ambiguity errors.
- **Runtime roots**: `ontology`, `code`, and `agent` are built-in query roots, not ontology SDL types. They adapt existing authoring-guide/idalloc/file-context/agent-surface providers into structured read results with warnings when optional providers are unavailable. `ontology.nextId` accepts ordered prospective `paths` and returns additive path-correlated allocation metadata; sequential-only numeric metadata is nullable for non-sequential strategies.
- **Record facts**: note and embedded object types expose `updatedAt` (the source note's indexed modification time) and `issueCount` (published validation issues on the note, or on the embedded node) unless an authored field claims the name. Interfaces declare them only when every implementor carries them and no extending interface authors the name; an interface without implementors declares them. Resolvers leave placeholders that `fillRecordFacts` fills after the selection tree resolves, so every selected fact at any depth shares one batched read (`record_facts.go`).
- **Note interfaces**: `NoteNode` is the universal runtime interface for file-backed note reads. When the authored schema defines `interface Note`, generated `NoteNode` implements it and every file-backed note object exposes those nullable general fields, including otherwise-untyped `note(path:)` reads. Domain-specific interfaces remain explicit opt-in.
- **Source contract**: `NoteNode.content` is authored raw UTF-8. `format`, `sourceRepresentation`, `evidenceRepresentation`, and `sourceCapabilities` let clients select rendering and editing behavior from the admitted executable provider rather than an extension.
- **Workspace projection**: `Node.workspace` is the composable public replacement for browser node-workspace reads. It exposes the focused node's schema-aware semantic `parentRef` and its index-read `parentTitle`, source-preserving field/collection metadata, bounded `bodies(first:)` entries with ordered body blocks and typed structural bindings, bounded `sourceLinks(first:)` occurrences in authored order, assessment, canonical structural refs, typed relation groups plus bounded `connected`/`backlinks`/`code` graph evidence, status/capabilities, version, and selected-domain flags. Field capabilities include effective display importance so frontend property ordering uses the compiled schema and the NORMAL default. Relation field states expose `links` (value, resolved `ref`, target `title`): targets come from indexed field values via `Scope.IndexedFieldValues` in one read shared by `fields` and `bodies`, titled by one summary hydration; staged or changed values fall back to one index-only resolve. Unresolved and ambiguous values keep null ref/title. Source links preserve each authored internal link or embed while resolving unique known-note targets in one shared scope batch; unresolved/unsupported syntax stays visible with its authored target. Same-file Markdown anchors retain their raw fragment-only destination and use the request's canonical source path, so literal percent escapes and hashes in that filename cannot be reparsed as URL syntax. Body block Markdown preserves the projection's whitespace, including leading separators and indentation, so staged narrative edits cannot join prose to a block locator. Body entries include metadata-only PANE/collection descendants so clients can render compact child identity without forcing nested body content; only the focus and INLINE paths carry body blocks. Relation targets retain their exact note/section/embedded/code kind and use batched summary hydration for projected titles, with path-derived labels only as fallback. Concrete-type link fields marked `@workspaceMember` add ordered owner/member navigation for the owner and every explicitly linked member; incoming membership discovery pairs each concrete owner type with its declared schema fields before applying the shared bound, owner expansion batches all instances of each owner type through the shared scope, and either bound reports a GraphQL error instead of silently dropping links. Incoming annotated edges expose multiple owners separately, and promoted members are removed from generic relation groups by full `NodeRef` identity. Pane stacks, rails, tabs, and rendered-outline orchestration remain frontend adapter concerns.
- **Document root locators**: serialize NOTE refs as their bare note path even when catalog identity includes a structural fingerprint or node ID. Previously emitted `#struct:` root locators resolve as notes only when the fingerprint matches the current projected document root; missing section or root identities remain errors.
- **Locator contract**: public `NodeLocator` is a direct projection of the canonical ontology locator: its own `ref`/`kind`, the link target's `ref`, diagnostics, and proposed `fixActions` stay selectable so a client can stage make-linkable work without fabricating node identity or inferring a block ID. The projection remains read-only; applying an action stays on the explicit edit-session path.
- **Key invariants**: note roots require path/find/property/semantic bounds; runtime roots require bounded field arguments; generated roots mirror compiled SDL; structural `@link`, its opt-in named `@reverse(field:)` read, and ambient `@neighbors` stay separate; reverse lists preserve embedded source refs and never collapse several embedded nodes to one containing note. `NodeRef` locators must survive note/section selection. Link filters use `eq`/`in` for resolved target membership or `exists`; unsupported operators and unresolved targets return errors. Scalar `contains` remains substring matching.
- **Execution shape**: roots resolve to bounded note records/`NodeRef`s, then note selection sets compile into a `noderead.NodeReadPlan`. GraphQL keeps JSON projection, aliases/fragments, nullability/errors, and section rendering; `noderead` owns BFS relation scheduling, hydration, request cache reuse, limits, and diagnostics.
- **Indexed ontology-node roots**: note and embedded types can push supported `filters`/`sort` into `OntologyNodesByTypePlan` before pagination and hydrate selected indexed fields from `ontology_node_field_values`. Project markdown only for `content`, children/workspace bodies, or non-indexed selections.
- **Scalar selection validation**: untouched note fields use their batched committed assessment; staged root fields use `ontology.AssessScalarFieldValues` with already-loaded current values and authored presence. Invalid optional fields return null, invalid required fields omit the field and report its response path, and invalid-to-valid edits replace stale diagnostics. Cardinality, enum/list validation, authored empty lists, and accepted spellings use the existing ontology assessment rules. Raw frontmatter and workspace values remain authored text for editing; predicate coercion does not own this selection policy.
- **Residual scalar parity**: selector filters, residual sorts, and noderead overlay comparisons share `pushdown/scalars.go` with compiled field types and typed rows, preserving exact integers and the index's canonical date/datetime text. Sort keys are prepared once per record; lists select their minimum ascending or maximum descending, and missing or invalid typed values stay last in either direction. Authored blank text bindings remain present for sorting, matching the indexed empty string. Text fields retain text comparison even when their values look numeric. Equal sort keys retain SQL's note-path, numeric source-offset, and canonical node-ID order. Predicate operands keep SQL's typed-column or textual fallback; authored blank sort presence stays separate from nonempty `exists` membership. Builtin `path`/`notePath` equality and membership preserve canonical path case, and their sort keys use raw paths before pagination, including find/property and coherent residual sorts. Scalar-selection validation remains independent of predicate coercion.
- **Typed-root coverage**: generated typed roots retain their array result and accept `offset` (default zero). Every successful typed root adds `extensions.typedRoots[responseAlias]` with `requestedFirst`, `returnedCount`, `offset`, nullable `hasMore`, nullable `nextOffset`, and `status`. A one-row lookahead distinguishes an exactly full page from a capped page; `status: complete` proves the selected result was exhausted, and `status: capped` supplies the next offset. `unknown_page_bound` means the 5000-row public page maximum prevented lookahead but a next offset can be probed. `unknown_candidate_bound` means a residual candidate read hit its 5000-row safety cap; `hasMore` and `nextOffset` are null, so narrow or repartition that query. Indexed typed roots continue with the existing SQL offset; selector and residual paths only continue while the bounded candidate window permits. Each response alias has independent coverage, including through saved recipes and code mode, because both serialize the shared `query.Result`.
- **Typed-root path pages**: `path` selects at most one note; a positive `offset` returns an empty array with complete coverage. Link `eq`/`in` target resolution is request-scoped and bounded through the shared pushdown resolver. Canonical note-root paths use provider-neutral indexed lookup; title/alias matching above 5000 target candidates reports `link_filter_resolution_incomplete` and asks for a canonical path or narrower target type.
- **Diagnostics**: keep ordinary roots quiet. Use `ontology.queryPlan(...)` when callers need to explain indexed vs residual vs projection fallback behavior or stale/missing indexed roots.
- **Broad selector inventory**: find and interface roots share a successful metadata inventory read within one execution. Failed reads remain retryable, cancellation still propagates, and the next execution consults the provider again. Ranking, type filtering, and pagination retain their existing order; candidate type reads remain batched through the scope.
- **Batching**: one loader set creates one `noderead.Scope`; relation caches are keyed by relation/provenance/type/limit and must remember empty source groups. Selection pre-execution should warm the same scope used by scalar/relation resolvers so per-parent field resolution hits cache instead of requerying SQLite/files.
- **Sections**: note-level section selections are still projected in this package, but they must request note content through `noderead` content hydration. Section neighbor/subtree behavior remains GraphQL-local unless generalized in `noderead`.
- **Canonical section identity**: lightweight heading-match records project their public `ref` from the current note snapshot, retaining structural fingerprints for navigation. Indexed catalog refs and existing projections retain their ref-only fast path without reading note content. Enrich serialized refs without changing internal scheduling refs or their warmed cache keys.
- **Section refs**: explicit Markdown paths with generated heading fragments resolve as `SECTION`; keep those fragments separate from explicit `#^block-id` refs. A caret-qualified ref must never widen to or be shadowed by a generated heading fragment with the same text.
- **Search**: the `search` root runs the shared unified engine restricted to notes through `Deps.NoteSearcher` (no mode argument; `type` filters owning-note concrete types before retrieval); `semantic:` selectors remain chunk-only through `Deps.SemanticSearcher`. Both are explicit opt-ins. Missing searcher, unavailable runtime providers, unresolved roots, unsupported fields, and relation misses must return warnings/errors/nulls instead of widening. A bounded read of the shared `noderead.Scope` note's own preferred field gates comprehensive preferred-identifier discovery: participating note hits union note and embedded candidates so mixed-kind collisions remain explicitly ambiguous, while unrelated path/alias hits keep their established precedence without type-wide scans.
- **Validation selection**: `validation(check:, scopeKind:, scopeKey:)` resolves IDs, public names, and aliases through the shared validation catalog and global/file/note/node/type/interface scopes through the persisted membership model. Unknown checks, invalid scopes, and invalid page limits return typed GraphQL errors. Scope counts and each nested `issues(first:)` page use the same generation, filters, and canonical check identity.
