# Namespace Git preparation

`Prepare` in [prepare.go](prepare.go) is the specific Git staging helper for the [native namespace transaction plan](../../../docs/efforts/2026-10-04-note-namespace-transactions.md). The validation engine supplies admitted canonical moves and captured original endpoint bytes/modes. The helper writes only its exclusive child below engine-owned scratch and returns standalone index bytes with ordered successful Git moves. It does not publish authored files, acquire a live lock, persist a journal, recover, or refresh projections.

The raw original index witness is admission authority. The engine must acquire the bound canonical `index.lock` and revalidate that witness immediately before authored publication. The normalized rollback preserves original staging entries, merge stages, persistent flags and resolve-undo state. The separate candidate follows actual `git mv` semantics for the moved entry, including its flags, intent-to-add and resolve-undo behavior, while keeping staged versus dirty content distinct. Split/sparse encoding and cache/stat bookkeeping may normalize. The engine alone durably owns returned snapshots and lock/decision/release evidence.

Preparation runs Git against the bound directory-backed repository, private copied indexes and an affected-file shadow tree. Both indexes use `core.splitIndex=false` and `index.sparse=false`; executable fsmonitor is disabled and `core.hooksPath` points to an owned empty directory for every command. Index writes can otherwise execute the live `post-index-change` hook even with a private index. These settings prevent the demonstrated creation of live shared-index/tree files and execution of index hooks. Existing immutable object/shared-index mtimes may freshen, but live authored bytes, index, refs, configuration, modes and metadata path inventory remain unchanged. Prepared snapshots do not depend on old split-index files surviving.

Nonempty inherited repository/index/object/namespace selectors are hard-refused before scratch changes. Admitted commands use a bound sanitized Git environment with global/system config disabled and no lazy network fetch. Actual Git tests cover synthetic global split-index/index-version and file-mode/ignore-case configuration, including executable staging distinct from dirty mode. This is staging parity for the supported moves, not a promise to reproduce every arbitrary global configuration or executable hook. Linked/shared worktree layouts retain the existing filesystem fallback.

`ErrFallback` permits the engine's explicit filesystem fallback only before a live effect. Malformed move/original/scratch/index admission is a hard error; cancellation stays cancellation. An all-untracked or absent-index batch has no Git participant. A mixed batch retains each successful tracked move and leaves untracked moves without a history claim. Failed preparation returns no partial candidate.

The real-Git matrix compares prepared staging with direct M1 moves, inventories unchanged live state, and installs only prepared index bytes in disposable repositories for later reads/tree production. Engine lock ownership, crash decisions, live replacement, projection convergence and native application integration are separate coverage obligations.
