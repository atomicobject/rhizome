## Cross-process indexing lock

Coordinates the vault runtime's indexing lane, one-shot CLI writers, and the runtime election with `.rhizome/index.lock` and `.rhizome/runtime.lock`, plus optional priority requests.

- **Entry points**: `TryAcquire`, `TryAcquireWithOptions` (role, process-lifetime mode), `StartHeartbeat`, `StartYieldingHeartbeat`, `RequestPriority`, `PriorityRequest.Active`, `PriorityRequest.Close`, `CheckPriority`, `ReadLockData`, `LastHeartbeat`, `PIDAlive`.
- **Key invariants**: acquire is non-blocking; fresh/corrupt locks are treated as held; a dead PID permits automatic recovery in the matching runtime identity or a proven earlier local boot, never a live PID regardless of heartbeat age. Recovery across boots requires the exact recorded hostname, a valid earlier boot identity, and an acquisition timestamp before this boot. Linux checks kernel `btime` and rejects a different PID namespace on the same boot. A reused PID remains protected. Runtime identity is the lowercase short hostname plus this boot (`sysctl kern.boottime` on darwin, boot id plus PID namespace on linux, `GetTickCount64`-derived boot time rounded to the minute on windows); unproven foreign or legacy locks require explicit operator recovery. Metadata creation, reclaim, heartbeat, and release use a persistent OS-locked guard file. Creation and reclaim write complete metadata to a sibling file and close it before publication under the guard. Creation requires an absent final path. Stale reclaim rechecks the current owner and atomically replaces its existing record through `fileio.Replace`, retaining the old metadata if preparation or replacement fails; a disappeared owner uses absent-path creation. Concurrent cooperative readers see a complete old or new record throughout takeover. A crash before publication leaves only an inert temporary file. Lock and priority-request ownership tokens are random and independent of the `Started` timestamp, so same-process successors remain distinct even when clock readings match. Heartbeats compare the full ownership token; `Role` names the holder; yielding holders poll for priority on the caller's interval, one second for the lane.
- **Metadata reads**: Lock metadata uses `fileio.ReadFile` and held readers use `fileio.OpenRead`, sharing the existing cooperative reader and extended-path handling. Windows readers share deletion as well as reads and writes, so polling does not block owner cleanup. Stale takeover uses the cooperative POSIX replacement primitive; ordinary readers that deny deletion sharing still cause a truthful publication failure.
- **Priority ownership**: one token-named record per waiter in the `PriorityPath` directory. Each request publishes complete metadata atomically to its unique path without waiting for other owners. Cleanup joins its heartbeat, is idempotent, and removes only its own record after checking its full owner token. A persistent sibling OS guard serializes heartbeat refresh with stale pruning. A busy scanner reads complete published records without pruning; guard contention alone does not imply priority. Checks prune expired token records and dead PIDs in the matching runtime, plus recognized abandoned publication files after the grace period. Unrelated files are preserved, and a symlink or non-directory at the exact priority path is rejected. The empty directory and one guard remain. Every active waiter retains priority when another exits. See [[indexing]] for the version-transition requirement.
- **Boundary**: this package coordinates writers; it does not decide indexing freshness, card convergence, or rebuild scope, and it does not own wait policy — `pkg/app/indexing.TryAcquireIndexLock` owns the interactive wait and `pkg/app/bootstrap/lane` owns the runtime's.

Waiters renew based on their own `PriorityRequest.Active`, which verifies fresh regular metadata and the captured full owner token independently of peers. They close the inactive handle before publishing a new one. Background holders alone use aggregate `CheckPriority`. `Close` stops and joins the heartbeat; a ready timer tick cannot start another guarded refresh after the stop signal. Interactive indexing retries nonfatal request errors on its normal poll.
