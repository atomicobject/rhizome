# Desktop starter recovery

The runtime page carries persistent starter readiness and recovery across navigation. Its verified page report can request `openRepositorySettings`; the native host supplies the current pane repository and worktree, then opens the existing repository Settings tab. It accepts no page-supplied repository identity.

`RHIZOME_DESKTOP_STARTUP_TRACE` enables elapsed startup milestones on stderr, from main entry through installation preparation and both WebViews. The Windows portability fixture enables it and records hidden owned windows as well as visible windows, so a delayed first window can be localized without changing the timeout.

# Repository upgrades

Pin offers and repository Settings open `UpgradeSheet` before changing a worktree. `upgrade-plan` previews the bundled release's generated files. Upgrade advances the pin, clears the worktree executable override, applies `settings-apply` with empty choices, then reopens the selected worktree or restarts its running runtime. A retry resumes the failed step and never advances an already saved pin again, including a pin saved before `pin-advance` reported an error. File changes remain uncommitted; the result's `commit` paths supply the copyable Git command, written for PowerShell on Windows.

A ready, trusted, configured worktree without an advance offer gets a background `settings-report`. Pending writes produce the toolbar's files update offer, which uses the same sheet without installation or restart. Checks are serialized per worktree, silent on failure, and repeated after a successful apply.

# macOS app-owned updates

[`updater.rs`](src-tauri/src/updater.rs) keeps the download, prepare-update, import/sign-in cancellation, window recovery, and restart-marker lifecycle. Its macOS installation boundary rechecks `Update.verify`, then calls [`updater/macos.rs`](src-tauri/src/updater/macos.rs). Other platforms continue to call `Update.install` directly.

The adapter validates the entire archive before considering a fallback. It extracts outside the installed bundle and requires the announced version, configured identifier, and an Apple-anchored requirement for the running app's signing team. The fast path requires a user-owned, writable real bundle and `Contents`, a clean root, a valid current signature, and same-volume staging. It atomically exchanges only `Contents`, verifies the result, and rolls back on failure. Failed rollback moves the old `Contents` to a unique private directory under `~/Library/Application Support/<identifier>/recovery/` and reports its exact path. If that move fails, it keeps the staging copy and warns that macOS may delete temporary storage. A successful swap never falls through to the privileged installer. EPERM is logged separately from EACCES. Bundle-root xattrs survive; touch and cleanup cannot turn a committed installation into a reported failure.

The full-bundle Tauri fallback handles root-owned or otherwise ineligible installs after replacement validation. The old installer stages a user-owned replacement; the intended one-authorization transition needs no chown migration. macOS App Management can still deny the Contents swap and send installation through the administrator-authorized fallback. Signed standard-account A to B to C acceptance did not establish password-free updates. Drew accepted this delivery limitation for PR #145 and deferred further manual testing; see [the effort deviation](../docs/efforts/2026-11-13-14-55-macos-app-owned-updates.md#deviations) and [the distribution contract](../docs/specs/technical/desktop-distribution-and-updates.md#updater).

# Menu bar host and quitting (macOS)

SPEC-0104 US7–US8 and EFF-2026-11-22-11-38 own this behavior; the README's Operation section describes it for people.

- [`sessions.rs`](src-tauri/src/sessions.rs) holds the window session. `Sessions::stash` (Quit Rhizome) persists geometry, moves the open windows to a stashed list, and leaves `quitting` false, so the windows' own close events change nothing. `save` writes stashed windows ahead of open ones and marks the file `pending` when only stashed ones exist; `Sessions::quit` (Quit Completely, logout, update) therefore never drops a stashed layout. `Sessions::begin` decides what a launch opens through `Launch`: `Open` restores every window or the last one closed, `Login` opens none and stashes the session, and `Restarted` (updater) reopens windows only when the session was not pending.
- [`windows.rs`](src-tauri/src/windows.rs) `resume` and `resume_from_event` restore every stashed window; `reopen`, the File menu's New Window, menu commands with no window, `terminal.rs`'s `open_in_new_window` and `target_window`, and the menu bar's Open Rhizome all call one of them first. `create` switches the app back to a regular Dock app; `quit::to_menu_bar` switches it to an accessory app when no window remains (the last window closing, a login launch, or a restart that opened none).
- [`host.rs`](src-tauri/src/host.rs) is the window-independent host loop, started only on macOS. It lists repositories with `rzm tasks hosts --json` (global executable or bundled sidecar, run in the app data directory), opens each checkout's runtime through `pipeline::hold`, and holds `GET /api/tasks/host` with [`host/api.rs`](src-tauri/src/host/api.rs). A held host's status drives [`tray.rs`](src-tauri/src/tray.rs) (a plain `Model`, drawn by `tray/native.rs` only when it changes so an open menu is not replaced), notifications through `host/notices.rs`, and the inbox badge for that repository (`inbox.rs` skips page reports for hosted repositories).
- [`quit.rs`](src-tauri/src/quit.rs) owns ⌘Q, Quit Completely, the one-time notice, the app menu's second quit item, and the Menu bar settings. Quit Completely asks first only when the streamed status shows a run, then drains every held runtime (`POST /api/tasks/host/drain`). Each drain answer, not the streamed status, decides what is busy: a run or a started pass (`dispatching`) the status had not shown asks wait or stop (no Cancel, since draining lasts until the runtime restarts). Stopping sends `POST /api/tasks/stop` to every runtime whose drain reported work or did not answer and waits for each answer (10 s each); waiting polls each busy runtime's drain until it reports none. Only then does it stop headless held runtimes through the companion's `stop` and call `app.exit(0)`.
- Terminate path: `main.rs` prevents only `ExitRequested { code: None }` (the last window closed) on macOS; `keeps_running` is the tested rule. Every `RunEvent::Exit` (logout, restart, shutdown, Dock Quit, updater restart, and the end of any quit) saves the session and calls `host::terminate` ([`host/release.rs`](src-tauri/src/host/release.rs), which also holds Quit Completely's drain, stop, and release steps); it drains and stops runs within 3 seconds on the async runtime, then sends each headless runtime's stop to a companion it does not wait for (`bridge::send`), so logout is never held up.
- [`login.rs`](src-tauri/src/login.rs) writes the LaunchAgent for Launch at login. A LaunchAgent can pass `--login`, which `SMAppService.mainApp` cannot, and it works the same for signed and development builds; the single-instance callback ignores a login launch while the app runs.
