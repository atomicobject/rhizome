## Anti-Patterns Verdict

**LLM assessment:** Fail, with strong foundations. The restrained AO palette, dense workbench shell, and typography avoid generic purple SaaS. The glossy gradient orb, decorative grid backdrop, hero-metric composition, and repeated bordered cards are explicit AI-design tells and contradict `DESIGN.md`.

**Deterministic scan:** 340 findings: `design-system-color` 152, `design-system-font-size` 105, `design-system-radius` 67, and `side-tab` 16. Most cluster in `web/src/ontology.css`; smaller clusters occur in `base.css`, `explorer.css`, and `agent.css`. The scan confirms substantial token drift, but it overstates severity: test-only color literals are non-rendered; several `side-tab` hits are blockquotes or CSS carets; `999px` hits include legitimate pills/legend lines; and two radius hits are parser artifacts around fallback expressions.

## Overall Impression

Rhizome already feels like a serious technical workbench on desktop. Its biggest weakness is not cosmetic: it visually treats unavailable evidence as valid empty evidence. That breaks the product's core promise of inspectable confidence. On narrow screens, the shell then compounds the trust problem by hiding routes outside the viewport.

## What's Working

- Dense rails, stacked surfaces, graph workspaces, and visible structure fit expert software work.
- AO-inspired red, warm ink, teal, Merriweather, Barlow, and JetBrains Mono provide a distinctive foundation.
- Labeled desktop navigation, active states, search controls, and the responsive Agent drawer establish solid semantic groundwork.

## Priority Issues

### P1: Disconnected state appears as valid empty data

**Why it matters:** Notes reports zero notes/types/issues when data was never loaded; GraphQL renders blank. Users cannot distinguish a clean vault from a broken connection, directly violating “make confidence inspectable.”

**Fix:** Introduce a shared connection/readiness state. Block or qualify metrics until data loads, use an announced error region, preserve last-known data where appropriate, and provide retry plus concise setup guidance.

**Suggested command:** `$impeccable harden web`

### P1: Primary navigation breaks at narrow widths

**Why it matters:** At 390px, the document is about 543px wide, creating roughly 153px horizontal overflow. Agent and GraphQL move offscreen; even the active route can disappear.

**Fix:** Add a deliberate shell breakpoint: retain the 2–3 primary workspaces, move secondary tools into a labeled workspace menu, preserve active-route visibility, and keep tap targets at least 44px.

**Suggested command:** `$impeccable adapt web`

### P2: Visual identity contradicts its own anti-slop direction

**Why it matters:** The glossy orb, decorative grid, hero metrics, and repeated cards weaken the structured-workbench identity documented in `DESIGN.md`.

**Fix:** Use the committed structured R mark, remove the decorative page grid, flatten the Notes composition into workbench bands/rows, and reserve cards for genuinely bounded items.

**Suggested command:** `$impeccable polish web`

### P2: Notes home lacks task hierarchy and a useful first-run state

**Why it matters:** Sidebar counts, repeated headings, hero metrics, Recently changed, and Most linked compete without presenting a productive next action. The empty state teaches nothing.

**Fix:** Lead with current work, validation health, recent notes, and provenance. Distinguish empty, loading, disconnected, and no-results states. Reduce duplicate “All notes” labels and metric repetition.

**Suggested command:** `$impeccable distill web`

### P2: Token drift and faint metadata erode consistency and accessibility

**Why it matters:** The detector found 324 color/font/radius deviations. Some are false positives, but the breadth indicates local values are bypassing the design system. Repeated 11px faint text and opacity reductions are fragile for low-vision users.

**Fix:** Audit rendered values, promote legitimate variants into semantic tokens, replace one-off literals, raise low-contrast metadata, and label unfamiliar symbolic controls.

**Suggested command:** `$impeccable audit web`

## Persona Red Flags

**Alex, power user:** No visible global command palette or route-shortcut discovery. Notes spends prime space repeating summary metrics instead of emphasizing search, recent work, validation, or batch actions.

**Sam, accessibility-dependent:** Narrow navigation overflows; symbolic controls rely on interpretation; faint 11px metadata is fragile at zoom. Backend errors are plain text rather than announced status/alert regions.

**Priya, technical lead inheriting a repository:** A disconnected Notes view falsely suggests an empty vault, while GraphQL offers no evidence at all. She cannot tell whether the repo is healthy, empty, stale, or simply unavailable.

## Minor Observations

- “All notes” appears in the rail, pane heading, and content heading simultaneously.
- The folder emoji clashes with the restrained technical icon language.
- “More” does not explain which graph controls it reveals.
- “auto via local tools” is too ambiguous to establish runtime confidence.
- Explorer adapts to mobile more successfully than the shell and Notes.

## Questions to Consider

- If trust and provenance are the thesis, why can failed loading ever render like a genuinely empty vault?
- Which three destinations deserve persistent navigation, and which belong in a workspace switcher?
- Could Notes begin with current work, validation health, and provenance instead of dashboard metrics?
- Is Agent a separate destination, or the command layer woven through Notes, Ontology, and Explorer?
