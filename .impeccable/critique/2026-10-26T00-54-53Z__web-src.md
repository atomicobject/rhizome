## Design Specificity Verdict
**LLM assessment.** Now specific. The themed chrome around an inset white panel is a recognisable composition, but the identity comes from Rhizome's own parts: typed sidebar groups with counts, mono evidence columns, status shapes, Merriweather note titles over Inter prose, teal note links, and a Record pane that receives the columns the table could not fit. The baseline's "every view stacks the same five bands" is gone: a view is a title row and a tab row. What still reads generic is the Briefing page, a two-column list of lists with no visual idea beyond hairlines.

**Deterministic scan.** CLI `detect` over `web/src`: 9 findings. Two `side-tab` hits at `configured-view.css:828` and `:1533` are CSS-triangle carets (false positives, as in the baseline; the baseline's `ontology.css` caret is gone). Seven `overused-font` hits on Inter in `fonts.css` are the user's chosen face, so they are accepted, not defects.

**Visual overlays.** `detect.js` was injected into three headless pages (Effort notes table, All notes, the spec note) at 1440 light. They were headless, so no `[Human]` tab is left open. The console reported: `low-contrast` on the global search placeholder ("Search this project…" `#c9c5bf` on `#55534f`, 4.47:1, needs 4.5:1) on every page; `skipped-heading` on the table (h2 "Effort notes" followed by h4 "Quick filters"); `flat-type-hierarchy` on the note (body 15, H3 16, H2 18, largest step 1.13:1, weight carries the difference); a content `straggler`; and `overused-font`. The contrast and heading findings are real and were missed by the design review.

## Priority Issues
- **[P1] Toggling Edit moves the note.**
  - **Why it matters:** SPEC-0126 US11 promises that toggling Edit does not move the text. In edit mode the properties become a boxed form (identifier help, segmented status, date input, relation selects, a bordered summary textarea), which pushes the body down about 137px. Each link gains an external-link icon that rewraps lines, and paragraph gaps grow from 11px to a full blank line. The section editors themselves are calm (no box at rest, tint on hover), but the page around them jumps. The reader loses their place every time they switch.
  - **Fix:** keep the read-mode property rows in edit mode and make each value editable in place (borderless until hover or focus, like the section editor). Drop the link icon in the editor or reserve its width in read mode, and map paragraph spacing to read mode's 0.75em.
  - **Where:** `web/src/components/OntologyPropertyPanel.tsx`, `web/src/markdown-editor.css:130-170`, and `web/src/ontology.css:1540-1640`.
  - **Suggested command:** /impeccable polish.
- **[P1] Header chrome still takes 210px before the first row.**
  - **Why it matters:** this is the baseline's "38% of the viewport is header chrome", improved but not to the spec's target. Together with the two-line default, a 900px window shows 12 records.
  - **Fix:** move the presentation tabs into the title row or the document tab strip (saves 40px), and shrink the group header band from 44px to the 36px row height (saves 8px). Start types without a curated summary in one-line density.
  - **Where:** `configured-view.css:21-27`, `:97-104`, and `:794-805`.
  - **Suggested command:** /impeccable distill.
- **[P1] One status value, three glyphs.**
  - **Why it matters:** "Active" is a half-filled blue ring in the table and the Record pane, a filled blue dot in Briefing's "In motion", and a filled teal dot in a pill in the note header. The hover card shows a lowercase "active" pill. This is the baseline's consistency finding, still open, and it breaks DESIGN.md's Status Marks rule (the shape is the meaning).
  - **Fix:** render the kit's `statusMark` everywhere a lifecycle value appears, and use the enum label.
  - **Where:** `configured-view.css:978-1030`, the Briefing dot in `web/bundled-views/group/`, and the identity chip in `web/src/ontology.css`.
  - **Suggested command:** /impeccable polish.
- **[P2] The ⌘P finder ranks typo queries poorly.**
  - **Why it matters:** "shcema" puts two Reference docs that match by scattered subsequence ("S·e·a·r·c·h - Exe·c·ution s·em·antics") above `schema.go`. Notes always rank before code files, so a weak note match beats a strong file match, and the highlights scatter across the path. SPEC-0126 US8 asks for exact and prefix title matches first.
  - **Fix:** apply a score floor relative to the best match before the notes-first ordering, and prefer contiguous or transposed runs over scattered subsequences when highlighting.
  - **Where:** the finder scorer in `pkg/app/web`.
  - **Suggested command:** /impeccable harden.
- **[P2] Overflowed columns are out of reach below 1200px.**
  - **Why it matters:** at 1100, selecting a row does not open the Record pane (the pane starts collapsed by design), yet the footer says "ID, Governing specs show in the Record pane". The pane toggle reports `aria-expanded="true"` while no pane is rendered. Sighted users must know `]`, and screen-reader users are told the pane is open.
  - **Fix:** make the footer note a button that opens the pane, and derive `aria-expanded` from the rendered state.
  - **Where:** `web/src/components/NotesShell.tsx` and `web/src/components/shellPanes.ts`.
  - **Suggested command:** /impeccable harden.
- **[P2] Global search placeholder misses AA in Graphite light.**
  - **Why it matters:** the placeholder is `--chrome-muted` on `--chrome-raised`, 4.47:1. `web/src/lib/themes.test.ts` checks muted text on `--chrome-bg` but not on the raised field, so other themes may fail the same way.
  - **Fix:** add the raised pair to the contrast test, and lighten `--chrome-muted` or the field.
  - **Where:** `web/src/base.css:211-226` and `web/src/tokens.css:225-231`.
  - **Suggested command:** /impeccable audit.
