# Process specs

## Summary

These specs define how work is shaped, approved, executed, verified, closed, backported, and compounded.

## Reading order

1. `agent-workflow.md` — orientation page for agents starting work
2. `development-loop.md` — the normative simple-task and complex-effort workflow
3. `effort-lifecycle.md` — effort note shape and closure rules
4. `story-lifecycle.md` — story authoring, readiness, typed acceptance criteria, satisfaction, and carry-forward rules
5. `ontology-design-principles.md` — how much to structure, when to use `@link`, and when to rely on prose plus `@neighbors`
6. `id-allocation.md` — top-level id allocation, required story ids, and on-demand acceptance-criterion locators
7. `agent-skills.md` — top-level and phase-skill routing
8. `debugging-workflow.md` — root-cause-first bug investigation and routing
9. `review-handling.md` — how to verify and route review feedback
10. `audits.md` — audit types run by `alignment-audit`
11. `compounding-work.md` — how repeated friction becomes future capacity
12. `quality-gates.md` — local and CI verification expectations before handoff
13. `testing-policy.md` — TDD and regression-test expectations for behavior changes
14. `transcript-ingestion.md` — how transcripts and raw source artifacts become durable ontology-backed docs
15. `specs-organization.md` — where new specs go
