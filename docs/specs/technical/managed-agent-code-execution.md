# Managed agent code execution

## Summary

An agent submits JavaScript, calls Rhizome operations through an available `rzm` object, and returns the evidence it needs. The execution tool owns client construction, process startup, and cleanup. This is the execution interface Drew approved after reviewing the nine-minute effort-delivery pilot in [[../../reference/analysis/persistent-code-mode-evaluation-results|the persistent code-mode evaluation]].

## Goals

- Make composed Rhizome operations directly executable without agent-managed setup.
- Preserve the existing operation contracts, evidence qualifications, and write authority.
- Finish each execution with bounded output and cleaned-up processes.

## Requirements

- `rzm agent code execute` accepts JavaScript through `--code` or standard input. The script supports top-level `await` and `return`, with the catalog's camel-cased operation methods on `rzm`. Agents need no imports, generated files, connection manifest, interactive driver, or lifecycle calls.
- Reuse [[persistent-agent-code-mode|SPEC-0092]]'s client, catalog, shared handlers, and operation outcomes. Every supported operation is callable without a generation or selection step; `code surface` and selective `code describe` remain the discovery contract.
- One execution owns its client and server. It closes and reaps them on success, script failure, cancellation, and timeout. Independent executions do not retain JavaScript variables or require a process to survive unrelated editing or testing steps. A supplied agent session ID continues to carry the existing conversation context and deduplication semantics.
- Return one JSON envelope with execution status and the script's selected JSON value. Operation outcomes keep their existing `ok`, `exitCode`, payload, diagnostics, and evidence qualifications. Execution success does not assert that every returned operation succeeded or that the evidence is complete. Logs and errors are bounded and cannot silently corrupt the normal result envelope.
- Bound code size, output, and whole-execution duration. Syntax errors, thrown errors, non-serializable results, missing Node, excessive output, and runaway synchronous or asynchronous scripts fail explicitly. A timeout or interruption does not roll back completed mutations; retain transport uncertainty and known outcome details when available. No automatic retries.
- Rhizome calls default to read authority. Supported writes require `--read-write` plus the existing operation-specific controls and user authorization. JavaScript runs with the caller's host permissions; this execution interface is not a sandbox or a restriction on JavaScript's filesystem access.
- Installed base, Agentic Engineering, and Complex Domain guidance uses direct execution for composition. SDK generation remains available for integrations that own a JavaScript runtime. No ordinary workflow asks an agent to maintain a process across the entire task.

## Verification

Use real Node execution to verify projected multi-call results, shared process use within an execution, inherited session/write controls, failure reporting, bounds, cancellation, and cleanup. Exercise the compiled CLI on a disposable vault and run the installed example from fresh base/AE/Domain installations. Repeated init must preserve generated bytes. Complete repository gates and fresh independent review.

## Non-Goals

A persistent agent REPL, new daemon, automatic indexing, new operation schemas, a JavaScript security sandbox, search-ranking changes, or a new model evaluation campaign. The six consumed pilot runs remain unchanged. Main merge and release publication remain separate.
