# Notemeta subsystem guidance

## Scope

`pkg/notemeta` is the canonical raw-note fact indexer: an explicit `Indexer` turns selected provider-projected authored source bytes into durable SQLite rows (note metadata, property values, tags, graph edges, and fragment targets) through the narrow `Store` port, and defines `NoteSourceSnapshot` as the raw-note source contract for downstream domains. It owns note-file freshness, source format identity, and raw facts only — ontology interprets typed meaning, anchors extracts code-anchor declarations, search consumes derived evidence.

- **Entry points**: `Indexer.EnsureIndexed` (full rebuild when state hash is stale), `Indexer.SyncPaths` (derive and immediately apply an incremental delta), `Indexer.BuildPathDelta` (derive the same complete source delta without writing), `Indexer.DiscoverDirtyPaths` (one note-only scan against persisted rows), `Indexer.LoadNoteSourceSnapshots` (store-assisted canonical inputs for downstream projectors), `Indexer.BuildNoteSourceSnapshots` (explicit-reader source factory), `BuildNoteSourceFacts` (live cache-bypassing source inventory for consumers that own structured-link discovery), `Indexer.LoadPersistedGraphSnapshot` (DB-backed source-neutral graph DTO), `NewContentOnlyNoteSourceSnapshot`, `LoadAliasMap`, `Indexer.MetadataStateCurrent`/`MetadataStateReady` (`pkg/notemeta/indexer_operations.go`, `dirty_paths.go`, `graph_snapshot.go`, `source_snapshot.go`). Application composition constructs and validates the required `Indexer`; no compatibility runtime fallback exists.
- **Entry points**: `EnsureIndexed` (full rebuild when state hash is stale), `SyncPaths` (derive and immediately apply an incremental delta), `BuildPathDelta` (derive the same complete source delta without writing), `DiscoverDirtyPaths` (one note-only scan against persisted rows), `LoadNoteSourceSnapshots` (store-assisted canonical inputs for downstream projectors), `BuildNoteSourceSnapshots` (explicit-reader source factory), `BuildNoteSourceFacts` (live cache-bypassing source inventory for consumers that own structured-link discovery), `LoadPersistedGraphSnapshot` (self-validating DB-backed source-neutral graph DTO), `LoadReadyPersistedGraphSnapshot` (bounded projection for callers that already validated the indexed reader), `NewContentOnlyNoteSourceSnapshot`, `LoadAliasMap`, `MetadataStateCurrent`/`MetadataStateReady` (`pkg/notemeta/index.go`, `dirty_paths.go`, `graph_snapshot.go`, `source_snapshot.go`).
- **Consumers**: indexing pipeline (`pkg/app/indexing/unified.go`, `commands.go`), ontology sync (`pkg/ontology/sync.go`, `index.go` — gates typed indexing on `EnsureIndexed`), MCP/watcher schedulers (`pkg/app/bootstrap/schedulers.go`), graph read paths (`pkg/app/cli/graph_store.go`, `graph_doc.go`), anchors ingestion via `notemeta.NewContentOnlyNoteSourceSnapshot` → `Service.IngestNoteSource` (`pkg/anchors/service_indexing.go`, `pkg/app/codeintel/ingest.go`).
- **Store implementation**: `*semdb.Store` in `pkg/anchors/sqlite/note_metadata.go` (tables `notes`, `note_projection_state`, `note_projection_diagnostics`, `note_property_values`, `note_tags`, `note_search_terms`, `note_search_regions`, `note_fragment_targets`, `note_metadata_state`, `graph_doc_edges`).

## Design constraints

- **Nested metadata keys remain authored data.** Root field names must be nonempty, but objects inside a metadata value preserve all string keys, including the empty string. Markdown and HTML use the same canonical value domain and legacy frontmatter conversion. Indexer version 11 invalidates prior metadata state for this acceptance change.

- **Snapshot vs delta semantics.** `EnsureIndexed` captures each selected note's contents once and computes an order-independent XOR-of-SHA256 notes hash (`capturedNotesHash`/`noteStateDigest`: path+contentHash — content identity only; filesystem mtime and size are freshness evidence persisted on the row and never part of the aggregate hash) and compares against `note_metadata_state.notes_hash` (which also folds in `noteMetadataIndexerVersion` + vault link-support via `metadataStateHash`). Match + materialized paths ⇒ no-op; mismatch ⇒ full `ReplaceNoteMetadataSnapshot`. The same captured contents supply provider projection; no-op checks do not stat or project sources. Snapshot publication derives its raw hash from the projected sources, so rows and the generation cannot describe different captures. Indexer version 12 invalidates earlier generations that could pair first-read hashes with second-read rows. `BuildPathDelta` bootstraps when state is unready, lacks a raw hash, or has a stale derivation/config fingerprint; bootstrap enumerates materialized rows independently of readiness so stale rows become tombstones. The incremental hash is maintained by XOR-removing old row digests and XOR-adding new ones (`incrementalNotesHash`) — it must stay equal to what a full recompute would produce or freshness checks silently rot.
- **Source/projection provenance is provider-populated.** Intel v65 retains one-to-one source status in `note_projection_state` and publishes ordered `note_projection_diagnostics` in the same source transaction. Diagnostics carry category, message, optional original-byte range, blocking state, and affected operation. The fatal summary columns are exact derived compatibility data, never the truth source. `current` publishes its nonblocking diagnostics and derived collections; `fatal` retains source identity and blocking diagnostics while clearing search, properties, tags, links, and fragments.
- **Content identity decides re-materialization; mtime never does.** Both delta builders partition their freshly projected entries against the durable rows with `partitionProjectedEntries`/`sameProjectionIdentity` (`projection_partition.go`): a missing row or any difference in title, content hash, format, or projection provenance is a rewrite; a row differing only in mtime/size becomes a `NoteMetadataDelta.SourceTouches` entry applied as an in-place `UPDATE notes SET mtime, size`; an exact match yields nothing. A delta whose changed and deleted sets are both empty carries the stored `State` verbatim, so `LoadedAt`, `RawNotesHash` and `NotesHash` — and therefore the published ontology generation — are retained. This is not an mtime shortcut: every selected note is still read, projected and re-hashed first, per B09. A touch for a path the same delta also rewrites or deletes is a store-level contract violation.
- **Derivation and publication are separate seams.** `BuildPathDelta` is pure with respect to the store: it derives metadata, properties, tags, links, and fragment targets together but does not write. `SyncPaths` remains the convenience wrapper that applies the returned delta. Coordinators needing ordering guarantees submit the delta through the shared writer lane and wait on its acknowledgement before deriving ontology.
- **Projection loading is bounded and deterministic.** Source stats and provider projection run through a `GOMAXPROCS`-bounded worker pool; cache snapshots use the same projection bound. Full Ensure freshness capture preserves the sequential preflight read order and defers stats until rebuild. Output is sorted by canonical authored path after out-of-order completion. `Projector.Project` is therefore a concurrent contract and providers must synchronize mutable implementation state.
- **Dirty discovery stays note-only and source-only.** `Indexer.DiscoverDirtyPaths` loads one authored source per selected note through the selected runtime's descriptors and compares observed path/content-hash/mtime/size against persisted note rows plus each row's projection status. It never runs the provider projector, so projection-time errors (`ErrProjectorUnavailable`, `ErrInvalidProjection`) surface from `BuildPathDelta` for changed paths rather than aborting a scan. `Indexer.MetadataStateCurrent` likewise performs exactly one inventory and one read per selected note, reusing the paths computed by its own freshness check. Neither may short-circuit the content read on timestamp or size equality. A changed raw hash does not force every note dirty; only an unready or derivation/config-stale metadata state expands to all current paths. An unchanged `stale` projection remains dirty and is retried; an unchanged `fatal` projection retains its durable source identity until source or provider-version change.
- **Fragment-target and search-region rows are provider facts.** `note_fragment_targets` stores heading, block, element ID, and legacy name targets. `note_search_regions` stores ordered visible or supplemental evidence with origin, media type, and optional original-byte range. Changed paths replace both collections atomically; deleted or renamed paths tombstone them. Markdown still uses its canonical heading/block parser.
- **URI resolution is source-neutral.** Provider-parsed URI facts expose decoded scheme, authority, path, query, and fragment components plus exact ranges and optional document base. Notemeta resolves internal paths without calling the Markdown resolver. Query affects navigation only, external bases and authorities produce no internal edge, and explicit authored extensions resolve against the common note set without preferring Markdown.
- **Bump `noteMetadataIndexerVersion`** (`pkg/notemeta/index.go`) whenever row derivation changes (new columns, changed tag/property/link/target extraction). That is the only mechanism forcing rebuilds on already-indexed vaults.
- **Path keys are vault-root-relative.** `NoteSourceSnapshot.Path` goes through `paths.CleanNotePath`, then `VaultPaths.RelNotePathStrict`; legacy content-only helpers retain compatibility normalization internally. Store rows must never contain absolute or vault-escaping paths (see `pkg/paths`, AGENTS.md "Path normalization").
- **Link resolution is Obsidian-compatible and alias-aware.** Full snapshot builds `BuildNotePathCacheWithAliases` from provider-projected paths and aliases; duplicate alias claimants remain a sorted multi-candidate set and never resolve first-wins. Incremental deltas overlay DB aliases (`CurrentNoteAliases`) with freshest projected aliases of changed notes and strip deleted paths (`overlayProjectionAliasesForDelta`). Topology comparison and cache population share one persisted alias snapshot; the overlaid aliases and candidate/alias-owner union are bulk-built by `buildProjectionAliasCache` to avoid quadratic per-alias updates. Their candidate cache asks the store only for decoded `UnresolvedAuthoredLinkFact.Path` targets, source-relativized when required, then overlays changed sources; opaque `ResolverInput` remains reserved for final shared-cache resolution. Added/deleted note paths and changed alias sets trigger complete note-link rederivation because unresolved inbound links are not persisted and either change can alter resolution for unchanged sources. Markdown angle destinations with titles remain unresolved when `NotePathCache` cannot interpret their preserved legacy resolver input; extending that shared resolver is deferred work, not a notemeta fallback. Display-alias edges flow into `graph_doc_edges` alongside their base wikilink edge. The coarse `wikilink` or `mdlink` row also carries `link_text`: the label (empty when the link has none) and the source line around each link from that source to that target, at most 8 entries of up to 300 bytes each (`semdb.AppendLinkText`). Detail `note_link:*` rows carry none. Scoped publication restores incident edges with their `link_text` from `CapturePublishedBaseline`, so editing a linked-to note keeps the labels its unchanged linking notes supply. Indexer version 13 forces this rederivation.
- **Store contract.** `pkg/notemeta/store_contract_test.go` is a compile-time conformance check: `var _ Store = (*semdb.Store)(nil)`. Behavioral invariants live in `pkg/anchors/sqlite/note_metadata_test.go`: snapshot replace clears all metadata tables + `note_projection_state` + note-link-kind `graph_doc_edges` and prunes stale indexed notes; delta apply deletes-then-upserts only touched paths and their projection state inside one write tx, applies `SourceTouches` as mtime/size-only note updates in that same transaction (`note_metadata_touch.go`), inherits `LoadedAt`/`Ready` from current state when unset, and survives large batches (`sqliteValuesBatchMaxParams = 900` chunking). A `fatal` projection keeps the current source row/provenance while the same transition clears stale derived rows.
- **Inventory readiness and requested-path availability are distinct.** `CurrentNoteMetadataRows`, its path-scoped variant, and the derived metadata/graph query helpers honor global `note_metadata_state.Ready` and can expose migration-stale legacy rows. `Indexer.UsableNoteMetadataRowsByPaths` is the narrow navigation exception: it uses the internal durable-row seam, then checks canonical path, selected format, projection status, provider and projection versions, and source hash against the active runtime. External Store implementations without that seam retain globally gated behavior. `Indexer.UsableNoteFactsByPaths` is the exact-hydration variant: it requires an atomic durable metadata/property/tag bundle, applies the same provider-current checks to metadata, and removes properties and tags for every rejected path. It fails when the store lacks that atomic capability because separate fallback reads could mix publication generations. `Indexer.UsableNoteMetadataCount` additionally accepts the application's current ownership predicate for warm-start probing. Broad consumers must keep inventory readiness.
- **Cross-domain ownership changes invalidate global metadata readiness.** The store-only ownership-transition seam deletes `note_metadata_state` in the same transaction that changes `notes`, preventing an unchanged legacy XOR digest from treating cleared derived rows as current. Provider-aware orchestration must rebuild note metadata before acknowledging the transition's durable reconciliation generation; it must not republish readiness merely to hide pending code, graph, link, ontology, or anchor work.
- **Full-index publication is explicit-path and format-aware.** `BuildPublishedMetadataDelta` accepts ownership-routed note paths plus sealed published Markdown sources; it never asks the reader to rediscover a vault. It produces normal metadata only for projectable Markdown. A descriptor-only HTML source remains a durable `stale` root identity and has no metadata children or derived evidence until a later HTML projector exists. When the complete raw/provider fingerprint, materialized path set, and projection freshness are already current, it returns no delta and preserves `LoadedAt`; this keeps the published ontology and note metadata on one generation. Do not add a state-only publication API: a changed state without the complete path set can falsely advance this barrier.
- **A failed candidate full run is non-destructive.** Ownership routing may retain a sealed source read for a code-to-Markdown handoff, but unreadable or build-failing Markdown candidate intake returns an error before the full run can acknowledge reconciliation. It must not retire the prior source or replace metadata with a guessed empty projection.
- **Batching/transactions.** All store writes go through `withWriteTx`; one snapshot or one delta = one transaction. Never issue per-row writes from the indexer side.
- **`NoteSourceSnapshot` is the only sanctioned raw-note ingestion DTO** for downstream indexing (anchors, semantic ops). Graph reads project either live entries or persisted rows into `obsidian.GraphSnapshot`, the single source-neutral input for graph algorithms and backlink derivation; do not add another graph model.
- **Ready graph loading trusts caller-selected persisted readiness.** `LoadReadyPersistedGraphSnapshot` checks persisted metadata readiness but deliberately does not prove live note freshness, call `MetadataStateCurrent`, enumerate notes, or reread files. Use it only when the caller intentionally accepts that indexed-only contract; ordinary callers use `LoadPersistedGraphSnapshot` and its self-contained freshness check.
- **Snapshot paths are already canonical.** Producers must supply vault-root-relative paths. Downstream consumers use `BuildNoteIndexWorkFromSource` / `IngestNoteSource`; raw path/content compatibility entrypoints no longer exist.
- **Consumer-owned link discovery uses authoritative filesystem facts.** `BuildNoteSourceFacts` exposes no reader port and constructs the direct filesystem reader internally, so cache-backed adapters cannot supply stale bytes or omit newly added notes. It enumerates and reads every live note exactly once and intentionally leaves `NoteSourceSnapshot.Links` empty. The consumer must perform its one sealed structured-link scan over the captured content; never treat empty `Links` from this entrypoint as evidence that the note has no links.

## Must-dos when changing this subsystem

- Any `Store` interface change: keep `store_contract_test.go` compiling against `*semdb.Store`, implement in `pkg/anchors/sqlite/note_metadata.go`, and add/extend behavioral tests in `note_metadata_test.go` for the new behavior.
- Any change to row derivation (tags, properties, titles, link kinds, hashing inputs): bump `noteMetadataIndexerVersion` and add a regression test in `pkg/notemeta/index_test.go`.
- Treat `FormatID` and `Projection` as one `NoteMetadataRow` transition; publish them only through the existing snapshot/delta store write, never through a side write to `note_projection_state`.
- Keep snapshot and delta paths symmetric: a `SyncPaths` over changed files must yield the same rows as a fresh `EnsureIndexed` for those files (hash, edges, properties, tags). Test both paths.
- Clean all paths through `pkg/paths` (`CleanNotePath`, `VaultPaths.RelNotePathStrict`); never `filepath.Abs/Rel` ad hoc.
- New edge kinds: register confidence defaults via `semdb.GraphDocEdgeConfidenceDefaults` and extend the snapshot-replace `DELETE ... graph_doc_edges` predicate so stale kinds are cleared.
- Run `go test ./pkg/notemeta/... ./pkg/anchors/sqlite/...` plus `go test -race -tags=integration ./...` before handoff; update `docs/specs/technical/note-node-indexing-architecture.md` and `pkg/notemeta/CONTEXT.md` if ownership boundaries move.

## Review checklist — problems to catch

- Absolute, `..`-escaping, or non-normalized paths entering rows or `NoteSourceSnapshot.Path` (OS-specific separators leak into SQLite keys).
- Snapshot staleness: derivation changed without `noteMetadataIndexerVersion` bump, or incremental hash drift vs full recompute (stale `Ready` state short-circuits reindex forever).
- Delta path skipping the `state.Ready`/`RawNotesHash` guards, or writing a delta when a full rebuild is required.
- Store changes bypassing the contract: new `Store` method without `*semdb.Store` implementation, or behavior added without a `note_metadata_test.go` case.
- Unbatched or out-of-transaction writes; exceeding SQLite param limits (respect the 900-param chunking helpers).
- Alias overlay regressions in delta rewrites (DB aliases must lose to fresher provider-projected aliases; deleted paths must be stripped).
- Schema drift: new columns/tables without snapshot-replace cleanup, stale-note pruning, or delta delete coverage.
- Legacy migration marked `current`, or a `fatal`/`stale` projection that drops the current source row instead of only its derived facts.
- Reintroducing legacy `obsidian.NormalizePath`/`AddMdSuffix` in new code paths.
- Adding a caller-supplied reader/cache seam to `BuildNoteSourceFacts`, rereading captured content, or consuming its intentionally empty `Links` as a resolved-link inventory.
- Calling `LoadReadyPersistedGraphSnapshot` from a path that has not explicitly selected the persisted-readiness contract, presenting readiness as proof of live note freshness, or adding a hidden live discovery/read to that bounded loader.
