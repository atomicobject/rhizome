# Agent surface guidance

## Scope

The agent surface is everything an AI agent consumes from Rhizome: the `rzm agent *` command family (`start`, `surface`, `file-context`, `vault-context`, `semantic-query`, `files`, `validate`, `ontology-*`, `code-*`, `query-recipe`, `next-id`, ...) plus the rendering pipeline behind it. Output is parsed by LLM agents, not humans — stability and token-density of the JSON/text contract are the product.

- `cmd/agent.go` + `cmd/agent_*.go`: thin Cobra fronts; build an args map, call `runAgentJSONTool` / `agentapi.CallJSON`, emit JSON via `writeAgentPayload`/`writeAgentError`, fail with `silentExitError{code: 1}`. `rzm agent start` is the one-call bootstrap for a session plus request-scoped repository guidance; `rzm agent surface` is the detailed command/flag contract and should be called only when an agent needs exact usage. `external-references` is the dedicated bounded pathless-target read and never widens ambient search or graph surfaces.
- `pkg/app/agentapi/`: in-process adapter over the MCP tool handlers (`CallJSON`, `SemanticQueryUnified`). Same JSON contract as MCP without a stdio server; argument normalization + text extraction only.
- `pkg/app/agentstart/`: shared start/session orchestration; Cobra and code mode supply runtime dependencies and consume the same response.
- `pkg/app/agent/`: LLM-facing retrieval planner types and parsing for local chat flows (`PlanToolCalls`, `ToolSpec`/`ToolCall`). Stops at planning; no vault state, runtime state, or packing.
- `pkg/app/contextpack/`: deterministic budget-aware packing of pre-rendered `Piece`s (`Pack`, `PackWithIntent`, `TrimToBudget`); optional LLM compression in `compress/`.
- `pkg/app/answer/`: turns ranked search results into answer packets (`Build`, `RenderText`): mustRead, supporting evidence, coverage, confidence, next queries.
- `pkg/app/presentation/`: implements `Packer` for `pkg/search.Service`; renders ranked results into budgeted text via contextpack.

## Design constraints

- **Jev evaluates explicit state.** `evaluate` reuses the native TypeSafe client through one shared handler and an empty one-shot runtime plan. Credentials resolve from environment/global configuration before the Atomic bundle. Catalog schemas preserve question and answer discriminators; discovery teaches independent questions and probability semantics. Evaluation sends only supplied state/questions, incurs provider usage, and preserves usage and request IDs. Session dedupe and response budgets do not alter evaluations.

- **Code discovery explains evidence recovery.** Selected describe carries shared invocation/outcome guidance once, with verified field semantics and operation-specific conditions. Examples preserve bounded context metadata and qualify projected file bodies. Session dedupe records delivery to JavaScript, so a follow-up may explicitly reread selected files with `dedupe: false` to recover content omitted from the model-visible projection. Keep execution, validation, and dedupe behavior unchanged by descriptive metadata. See [[code-mode-evidence-guidance|SPEC-0096]].

- **Startup teaches selective code discovery.** Every successful start includes the compact live code-operation catalog and describe/execute examples alongside session context. It reuses catalog metadata without schemas, vault readiness probes, or broader runtime initialization. Preserve existing startup fields. The base skill teaches when code mode helps, its reference teaches execution, and live describe owns exact operation contracts. See [[startup-code-discovery|SPEC-0095]].

- **Direct code execution owns lifetime.** `agent code execute` accepts a JavaScript function body, provides the catalog's camel-cased methods on `rzm`, and returns a selected JSON value. `pkg/app/agentcode` owns Node, the in-memory generated client, and server cleanup for that execution. Agents do not generate artifacts or maintain a process across unrelated task steps. Session IDs retain their existing cross-execution role. `--input` or `--input-file` passes one validated JSON value the script reads as `input` (`null` when absent), so saved skill scripts take arguments without environment variables. Bound scripts, results, diagnostics, and duration; preserve operation failures and mutation uncertainty. Track pending calls and still-unobserved failures without retaining discarded completed successes or observed outcomes. Drain accepted calls before cleanup, clear failure evidence on late observation, and report the first still-unobserved failure in invocation order. This is execution with caller permissions, not a JavaScript sandbox. See [[managed-agent-code-execution|SPEC-0094]].

- **Selective discovery shares the live contracts.** `agent surface --command` and code-mode `surface.command` select reflected command syntax, including inherited flags and nested commands. Unselected output remains complete. `code describe --operation` accepts a catalog name or its exact JavaScript method; `--schema input|output|both` selects complete schemas while retaining shared invocation/outcome guidance. A filtered view reports `schemaSelection` and retains the full selected-contract hash, so discovery projection cannot change generated-client negotiation. Ontology selectors and compact search are additive inputs on existing operations; generated declarations reflect the same catalog and shared response types. Local code-mode workflow branching belongs in application services below Cobra.

- **Persistent code mode is opt-in.** `agent code surface|describe|generate` are runtime-free fronts; only explicit generate writes task artifacts. The existing tool catalog owns contracts and CLI-leaf coverage for every task operation, including local-only families and the note-move exception. `pkg/app/agentcode` generates a selectively typed ESM client that owns one `agent code serve` child over bounded JSON-RPC stdio. Calls use bounded concurrency with resource-scoped locking, reuse shared application handlers, and retain payloads, warnings, refs and domain exit outcomes. `payload` is the only copy of a structured result: `stdout` stays present but empty rather than repeating it, so the envelope keeps its fields and a script that returns a raw outcome does not double the agent's read. Runtime resources are built and closed per request so live edits and index replacement do not reuse stale snapshots; configuration changes require reconnect. Supported writes require explicit read-write connection authority plus operation-specific controls. See [[persistent-agent-code-mode|SPEC-0092]]. Client calls use a bounded FIFO queue; queued cancellation releases capacity. Fatal framing errors discard queued work, and unacknowledged cancellation retains its worker slot until the server responds or the client closes. Post-execution faults retain execution uncertainty and any known outcome (oversized replies retain bounded completed status and explicit truncation evidence).

- **Output contract is an API.** Downstream agents parse field names, exit codes, and text shapes. Renaming/removing JSON fields, changing exit semantics, or restructuring packed text is a breaking change for every consuming agent and for guidance baked into RHIZOME.md templates. Add fields; do not silently mutate or drop them.
- **CLI/MCP parity by construction.** The CLI deliberately calls the shared MCP tool handlers in process (`runAgentJSONTool` -> `agentapi.CallJSON` -> `pkg/app/mcp` handlers) so CLI and MCP JSON shapes stay identical. Never fork a CLI-only response shape; `agentapi` type aliases (`FilesResponse`, `ContextTextResponse`, ...) are re-exports of `pkg/app/mcp` types.
- **One tool catalog.** `pkg/app/agentapi/catalog.go` owns shared and local-only tool identity, handler factories, agentapi/agent-CLI/capability surface membership, and mutation classification. Dispatch, CLI command mapping, and capability advertisement derive from it. `pkg/app/oneshotruntime` may exhaustively classify executable CLI leaves and compose explicit one-shot requirements, but it does not become a second tool catalog. Runtime-free declared fronts pass through that boundary without a runtime factory. Exact `code-symbol`, `code-references`, `code-rationale`, and `graph-path` plans select and await only CodeIndex and use the caller-managed existing index; `code-symbol-context` remains request-derived until source-snippet parity is frozen. Readiness remains handler-owned and absent from descriptors because capabilities initialize independently.
- **Code-mode note moves preserve publication decisions.** The local workflow retains the full mutation summary in `Payload` even when required follow-up work returns an error. The existing diagnostic carries a bounded whitelist of current decision, transaction ID, receipt path, and recovery-pending state, with recovered outcomes kept separate. Cancellation and deadlines preserve known completed outcomes; oversized replies preserve the current status, bound recovered identities, and report their count and truncation without duplicating the full move summary.

- **Code-mode local dispatch stays catalog-owned.** `agentapi.CallOutcome` is the transport-neutral domain result. `CodeLocalService` is the narrow adapter contract implemented by `cmd/`, and `CallCodeLocal` invokes the local method selected by each catalog descriptor. Shared descriptors may declare a local override when code mode must preserve CLI behavior; every code contract must have either that route or its shared handler. A descriptor's `CodeRuntimeRead` admits individual reads of a local override (typed queries, recipe runs, view reads without a caller `path`) to the vault runtime. `pkg/app/cli.CodeModeRuntimeReads` serves them there through the same workflows over the runtime's open index, behind its currency checks; `cmd` only adapts the live runtime. The host forwards them under shared access, takes a write-capable call as the end of runtime reads for that connection, and runs a read in-process whenever the runtime cannot prove its projection current ([[code-mode-skill-scripts|SPEC-0115]]).
- **`next-id` is an intentional local-only command.** It is cataloged for `rzm agent surface` but has no `ToolName` or `agentapi.CallJSON`/MCP dispatch. Its CLI and code-mode fronts share local application logic. Its Cobra surface may add strategy inputs such as repeatable `--path`, while runtime GraphQL carries the programmatic allocation contract; tests keep this boundary explicit rather than implying MCP parity.
- **Token budget discipline.** Contextpack invariants: priority-first greedy selection; first piece always included (trimmed if needed); stable tie-break priority -> score -> key. `DefaultBudgetChars` = 70k is the package fallback; config/explicit budgets override; the agent CLI applies `agentCLIBudgetFloor` = 150k (`cmd/agent.go`). Search packed output must honor the query-spec budget and must not inherit broad agent defaults (see `docs/code-anchors/contextpack.md`). Callers pass already-rendered pieces; contextpack never fetches, ranks, or interprets.
- **Structured warnings over false confidence.** `semantic_query` (`pkg/app/mcp/semantic_query_unified.go`) returns deduped `search.Warning`s (code/kind/source/message) when path/symbol resolution is ambiguous or unresolved, rather than downgrading to broad fuzzy matches. Preserve this: a wrong-but-plausible match poisons agent reasoning more than an explicit warning.
- **Semantic session history records final bodies.** Detailed and compact shared handlers inspect candidates without publishing delivery, reserve exact bodies after final budget selection, and commit only successfully encoded representations. Detailed packed-text prefixes cannot establish full delivery; one source with multiple surviving bodies owns a deterministic represented-set decision. Selected distinct siblings defer individual history filtering until the group decision so repeat groups settle after subset requests. Concurrent suppression updates all owned text and body fields together, using their normalized JSON representation. Missing/trimmed evidence remains eligible at a larger budget, while successfully delivered representations dedupe normally.
- **Compact semantic query is a selected-source representation.** With `compact=true`, `semantic_query` keeps its pagination and diagnostics envelope but clears detailed match/text/role fields. The compact source array owns each selected body once and exposes stable refs used by `mustRead` and `supporting` roles. Its continuation token binds compact mode along with scope, exact-symbol, and test-exclusion controls.
- **Indexed enrichment has a typed fail-soft boundary.** Requests carry normalized target kind plus item/byte budgets; results carry explicit `available|stale|incompatible|missing` freshness and remediation. Freshness does not expire merely with wall-clock age, and the reader contract cannot perform discovery or repair.
- **Answer packets select, never invent.** `pkg/app/answer` does role coverage selection over evidence passed in by upstream callers — no filesystem walks, embedding calls, or ontology projection there. Explanatory intents require docs + code; tests only when requested.
- **Session semantics.** `--session-id` (persistent flag on `rzm agent`) enables cross-invocation content dedupe (`dedupe` in `files`, session-aware context); `--session` is an equivalent CLI alias. Normal bootstrap is `rzm agent start --intent "<task>"`, with only a few ordered repeatable `--file` seeds when they materially help; agents reuse the returned `sessionId` for the whole conversation. Minimal bootstrap has no session store: minting and returning the ID is sufficient, persistence/dedupe is opportunistic, and a later store-backed command may establish the same session. Never reject or suppress a minimal response because its new session ID was not persisted. `--profile vault`, `--ontology`, `--graph-summary`, `--context-file`, and Markdown-note targets are explicit rich-context selectors; `--submodule-depth 1` only bounds requested directory guidance. Breaking dedupe or invalidating sessions mid-conversation silently re-sends large content and burns agent context.
- **Minimal start stays below global runtime layers.** Bare start, code profile, directory targets, and code-file targets select `VaultContextRequestScopeMinimalBootstrap` before rich vault-context construction. They resolve the repository and render bounded root/ancestor/target/requested-submodule guidance without reading notes or performing graph analysis, ontology projection, coderef discovery, broad repository-doc ranking, code-index readiness, SQLite/store opening, or session-store work. Do not reintroduce any of those merely to preserve historical start output; agents explicitly request richer context when they need it.
- **Rich behavior remains explicit and shared.** Vault profile, ontology, graph-summary, context-file, and Markdown-note selectors make `agent start` choose indexed bootstrap: minimal repository guidance plus bounded persisted selected-note metadata, code→note, rationale, resolved-edge, aggregate graph-summary, and ontology-summary evidence. It opens only an existing validated unified index in read-only/query-only mode; it never creates or migrates the database, runs session cleanup, or requests Search/cache, providers, discovery, projection, or repair. A root target is the bounded whole-vault subtree, while a requested graph summary without persisted score evidence degrades with structured `rzm index` remediation instead of rendering a false zero-document summary. Standalone `vault-context` still defaults rich when request scope is omitted, so this private start scope does not change other CLI/MCP callers. Unavailable indexed data preserves session creation and guidance while returning additive `indexedEnrichment` warnings and remediation. Default and serve runtimes retain the full capability set. `--timings` is additive diagnostics over the shared paths, not a separate retrieval implementation.
- **Session packing reserves then commits emitted context.** Batched reservations preserve exactly one winner across processes, but only emitted top-level and nested items become committed/seen. Budget-omitted owned reservations are released, and abandoned reservations have bounded TTL recovery; persistence failure remains opportunistic and must not suppress the response.
- **Context delivery survives final assembly.** File/vault contexts use exact retained piece text and renderer-owned byte ends, including retained original bytes before a truncation indicator, to publish only complete emitted containers after every enclosing trim. Bundled file context stays pending until vault output is final. Warning assembly preserves delivery within its retained original prefix. Successful compression does not prove raw source fingerprints; partial or compressed containers leave those sources eligible for a larger raw retry. Request cancellation reaches compression and releases pending reservations. Previously incorrect committed history cannot prove which bytes were delivered; start a fresh session to reread affected context.
- **Intent strings shape retrieval.** `--intent` flows into profile selection, compression prompts (`contextpack/compress`), and ranking; `--mode` is the search-mode contract for `semantic-query` (freeform intent is not a mode).
- **Semantic-query diagnostics are the shared path.** Opt-in `--timings` / `timings=true` exposes stable phase availability, operation counts, existing search stage/retriever events, and deadline margin from the same handler run. It must not select a different runtime, retriever, ranker, budget, or response contract. Unobserved work is unavailable, not a measured zero, and overlapping spans are not additive wall time.
- **Minimal high-signal options.** Bias against new knobs, especially on the MCP mirror. Prefer good defaults; every option added to `cmd/agent_*.go` must earn its place and be mirrored in the corresponding `pkg/app/mcp/tool_*.go` handler's request parsing if agent-relevant.
- **Agent validation is one-selector, structured, and non-interactive.** `rzm agent validate [default|all|audit|<check>]` returns the same additive selector/effective-check/outcome contract as human/CI validation. It never prompts or silently skips an explicit check. `identifiers` adds the pool-aware reconciliation plan, canonical claimant/conflict evidence, and all six stage timings without renaming existing result fields. Planning uses `validate fix [selector]`; agent apply is safe-only unless `--action`/`--from-plan` names exact reviewed actions, preserves transaction/replan evidence, and returns structured unresolved questions rather than asking on stdin.

## Must-dos when changing this subsystem

- **Output shape changes are breaking.** When you change a response struct, packed-text layout, warning code, or exit behavior: grep docs and RHIZOME.md templates for the old shape; update the directly embedded `docs/rhizome-md-templates/*` sources whenever agent workflow guidance changes.
- **Keep CLI and MCP aligned.** New flags/options on `rzm agent *` that matter to agents: mirror them in the shared `pkg/app/mcp/tool_*.go` handler's request parsing and update the tool descriptions in `pkg/app/mcp/CONTEXT.md` and `README.md`. New tools add one catalog descriptor with the correct memberships, factory, CLI display order/category, plus the CLI front when applicable. `rzm agent surface` derives catalog-backed command membership and metadata directly from those descriptors; only the self-describing `surface` command and top-level `note move` exception remain explicit.
- **Respect layer boundaries.** Planning/dispatch in `pkg/app/agent`; handler adaptation in `pkg/app/agentapi`; retrieval/runtime in `pkg/app/mcp`; packing in `contextpack`; rendering in `presentation`; packet assembly in `answer`. Don't let packing logic leak into commands or retrieval leak into answer.
- **Budget changes touch documented surfaces.** Changing `DefaultBudgetChars`, `agentCLIBudgetFloor`, or budget precedence requires updating `pkg/app/contextpack/CONTEXT.md` and the budget-surfaces note it links.
- **Tests beside the change** (table-driven, testify): `pkg/app/agent/*_test.go`, `pkg/app/agentapi/agentapi_test.go`, `pkg/app/contextpack/pack_test.go`, `pkg/app/answer/answer_test.go`, `pkg/app/presentation/ontology_context_test.go`, `cmd/agent_test.go`. Add a regression test for any contract fix.
- **No interactivity.** `rzm agent *` is machine-facing: JSON out, `silentExitError` on failure, never an editor or prompt.
- Validation result changes must preserve machine-valid JSON, public kebab-case check labels, explicit `completed|not_applicable|blocked` outcomes, the original selector/vault/scope in exact apply guidance, and exit 0/1/2. Source-bound repair follow-ups remain non-failing JSON evidence and GitHub warnings; they never become actions or alter counts. Migrate directly embedded templates whenever selector grammar or follow-up commands change.

## Review checklist — problems to catch

- Token budget blowouts: a caller bypassing contextpack, packing un-trimmed pieces, or inheriting the 150k agent floor on a search path that should honor the query-spec budget.
- Schema/format drift in JSON output: renamed/removed fields, changed warning codes, reordered packed-text sections, or CLI response shape diverging from the MCP handler's.
- False-confidence fallback matching: ambiguous target resolution silently widening to broad matches instead of returning structured warnings; answer packets fabricating sources not in the evidence set.
- SessionId invalidation/dedupe bugs: sessionId dropped from an args map (`maybeSetString(payload, "sessionId", agentSessionID)` missing in a new command), dedupe re-sending already-delivered content, or session state assumed where none exists.
- Guidance text drift: directly embedded `docs/rhizome-md-templates/*`, `pkg/app/mcp/CONTEXT.md`, or `README.md` describing options that no longer exist.
- Validation drift: repeatable `--check`, multiple selectors, a legacy `Skipped` result, interactive agent confirmation, or output that omits an exact preparation/apply/replan command where executable or structured unresolved guidance otherwise.
- New command not registered in `cmd/agent.go`, or missing its `ToolDescriptor` CLI membership/order/category (invisible to agents).
- Nondeterministic packing: pieces without stable `Key`s, tie-breaks depending on map iteration, or compression applied when budget pressure is immaterial.
- Knob creep: options added to MCP registration that agents will never set correctly; defaults that require a flag to be useful.

## Bulk audits and concurrency

`check_paths` returns ordered decisions from the unified ignore matcher, including nested git rules, Rhizome ignore files, configuration excludes, and physical path containment. It does not infer note inclusion. `evaluate_batch` runs independent typed requests with bounded workers, one retry policy, shared batch throttle pauses, and per-item completion evidence. Callers persist checkpoints and must not replay uncertain requests automatically.

Code-mode dispatch admits concurrent calls, with exclusive access for live vault refresh/mutation, shared access for audited existing-index reads, and independent provider/ignore calls. Lock waits honor cancellation. The client defaults to eight concurrent calls, configurable up to 32; the server admits at most 32 active handlers. Callers use `await` to order dependencies. This updates the initial serial behavior described by the persistent code-mode spec. Whole-script execution allows an explicit deadline up to 24 hours; default and per-call limits remain bounded.

Credential environments are consumed without offering to persist their values.
Compression requires explicit `compression.enabled: true`; setup no longer offers
compression configuration. See [credential policy](../../engineering/secrets.md).
