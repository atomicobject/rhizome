# Noderead subsystem guidance

## Scope

`pkg/ontology/noderead` is the request-scoped read facade over indexed ontology rows: a thin `Service` (vault def, note reader, store, schema) mints one `Scope` per request/job, and that scope batches and memoizes everything a caller needs — node hydration, locator resolution, type listings, edge traversal, neighborhoods, relation counts, multi-step expansion, and graph assembly — without re-reading the same catalog/projection data. `pkg/ontology/readmodel` is the storage-neutral DTO + store-interface layer beneath it (`NodeRow`, `FieldValueRow`, `NodeQueryPlan`, `GraphStore`): SQLite returns these rows, noderead merges them into endpoint-aware payloads. Entry points: `Scope.Execute`, `Hydrate`, `Resolve`, `TypeInstances`, `Traverse`, `Neighborhood`, `Expand`, `RelationCounts`, `Graph`/`GraphFacts`, `Walk` (`pkg/ontology/noderead/scope.go`, `execute.go`, `resolve.go`, `type_instances.go`, `graph.go`). Consumers: web UI (`pkg/app/web/node_workspace.go`, `ontology_graph.go`, `edit_session_overlay.go`, `node_projection_cache.go`), MCP tools (`pkg/app/mcp/tool_files.go`, `tool_graph_path.go`, `semantic_query_unified.go`), CLI (`pkg/app/cli/file_context.go`, `context_text.go`, `ontology_summary.go`), search retrieval (`pkg/search/retrieval/ontology.go`, `graph_ppr.go`), configured-view sources (`pkg/app/views/source_ontology.go`), GraphQL query loaders (`pkg/ontology/query/loaders.go`).

## Design constraints

- **Authored relative wikilinks resolve from their source.** Resolve `./` and `../` against `FromPath` before canonical reads, allowing an omitted extension. A missing explicit relative target must not fall back to a same-named note in another directory.

- **Read-only contract, one sanctioned write seam.** Scope methods read indexed rows and project files. `Resolve` and `LocatorsWithEnsure` with `EnsureLinkTargetApply` share one private dispatch to the explicit `Service.ApplyLinkTargets` writer capability; the application owns source mutation and durable metadata/ontology convergence. Every attempt drops scope caches and invalidates shared derived state, including source-committed publication failures and already-linkable retries. Never bypass this owner with a bare node-link apply or write the catalog from noderead.
- **Cancellation is an operation error.** Hydration and locator reads preserve cancellation/deadline errors before fallback or cache publication, including errors returned by a source reader whose child context expired while the caller context remains live. Canceled reads never become known projection/ref misses, cached snapshot errors, or completed unresolved locators. Ordinary per-host faults still fall back or omit only that host; genuine misses remain memoized.
- **One Scope per concurrent request/job.** Scope methods serialize on an internal mutex and memoize aggressively (`types.go` `Scope` struct); a scope shared across requests serves stale rows. Web mints a fresh scope per request (`node_workspace.go: nodeReadScope`); MCP tools construct service+scope per call (`tool_files.go`).
- **NOTE locator spelling remains a file path.** Catalog fingerprints and node IDs stay on canonical refs, but public document-root locators and locator-map keys use the bare note path. This does not change hydration/cache identity for any node kind.
- **Provider roots disclose their source contract.** Root hydration carries the selected format, raw-source and derived-evidence representations, and only capabilities from the executable runtime that admitted the current row. Non-Markdown workspace projection dispatches through that runtime and never enters the Markdown snapshot fallback.
- **Canonical `NodeRef` identity in every cache key.** `NodeCacheKey` is `{Ref, Profile}`; never reduce to `NodeRef.String()` or note path — locator strings collapse note roots, headings, block IDs, and embedded IDs that need different projection behavior (`types.go` doc on `NodeCacheKey`). Refs normalize through `NormalizeRef` (`helpers.go`) before keying.
- **Catalog rows are the fast path; projection fallback is bounded and scope-local.** Embedded/section hydration prefers `CatalogStore` rows; live projection only fills gaps and is cached per scope. Empty misses are cached (`refKnown`) so broad callers do not requery (`scope.go: Hydrate`, CONTEXT.md).
- **Positional source refs verify structural identity.** Unanchored `item-<byte>` refs carrying structural fingerprints batch-load catalog nodes for their requested hosts and select only a unique fingerprint match. A miss projects the requested host; duplicate matches remain ambiguous, and the offset never selects replacement content.
- **Host snapshot eligibility is a requested-path read.** `Service.ExactNoteMetadataRows` is an optional application-composed capability for provider-current, note-owned hosts during unrelated reconciliation; exact property/tag loaders may accompany it for those already admitted paths so summary hydration does not lose raw-note facts behind the global ready bit. The exported Store interface remains compatible and globally gated by default. Cache known misses within the scope. Never load whole-vault metadata, properties, tags, type rows, or assessments to project one host. Exact property/tag reads may load only requested sources already proven current Markdown; metadata eligibility failures remain errors. Whole-vault type listings retain their globally ready inventory path: that path reads `Store.OntologyAssessmentFlags` (one scan, no JSON) for has-issues and type-ambiguity only when `ontology_schema_state` is ready at the current `OntologyMaterializationVersion`; a migrated-but-not-rebuilt index carries default flags, so the scope decodes `assessment_json` for the vault instead until the rebuild lands. Decoded assessments are otherwise loaded lazily by `AssessmentsByPaths` only for callers that need issue detail.
- **Embedded cache hits must satisfy the hydration profile.** Identity/summary and content/workspace have separate cache authority, including misses. A summary hit or miss cannot suppress a later content load; successful content can serve summary. Repeated equivalent requested/canonical refs must not become cached misses. Keep per-host snapshots shared across profiles and invalidate touched source state after ensure-apply.
- **Identity-only resolution may omit link rendering.** `ResolveRequest.OmitLocators` retains parsing, catalog identity, hydration, ambiguity, and resolution errors while omitting locator fields and link-fix diagnostics. Explicit ensure-plan/apply overrides omission. Default callers still receive the complete locator result. Path-qualified identity reads must not enumerate the vault merely to choose shortest wikilink spelling.
- **Public node selectors retain canonical identity.** Resolve `#struct:` and `#node:` selectors through batched host-catalog reads. Missing or ambiguous indexed selectors remain unresolved under `IndexOnly`; previews must not substitute the note root. When staged hydration relocates an unanchored item, return its current canonical ref and record together.
- **Root-level names retain basename resolution.** A target such as `README.md` still checks the existing basename/alias inventory and can be ambiguous with `nested/README.md`. The bounded path-qualified route requires a directory separator; locator omission must not choose a root note over other basename claimants.
- **Hydration profiles gate I/O.** `identity` < `summary` < `content` < `workspace` (`types.go`). Summary hydrates from indexed metadata, properties, tags, and indexed ontology type rows, including path-matched types without authored `type` frontmatter. Declared section-backed SUMMARY fields add a batched catalog field read for note roots; staged projection supplies the same normalized body text. Never add file reads to summary paths; content/workspace explicitly opt into snapshot/projection work. `ResolveRequest.IndexOnly` also rejects catalog-missing fragments instead of projecting note content.
- **`ScopeOptions.ReadOverlay` is the only edit-session hook.** Web restores/previews the session elsewhere (`edit_session_overlay.go`) and passes touched-note markdown in. With an overlay, `Hydrate`/`TypeInstances` project touched notes from preview content, merge touched rows with committed rows by canonical `NodeRef`, and apply filter/sort/page *after* the merge so staged edits can move rows across filters/pages (CONTEXT.md). Overlay predicates and merged sorts share pure scalar/key rules with query residual evaluation in `pushdown/scalars.go`; builtin path/notePath comparisons retain exact path casing. Capture projection values and authored presence privately so empty presence survives without reading source on summary paths; committed field rows remain authoritative. `Scope.FieldValues` still supplies displayed values. Overlay type-list reads may deliberately overfetch committed rows before merging. Projection-backed records spell frontmatter dates and timestamps as the catalog stores them (`2026-09-22`, not a midnight timestamp), so a staged row matches its committed row (`frontmatterWithTemporalText` in `records.go`).
- **`ReadOverlayIndex` is immutable per session revision.** Built once (`overlay_index.go: BuildReadOverlayIndex`), shared across request scopes; web caches it keyed on `(ops, schemaHash, plan, status, conflicted, rebased)` (`edit_session_overlay.go: ontologyReadOverlayCacheKey`). A conflict does not stop staged reads: a conflicted note reads its staged replay against the session base, other touched notes read the current plan, and the overlay is marked `Conflicted` while the session routes report the conflict (`stagedPlanForConflictedPaths`).
- **Merged sorts preserve indexed null placement.** `NullsLast` keeps missing values last for ascending and descending sorts. Without it, missing values follow SQLite's native placement: first ascending and last descending. Apply direction only to comparisons of present values, preserve minimum/maximum aggregation for list fields, and break equal-value ties by SQL's note path, numeric source offset, and catalog node ID before paging. Prepare extraction and sort keys once per candidate; no store reads or projection belong in the comparator. Full canonical refs still own merge/cache identity.
- **readmodel stays DTOs + store interfaces.** It must not learn browser, search, or profile semantics; endpoint-scoping and fallback rules live in noderead so all consumers share them (`readmodel/doc.go`).
- **Graph merge is owned by `Scope.Graph`/`GraphFacts`.** Endpoint selectors keep an embedded-node request from widening into the parent note's full ambient neighborhood (`readmodel/graph.go: GraphEndpointSelector`); ontology edges take precedence over wikilink fallback; `IncludeCodeEdges`/`IncludeCalls` are opt-in; diagnostics per [[ontology-indexed-read-model-contract]]. Callers consume `Graph`/`GraphFacts`, never join graph tables directly.
- **Traverse is note-root only; Neighborhood owns embedded endpoints.** Traversal results stay grouped by source; cached unbounded batches are reusable by lower per-source limits (`scope.go: Traverse`).
- **Indexed field rows serve committed link targets.** `Scope.IndexedFieldValues` (projections) and `Scope.IndexedRecordFieldValues` (hydrated records, found by source locator) read committed field rows in batches and omit overlay-touched notes. Callers accept a row only when `IndexedLinkRow` matches its field name and value text, and resolve the rest. Note refs canonicalize to themselves; `Neighborhood` reads locators only for embedded refs, because a note locator lists every vault file (`neighborhood.go: canonicalizeNodeRefsLocked`).
- **Relation counts equal unbounded relation lists.** Count requests compile from the same computed relation selection as list reads, preserve canonical embedded source and target identity and target type/interface filters, and count distinct target refs in one batch across all sources. For inbound edges from embedded nodes, resolve source type through the catalog source locator rather than the containing note's type. `@reverse(field:)` selects inbound structural edges with the named authored relation; `@neighbors` retains ambient discovery.
- **Scope owns path-oriented walking.** `Scope.Walk` is the sole adapter from batched `Expand` traversal to the stable CLI walk result. Do not reintroduce path-by-path traversal under `pkg/ontology` or a surface-local implementation.
- **Expansion separates requested roots from canonical frontier identity.** Preserve the normalized request in each source group, canonicalize the initial frontier through the scope's existing helper, and key internal ownership and seen sets by `RefIdentityKey`. Publish groups under existing result-key conventions with locator aliases only when unambiguous and without overwriting primary keys. Each grouped edge emission consumes the minimum positive `FirstTotal`, `MaxEdges`, and edge budget; a shared downstream edge repeated for multiple roots consumes that bound for each root. Keep existing per-root `MaxNodes`, depth, cycle, filtering, and hydration behavior.
- **Fallback nodes are internal.** `_FallbackNote`/`_FallbackSection` rows hydrate for search/navigation but stay hidden from public type-list reads unless a diagnostic path asks for catalog evidence (CONTEXT.md). Concrete `@node(default: true)` note types are authored public types and should appear in ordinary `TypeInstances` / all-note reads.
- **Consumer caches must be freshness-guarded.** Web's `nodeProjectionCache` validates entries on `(schemaHash, modTime)` per note (`node_projection_cache.go`). The `SharedNodeCache` seam in `types.go` requires invalidation-aware implementations before broad use — Scope remains the authoritative cache boundary today.

- **Ensure-apply owns source and durable convergence together.** `Service.ApplyLinkTargets` is an explicit app-owned capability backed by the same live vault/store as the Scope. Missing capability or a preview overlay rejects apply before source mutation. Apply always invokes convergence for resolved embedded refs, including already-linkable refs after an earlier publication failure. The app holds the canonical index lock across the source edit and queued metadata/ontology publication; noderead never writes the catalog directly. After any attempt, all request caches and shared derived state are invalidated. Source-committed/index-incomplete errors propagate; success resolves again with ensure=never. Retained published read bundles cannot receive this capability. Graph, GraphFacts, and note-path builders capture the scope cache generation before unlocked work and publish only if it still matches; apply invalidation advances that generation. Overlapping reads may finish, but cannot restore pre-apply entries for later reads.

## Must-dos when changing this subsystem

- Keep all three surfaces consistent: web, MCP, and CLI render the same nodes through the same Scope APIs. A semantics change (identity, filtering, overlay merge, graph precedence) must hold across `pkg/app/web`, `pkg/app/mcp`, and `pkg/app/cli` consumers — no surface-local special cases.
- Cache invalidation must follow data changes. Anything that mutates catalog rows or note content must drop or version the affected caches (scope projection/snapshot maps, `nodeProjectionCache` via modTime/schemaHash, overlay cache via revision key).
- New store capability: extend `Store`/`CatalogStore`/`GraphStore` (`noderead/types.go`, `readmodel/graph.go`), implement in the sqlite store, and cover via the store contract tests (`store_contract_test.go`, `scope_test.go`). Keep batching by paths/sources — no per-row store methods.
- New overlay predicate/sort support: implement deliberately inside noderead (merge-then-filter contract), not as ad hoc operators in callers (CONTEXT.md "Overlay limits").
- Keep fan-out bounded: respect request limits and `ScopeOptions.Budget`; new expansion takes the narrower of the two.
- Run `go test ./pkg/ontology/noderead/... ./pkg/ontology/readmodel/...`; add `go test -tags=integration ./...` when store row shapes or graph merge change.
- Update `pkg/ontology/noderead/CONTEXT.md` and the linked specs when entry points or invariants move.

## Review checklist — problems to catch

- **Writes sneaking into read paths**: note edits, catalog writes, or index mutation inside noderead. Explicit Resolve/locator ensure-apply delegates the whole operation to a caller-composed live-writer capability.
- **Stale reads after edits**: a Scope reused across requests; a consumer cache missing schemaHash/modTime guards; catalog refresh that forgets to drop scope projection/snapshot caches.
- **Overlay bypass**: a web read path consulting committed rows directly while an edit session overlay is active; or filter/sort/page applied before the touched/committed merge.
- **Identity collapse**: caching or deduping embedded/section nodes by note path or `NodeRef.String()` instead of canonical ref + profile.
- **Per-node N+1**: looping `Hydrate`/`Traverse` one ref at a time, or store methods that query per row instead of batching by paths/sources.
- **Web/MCP/CLI divergence**: one surface re-implementing resolution, graph precedence, or fallback visibility instead of calling the Scope API.
- **Endpoint widening**: graph requests for embedded nodes dropping `GraphEndpointSelector` and pulling the parent note's whole ambient neighborhood.
- **Fallback leakage**: `_FallbackNote`/`_FallbackSection` rows appearing in public type lists.
- **Profile creep**: file reads added to summary hydration; readmodel DTOs growing browser/search/profile semantics.
- **Inventory decode**: a whole-vault read that decodes `assessment_json` to derive a flag while the materialized columns are trusted (state ready at the current materialization version).
- **Unbounded fan-out**: new traversal/expansion ignoring request limits and scope `Budget`.
