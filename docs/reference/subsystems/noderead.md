# Noderead subsystem guidance

## Scope

`pkg/ontology/noderead` is the request-scoped read facade over indexed ontology rows: a thin `Service` (vault def, note reader, store, schema) mints one `Scope` per request/job, and that scope batches and memoizes everything a caller needs — node hydration, locator resolution, type listings, edge traversal, neighborhoods, relation counts, multi-step expansion, and graph assembly — without re-reading the same catalog/projection data. `pkg/ontology/readmodel` is the storage-neutral DTO + store-interface layer beneath it (`NodeRow`, `FieldValueRow`, `NodeQueryPlan`, `GraphStore`): SQLite returns these rows, noderead merges them into endpoint-aware payloads. Entry points: `Scope.Execute`, `Hydrate`, `Resolve`, `TypeInstances`, `TypeSummaries`, `Neighborhood`, `Expand`, `RelationCounts`, `Graph`/`GraphFacts`, `Walk` (`pkg/ontology/noderead/scope.go`, `execute.go`, `resolve.go`, `type_instances.go`, `graph.go`). Consumers: web UI (`pkg/app/web/node_workspace.go`, `ontology_graph.go`, `edit_session_overlay.go`, `node_projection_cache.go`), MCP tools (`pkg/app/mcp/tool_files.go`, `tool_graph_path.go`, `semantic_query_unified.go`), CLI (`pkg/app/operations/file_context.go`, `context_text.go`, `ontology_summary.go`), search retrieval (`pkg/search/retrieval/ontology.go`, `graph_ppr.go`), configured-view sources (`pkg/app/views/source_ontology.go`), GraphQL query loaders (`pkg/ontology/query/loaders.go`).

## Design constraints

- **Authored relative wikilinks resolve from their source.** Resolve `./` and `../` against `FromPath` before canonical reads, allowing an omitted extension. A missing explicit relative target must not fall back to a same-named note in another directory.

- **Read-only contract, one sanctioned write seam.** Scope methods read indexed rows and project files. `Resolve` and `LocatorsWithEnsure` with `EnsureLinkTargetApply` share one private dispatch to the explicit `Service.ApplyLinkTargets` writer capability; the application owns source mutation and durable metadata/ontology convergence. Every attempt drops scope caches and delegates shared-state invalidation to the writer owner, including source-committed publication failures and already-linkable retries. Never bypass this owner with a bare node-link apply or write the catalog from noderead.
- **Cancellation is an operation error.** Hydration and locator reads preserve cancellation/deadline errors before fallback or cache publication, including errors returned by a source reader whose child context expired while the caller context remains live. Canceled reads never become known projection/ref misses, cached snapshot errors, or completed unresolved locators. Store failures propagate. Explicit source projection may report an ordinary unresolved host diagnostic; genuine misses remain memoized.
- **One Scope per concurrent request/job.** Scope methods serialize on an internal mutex and memoize aggressively (`scope_types.go` `Scope` struct); a scope shared across requests serves stale rows. Web mints a fresh scope per request (`node_workspace.go: nodeReadScope`); MCP tools construct service+scope per call (`tool_files.go`).
- **NOTE locator spelling remains a file path.** Catalog fingerprints and node IDs stay on canonical refs, but public document-root locators and locator-map keys use the bare note path. This does not change hydration/cache identity for any node kind.
- **Provider roots disclose their source contract.** Root hydration carries the selected format, raw-source and derived-evidence representations, and only capabilities from the executable runtime that admitted the current row. Non-Markdown workspace projection dispatches through that runtime and never enters the Markdown snapshot fallback.
- **Canonical `NodeRef` identity in every cache key.** `NodeCacheKey` is `{Ref, Profile}`; never reduce to `NodeRef.String()` or note path — locator strings collapse note roots, headings, block IDs, and embedded IDs that need different projection behavior (`scope_types.go` doc on `NodeCacheKey`). Refs normalize through `NormalizeRef` (`helpers.go`) before keying.
- **Summary uses indexed identity.** Embedded and section summary hydration uses the required `ReadStore` catalog. A catalog miss remains a memoized miss. Content hydration explicitly projects requested hosts and shares their snapshots within the scope. Empty embedded type listings never trigger whole-vault source projection.
- **Positional source refs verify structural identity.** Unanchored `item-<byte>` refs batch-load only requested host catalog rows. Match a unique canonical structural identity or the separate indexed `RelocationFingerprint` continuity witness. Duplicate matches remain ambiguous; an offset never selects replacement content. Content hydration can verify the requested source when the index lacks identity.
- **Host reads are scoped to requested paths.** Exact metadata, property and tag loaders remain optional application-composed authority for provider-current notes during reconciliation. All storage capabilities are required by `ReadStore`. Summary issue flags use `OntologyAssessmentFlagsByPaths` only when the persisted materialization is current; stale publications decode only requested assessments. Whole-vault metadata/type/flag inventory is reserved for All/Issues and explicit aggregate reads. `MetadataInventory` loads metadata independently of type and assessment state.
- **Embedded cache hits satisfy their profile.** Summary and content have separate cache entries, including misses. A summary miss cannot suppress a later content load. Content can serve summary, but summary output always omits Content. Clone mutable values once at the API boundary, including nested frontmatter, typed scalar pointers, projected field slices and locator diagnostics.
- **Link rendering is opt-in.** `ResolveRequest.IncludeLocators` requests source locators and author-facing links. Explicit ensure-plan/apply also computes them. Canonical identity reads use catalog rows and preview records without enumerating notes or reading source. Explicit rendering shares one prepared renderer, path inventory and staged snapshot loader per scope.
- **Preferred identifiers use bounded indexed fields.** Resolve note and embedded identifiers through field-equality plans, cache normalized hits and misses per scope, and merge staged replacements before ambiguity decisions. Do not enumerate type paths or load note properties to discover identifiers. A basename note that claims a duplicate identifier must report that ambiguity through the same Scope contract.
- **Public node selectors retain canonical identity.** Resolve `#struct:` and `#node:` selectors through batched host-catalog reads. Missing or ambiguous indexed selectors remain unresolved under `IndexOnly`; previews must not substitute the note root. When staged hydration relocates an unanchored item, return its current canonical ref and record together.
- **Root-level names retain basename resolution.** A target such as `README.md` still checks the existing basename/alias inventory and can be ambiguous with `nested/README.md`. The bounded path-qualified route requires a directory separator; locator omission must not choose a root note over other basename claimants.
- **Hydration profiles gate I/O.** The public profiles are `summary` and `content`. Summary uses indexed metadata, properties, tags, types and catalog field rows. Preview summary reads project supplied staged content without reading files. Content opts into source snapshots. `ResolveRequest.IndexOnly` rejects catalog-missing fragments instead of projecting source.
- **`ScopeOptions.ReadOverlay` is the only edit-session hook.** Web restores/previews the session elsewhere (`edit_session_overlay.go`) and passes touched-note markdown in. With an overlay, `Hydrate`/`TypeInstances` project touched notes from preview content, merge touched rows with committed rows by canonical `NodeRef`, and apply filter/sort/page *after* the merge so staged edits can move rows across filters/pages (CONTEXT.md). Overlay predicates and merged sorts share pure scalar/key rules with query residual evaluation in `pushdown/evaluate.go` and `pushdown/scalars.go`; builtin path/notePath comparisons retain exact path casing. Capture projection values and authored presence privately so empty presence survives without reading source on summary paths; committed field rows remain authoritative. `Scope.FieldValues` still supplies displayed values. Overlay type-list reads may deliberately overfetch committed rows before merging. Projection-backed records format dates and timestamps according to their declared scalar type, preserving DateTime midnight timestamps and authored offsets, so a staged row matches its committed row (`frontmatterWithTemporalText` in `hydrate_projection.go`). Staged records use their supplied modification time or explicitly loaded host metadata, independent of prior reads.
- **`ReadOverlayIndex` is immutable per session revision.** Built once (`overlay_index.go: BuildReadOverlayIndex`), shared across request scopes; web caches it keyed on `(ops, schemaHash, plan, status, conflicted, rebased)` (`edit_session_overlay.go: ontologyReadOverlayCacheKey`). A conflict does not stop staged reads: a conflicted note reads its staged replay against the session base, other touched notes read the current plan, and the overlay is marked `Conflicted` while the session routes report the conflict (`stagedPlanForConflictedPaths`).
- **Merged sorts preserve indexed null placement.** `NullsLast` keeps missing values last for ascending and descending sorts. Without it, missing values follow SQLite's native placement: first ascending and last descending. Apply direction only to comparisons of present values, preserve minimum/maximum aggregation for list fields, and break equal-value ties by SQL's note path, numeric source offset, and catalog node ID before paging. Prepare extraction and sort keys once per candidate; no store reads or projection belong in the comparator. Full canonical refs still own merge/cache identity.
- **readmodel stays DTOs + store interfaces.** It must not learn browser, search, or profile semantics; endpoint-scoping and fallback rules live in noderead so all consumers share them (`readmodel/doc.go`).
- **Graph merge is owned by `Scope.Graph`/`GraphFacts`.** Endpoint selectors keep an embedded-node request from widening into the parent note's full ambient neighborhood (`readmodel/graph.go: GraphEndpointSelector`); ontology edges take precedence over wikilink fallback; `IncludeCodeEdges`/`IncludeCalls` are opt-in; diagnostics per [[ontology-indexed-read-model-contract]]. Callers consume `Graph`/`GraphFacts`, never join graph tables directly. Shared truncation preserves requested sources, prioritizes typed evidence and weight, and returns edges only when both endpoints fit the retained node set.
- **Indexed neighborhoods batch exact endpoints.** `OntologyNeighborhood` selects all relation names, direction, provenance and structural/ambient filters in one batched SQL request. Note roots do not include embedded endpoints. Eligible limits use per-source window ranking with one extra row to retain truncation evidence; target-type/kind filters use canonical endpoint identities before final limits. A section target keeps SECTION kind, and embedded types come from catalog identity rather than host-note types. All relation consumers share this path; request-shaped raw row caches include direction, filters, endpoint identity and limits, and never cache failures.
- **Indexed field rows serve committed link targets.** `Scope.IndexedFieldValues` and `IndexedRecordFieldValues` batch committed rows and omit touched preview notes. Accept a row only when `IndexedLinkRow` matches the field name and authored value text. Embedded canonicalization uses catalog or preview identity directly and never invokes link rendering.
- **Relation counts equal unbounded relation lists.** Count requests compile from the same computed relation selection as list reads, preserve canonical embedded source and target identity and target type/interface filters, and count distinct target refs in one batch across all sources. For inbound edges from embedded nodes, resolve source type through the catalog source locator rather than the containing note's type. `@reverse(field:)` selects inbound structural edges with the named authored relation; `@neighbors` retains ambient discovery.
- **Scope owns path-oriented walking.** `Scope.Walk` is the sole adapter from batched `Expand` traversal to the stable CLI walk result. Do not reintroduce path-by-path traversal under `pkg/ontology` or a surface-local implementation.
- **Expansion separates requested roots from canonical frontier identity.** Preserve the normalized request in each source group, canonicalize the initial frontier through the scope's existing helper, and key internal ownership and seen sets by `RefIdentityKey`. Publish groups under existing result-key conventions with locator aliases only when unambiguous and without overwriting primary keys. Each grouped edge emission consumes the minimum positive `FirstTotal`, `MaxEdges`, and edge budget; a shared downstream edge repeated for multiple roots consumes that bound for each root. Keep existing per-root `MaxNodes`, depth, cycle, filtering, and hydration behavior.
- **Fallback nodes are internal.** `_FallbackNote`/`_FallbackSection` rows hydrate for search/navigation but stay hidden from public type-list reads unless a diagnostic path asks for catalog evidence (CONTEXT.md). Concrete `@node(default: true)` note types are authored public types and should appear in ordinary `TypeInstances` / all-note reads.
- **Structural dispatch follows provider capabilities.** Generic root projection selects structural handling from the registered provider’s capabilities. The named `markdownStructuralSnapshotCompat` adapter requires current Markdown identity and executable structural capability before parsing; unsupported structural providers keep their native root projection. Explicit legacy Markdown rows can enter only when no selected provider owns the path. Preview syntax enters through the explicitly Markdown overlay contract. Generic projection and snapshot caches do not choose syntax by format-name literals.

- **Current snapshots retain selected-provider facts.** Registered Markdown sources project through their selected provider before `BuildMarkdownDocumentSnapshot` captures structural state. `DocumentSnapshot.SelectorFacts` supplies defensive copies of captured title, tags, frontmatter, and inline values. Scope retains the selected provider root beside its structural snapshot and attaches it to Markdown root projections, so authored link facts remain authoritative even when the provider replaces or suppresses a raw link. Root-first and section-first reads share one source capture; preview snapshots never acquire committed provider facts. Projection-backed records read its authoritative tags, including an empty set, without reparsing raw source or inferring missing provider facts. Plain Markdown syntax construction uses the shared neutral title/tag rules once.

- **Consumer caches require freshness guards.** Web projection entries validate schema hash and modification time. Scope owns request-local memoization; there is no speculative shared node cache.

- **Ensure-apply owns source and durable convergence together.** `Service.ApplyLinkTargets` is an explicit app-owned capability backed by the same live vault/store as the Scope. Missing capability or a preview overlay rejects apply before source mutation. Apply always invokes convergence for resolved embedded refs, including already-linkable refs after an earlier publication failure. The app holds the canonical index lock across the source edit and queued metadata/ontology publication; noderead never writes the catalog directly. After any attempt, all request caches and shared derived state are invalidated. Source-committed/index-incomplete errors propagate; success resolves again with ensure=never. Retained published read bundles cannot receive this capability. Graph, GraphFacts, and note-path builders capture the scope cache generation before unlocked work and publish only if it still matches; apply invalidation advances that generation. Overlapping reads may finish, but cannot restore pre-apply entries for later reads.

- **Type summaries share one catalog pass.** `TypeSummaries` counts named public types and interfaces from one catalog read, with requested-host flags and metadata. Interface unions deduplicate canonical refs and issue counts deduplicate hosts. Counts cover the whole selection while preview slices retain at most the requested examples. Preview records merge before counting and preview ordering. `OntologyShape` remains a committed note-only aggregate.

- **Scope aggregates are committed index reads.** `OntologyShape` uses `readmodel.ShapeStore` to read one SQLite snapshot, then derives profiles, distinct note pairs, target sets, and folder counts without hydration. Embedded/section relation endpoints are excluded; independent host document links and broad `Note` fields count as plain links. Member issue counts use published validation scopes through the web adapter, matching the issues panel. Interfaces use their own profiles over note-type implementors. `Scope.RecentNotes` uses `readmodel.RecentStore` to select the newest 1..500 notes in SQL before enrichment, with All notes identity and untyped inclusion. Requested parts are independent, and mismatched metadata/ontology publication witnesses or a schema mismatch set `rebuilding`. Materialized assessment flags require current materialization evidence; stale snapshots decode their retained assessments.

## Must-dos when changing this subsystem

- Keep all three surfaces consistent: web, MCP, and CLI render the same nodes through the same Scope APIs. A semantics change (identity, filtering, overlay merge, graph precedence) must hold across `pkg/app/web`, `pkg/app/mcp`, and `pkg/app/operations` consumers — no surface-local special cases.
- Cache invalidation must follow data changes. Anything that mutates catalog rows or note content must drop or version the affected caches (scope projection/snapshot maps, `nodeProjectionCache` via modTime/schemaHash, overlay cache via revision key).
- New store capability: extend the required `ReadStore` in `service.go` and the relevant `readmodel` contract. Implement SQLite batching and cover observable behavior with owning store or scope tests. Missing capabilities must fail during composition rather than silently changing read semantics.
- New overlay predicate/sort support: implement deliberately inside noderead (merge-then-filter contract), not as ad hoc operators in callers (CONTEXT.md "Overlay limits").
- Keep fan-out bounded by explicit request limits and `TraverseBudget`. Overlay listings fetch at most 10,001 committed candidates and return an explicit error when the 10,000-candidate merge budget is exceeded.
- Run `go test ./pkg/ontology/noderead/... ./pkg/ontology/readmodel/...`; add `go test -tags=integration ./...` when store row shapes or graph merge change.
- Update `pkg/ontology/noderead/CONTEXT.md` and the linked specs when entry points or invariants move.

## Review checklist — problems to catch

- **Writes sneaking into read paths**: note edits, catalog writes, or index mutation inside noderead. Explicit Resolve/locator ensure-apply delegates the whole operation to a caller-composed live-writer capability.
- **Stale reads after edits**: a Scope reused across requests; a consumer cache missing schemaHash/modTime guards; catalog refresh that forgets to drop scope projection/snapshot caches.
- **Overlay bypass**: a web read path consulting committed rows directly while an edit session overlay is active; or filter/sort/page applied before the touched/committed merge.
- **Identity collapse**: caching or deduping embedded/section nodes by note path or `NodeRef.String()` instead of canonical ref + profile.
- **Per-node N+1**: looping `Hydrate`/`Neighborhood` one ref at a time, or store methods that query per row instead of batching by paths/sources.
- **Web/MCP/CLI divergence**: one surface re-implementing resolution, graph precedence, or fallback visibility instead of calling the Scope API.
- **Endpoint widening**: graph requests for embedded nodes dropping `GraphEndpointSelector` and pulling the parent note's whole ambient neighborhood.
- **Fallback leakage**: `_FallbackNote`/`_FallbackSection` rows appearing in public type lists.
- **Profile creep**: file reads added to summary hydration; readmodel DTOs growing browser/search/profile semantics.
- **Inventory decode**: a whole-vault read that decodes `assessment_json` to derive a flag while the materialized columns are trusted (state ready at the current materialization version).
- **Unbounded fan-out**: traversal or expansion ignoring request limits and the explicit plan budget.

## Key files

- `service.go`, `scope_types.go`, `types.go`: required store composition, scope state and hydration contracts.
- `scope.go`, `hydrate_notes.go`, `hydrate_embedded.go`, `hydrate_projection.go`: profile-specific hydration and API-boundary cloning.
- `resolve.go`, `resolve_targets.go`, `resolve_paths.go`, `locators.go`, `link_service.go`: canonical resolution, optional rendering and explicit apply.
- `type_instances.go`, `interface_instances.go`, `type_instances_overlay.go`, `field_values.go`: indexed selection and merge-before-page semantics.
- `overlay_index.go`, `overlay_records.go`: immutable preview index and staged records.
- `execute.go`, `execute_relations.go`, `execute_planning.go`: batched plan execution and explicit budgets.
- `graph.go`, `graph_facts.go`, `graph_limits.go`, `neighborhood.go`, `expand.go`, `counts.go`, `walk.go`: graph assembly and traversal.
- `inventory.go`, `scope_inventory.go`, `scope_state.go`: independent metadata inventory and requested-path state.
- `pkg/ontology/readmodel`: catalog/query/graph DTOs and storage contracts.
- `pkg/app/web/edit_session_overlay.go`, `node_projection_cache.go`: preview ownership and freshness guards.
