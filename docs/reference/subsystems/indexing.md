# Indexing subsystem guidance

## Scope

Everything that turns vault + code roots into persisted SQLite indexes: batch `rzm index`, watcher-driven live refresh, lightweight validation projection refresh, file discovery, queued writeback, perf instrumentation, and cross-process lock coordination. Entry points: `RunUnifiedCore` (`pkg/app/indexing/unified.go`), `RefreshValidationProjection` (`pkg/app/indexing/validation_projection.go`), `RunCodeIndexCommand`/`RunCodeAnchorsCommand` (`pkg/app/indexing/commands.go`), `TryAcquireIndexLock` (`pkg/app/indexing/lock.go`), `CountFiles`/`ProcessFiles` (`pkg/app/indexingpipe/files.go`), `indexlock.TryAcquire` (`pkg/vault/indexlock/lock.go`), CLI wiring in `cmd/index.go`, MCP-boot background index in `cmd/runtime_helpers.go` (`runBackgroundIndex`).

## Design constraints

- **Semantic factories own provider lifetimes.** Unified indexing closes every provider it constructs, including setup failures before a store opens. It drains lane nodes and stores before closing optional provider caches; compatible lanes sharing a node do not transfer ownership of either factory-created provider.

- **Metadata polling permits owner cleanup.** Windows lock and priority-file readers share read, write, and delete access. A polling reader must not block an owner from removing its metadata; existing ownership checks still govern cleanup and stale-lock reclamation. Existing stale metadata is replaced through the cooperative `fileio.Replace` primitive, without a delete/open gap; ordinary Windows readers that deny deletion sharing still cause a truthful publication error.
- **Every active waiter retains priority.** `.rhizome/index.priority/` contains one token-named JSON record per request. `RequestPriority` returns an owned `PriorityRequest`: `Active` checks this exact record's freshness, regular-file metadata, and full owner token; `Close` is idempotent and joins the heartbeat before removing only that owner record. Wait loops for repair, CLI mutation, ontology recovery, and interactive indexing close and replace their own inactive handle even while a peer remains live. Interactive indexing keeps priority errors nonfatal and retries on its normal poll. Publication writes complete metadata atomically to an independent unique path; admission and cleanup do not wait for other owners' scanning. Heartbeats never recreate missing/replaced records and check stop before starting another guarded refresh. The persistent sibling OS guard serializes refresh with stale pruning. Background holders use aggregate `CheckPriority`, which honors same-process and fresh foreign-runtime requests and removes expired or same-runtime dead-PID records. A busy guard permits a read-only scan without pruning and is not evidence of a waiter. Pruning is limited to token-named records and recognized temporary publication files, with expired entries removed after the 90-second recovery grace; unrelated files and non-regular entries are preserved. The exact priority path must be a directory, never a symlink; parent vault aliases remain supported. Empty directories and the single guard remain. This replaces the former single `index.priority` file: concurrent old and new versions cannot exchange priority requests. Stop every Rhizome process using the vault before upgrading, and remove a leftover legacy priority file after its waiters exit. Index-lock exclusivity is unchanged.
- **Lock ownership survives pauses and crashes.** A live PID keeps its lock regardless of heartbeat age because a paused writer can resume. A dead PID is reclaimed automatically in the same runtime identity or a proven earlier local boot. Earlier-boot recovery requires the exact recorded hostname, valid boot metadata, and an acquisition timestamp before the current boot; Linux also rejects another PID namespace on the same boot. Foreign hosts, uncertain identities, and reused live PIDs remain protected. A persistent OS-locked guard serializes metadata creation, recovery, heartbeat, and release and is released by the kernel on process exit. Creation publishes fully written, closed metadata from a sibling file to an absent final lock path while holding the guard. Stale takeover rechecks the current owner under that guard and atomically replaces an existing record through `fileio.Replace`; if the old owner disappeared, it uses absent-path creation. Preparation and replacement failures preserve existing metadata and clean up the owned temporary file. A crash before publication cannot leave an empty final lock. Lock and priority-request tokens are random and independent of the `Started` timestamp, so successive owners in one process remain distinct when clock readings match. The heartbeat checks the full owner token before touching metadata.

- **Validation publication shares the writer lane.** Full indexing submits its complete diagnostic snapshot through the existing queued writer. Live startup, watcher changes, and post-save invalidation converge through the validation coordinator and coalesced refresh requester; do not bypass it with a second scan that loses live repair authority.
- **Validation yields with its indexing job.** The configured snapshot has its own `validation_snapshot` span. Identifier migration honors the job context inside note, section and reference loops, and suite cancellation discards partial findings and fixes after all checks join. Reconciliation acknowledgement and durable writer barriers retain their existing ordering.
- **Semantic watch work has independent ownership.** The watcher retains hub paths and resync notices across read-side cache refreshes. It swaps the pending set into a lane batch, restores failed inputs without overwriting newer events, and removes completed inputs only after the destination work succeeds.

- **Intent snapshots use the durable writer.** Full indexing publishes the complete intent exemplar snapshot through `SubmitIntentEmbeddingSnapshot`; it obeys queue flush/error barriers and carries the provider fingerprint with the vectors. The intent producer must not write directly to SQLite. Held snapshots expose pending rows until publication or failure.
- **Timings include unspanned work.** Counter/latency-only ontology embedding phases remain visible without inventing a wall duration. Ownership discovery/transition and the final ontology body pass have separate spans; provider attempts, received response headers, transport failures, status retries, splits, and backoff retain the shared batch phase. Provider inflight counts physical calls after concurrency-gate acquisition; active calls and held intent snapshots keep rolling windows visible.

- **Minimum end-to-end latency is the optimization target.** Parse/embed/provider work fans out in parallel; latency wins come from overlap and batching, never from extra passes (`pkg/app/indexing/doc.go`).
- **Note metadata composition stays explicit.** Every public indexing-core and validation-projection request carries an explicit `notemeta.Indexer`, validates it before lock or store mutation, and never selects a provider itself. The command or `LiveRuntime` composes that indexer; provider-projected metadata crosses the durable source barrier before ontology receives `SyncPublishedPaths`.
- **One queued writer per indexing job.** `indexwriter.Writer` owns bounded submission, batching, and ordered controls for both batch and live structural work. SQLite WAL commits one writer at a time; parallel producers submit to this queue instead of competing for writes. Runtime derived publication uses short serialized lane jobs under the same vault lease.
- **Batch and live share structural publication.** `indexcore.Discover` captures the prior metadata and ownership before destructive transitions. `indexcore.Publish` owns dependency expansion, sealed source preparation, ingestion, metadata, structural dependency finalization, and ontology publication. Batch keeps streaming semantic hooks; live schedules derived work after this committed boundary. A non-nil empty path set is a no-op. Ordinary content edits use scoped metadata without rereading untouched sources; alias or path topology changes may request complete publication.
- **Derived work is durable before structure changes.** Record dirty kind/path scopes before the first structural mutation, then activate them only after structural publication drains. An inactive obligation forces full structural recovery even if interruption preceded the ownership marker. Provider failures leave active obligations for quiet retries; they do not reopen completed structural reconciliation.
- **Provider results require current inputs.** Batch and live use the same semantic compute stages. Live computes outside the vault writer lease and publishes in bounded lane jobs. Before result, cleanup, freshness, or acknowledgement writes, compare the exact work generation and the structural source fingerprint. A direct save can change that fingerprint before the watcher observes its path. Derived outputs must not appear in their own input fingerprint.
- **Ownership replacement and reconciliation acknowledgement are ordered writer controls, not batches.** Each control captures a submit barrier, drains and flushes earlier payloads, performs exactly one store call on the writer goroutine, and returns the committed result. This exception exists because destination-lane work depends on the transition result and exact-generation acknowledgement must not race queued writes; controls remain specific typed operations rather than arbitrary closures.
- **A normal unified run has one ownership discovery run.** It walks eligible vault files once before lane filtering, preserves dotfile/hidden-directory pruning independently of unified ignore, and assigns each candidate exclusively to Markdown-note, code, or unowned/ignored. Destination lanes consume only its explicit candidates and keep sets; they must not rediscover or reclassify paths.
- **Full scope changes converge through ownership discovery.** The legacy mtime-invalidation scope-change path no longer exists: erasing durable source hashes and mtimes before ownership reconciliation is not a supported convergence mechanism. The explicit ownership run already sees additions, removals, and owner changes under the current include/exclude scope.
- **Ownership is committed before destination work.** The full-index prefix reads persisted owners, prepares deterministic source-only replacements, submits the typed transition fence before note/code enqueue, and uses returned affected paths/anchor IDs only after commit. Every executable provider enters one sealed metadata publication pass. Markdown alone enters structural section and anchor ingestion. Descriptor-only formats publish canonical source identity with a stale projection and no metadata, search, graph, ontology, or code evidence. Each transition deletes or replaces the touched path's metadata and provider-region lexical rows in the same transaction that marks global metadata pending, so requested-path readers may continue using retained current projections for untouched paths while inventory readers remain behind global readiness.
- **Ontology semantic rebuilds use the projectable path set.** Full indexing and watcher rebuild routes select provider-current, ontology-eligible paths through `ontology.ProjectableMetadataPaths`. Semantic preparation uses the same provider source snapshots as structural projection; only Markdown receives Markdown spans. `CurrentNoteMetadataPaths` is raw source inventory and includes descriptor-only sources, so it is not an ontology projection worklist. Live and full indexing derive changed root work from the committed provider metadata delta, including root-only formats that never enter Markdown ingestion.
- **Structural recovery is intentionally coarse.** A pending ownership generation or inactive derived obligation forces every current owner through its eligible lane, including no-code-root and embeddings-disabled runs. Exact-generation ownership acknowledgement follows structural dependency finalization, ontology publication, and durable derived activation. Semantic cleanup and graph completion have separate durable obligations. Complete code cleanup uses the complete code keep set, including an empty set; a scoped keep set must never drive global pruning. Candidate Markdown or explicit code read/build failure stops publication and preserves recovery debt.
- **Batch everything**: per-kind flush policies (rows/bytes/idle, e.g. code 512 rows / 8 MiB / 100 ms) accumulate writes into bulk transactions; batching only at the queue is insufficient if store internals still autocommit per row.
- **Integrate into existing pipeline stages, not bolt-on passes.** New work joins discovery → ingest → ontology projection → semantic lanes → final drain → graph → maintenance, sharing the timing collector, writer lane, and barriers — the package is "a coordinator, not a bag of independent jobs".
- **Ontology publication is atomic.** Sync submits its assessment/edge delta and ordered node read models together through `SubmitOntologyDelta`. SQLite commits the rebuild clear and replacement catalog together, so readers never observe an empty catalog between those writes. Standalone catalog/body writes retain their existing queue ordering. Validation binds the semantic-preserving delta writer.
- **Explicit correctness barriers stay explicit**: `FlushAndWait` drains before cross-file work (call graph, graph signals); ontology deltas drain before ontology node read-model writes so FullRebuild truncates cannot wipe queued inserts (`indexwriter/run_flush.go` flush ordering). Initial streaming producers and their queued writes finish before the final ontology catalog refresh; a catalog replacement may delete chunk parents reused by an in-flight ontology body worker.
- **Streaming drain preserves accepted writes before reporting cancellation.** `DrainStreamingWrites` closes streaming producers, flushes their queued writes, then reports caller cancellation alongside any queue error. Cancellation must not short-circuit the durability barrier.
- **Cross-process exclusivity via `.rhizome/index.lock`**: every index-writing entry point acquires the lock with a `role`; stale PID/heartbeat reclaim requires matching runtime identity (lowercase short hostname plus boot time); foreign locks require explicit operator recovery because mtime alone cannot fence a paused owner; interactive runs request priority (`RequestPriority`) and wait without a deadline while naming the holder instead of deleting a live lock; background holders poll priority every second and cancel promptly (`pkg/vault/indexlock/lock.go`). Runtime indexing and validation projection use the indexing lane, once per job; interactive repairs keep the validate-owned lease through source writes and postcheck. Priority requests include interactive writers in the same process ([[vault-runtime]], [[vault-runtime-coordination|SPEC-0104]]); `rzm index` with a live runtime submits a lane job instead of acquiring the lock itself.
- **`--rebuild` is destructive authorization.** An explicit rebuild clobbers the unified SQLite DB and WAL/SHM sidecars after acquiring the index lock, then recreates every domain. It never runs inside a live vault runtime: `PrepareFreshRebuild` refuses while a live manifest exists, and the command stops a headless runtime first (an attached one must be stopped by the operator). Top-level code/semantic mode flags, force overrides, and scoped rebuilds are retired. Plain indexing honors configured code roots (with no roots configured, the whole project; see the code-intel note) and embedding enablement. Ordinary indexing never clobbers the database and tells the operator to rerun with `--rebuild` when replacement is required.
- **Watcher batches yield and fail without losing reconciliation.** The indexing lane cancels the batch context, retains the lease until active work stops, and lets the next watcher tick retry incomplete work. Preserve drained events after cancellation or any other reconciliation failure, retain pending generations, defer while interactive priority remains requested, and never acknowledge incomplete destination work.
- **Deletions bypass the rewrite throttle.** The per-path cooldown damps repeated rewrites of a hot file; a dirty path that no longer exists on disk is processed in the current batch. Live metadata publication reads every persisted note that the batch did not observe, so a deferred deletion would leave a persisted row whose read fails and forces a resync.
- **Bounded backpressure, no hidden queues**: discovery walk-ahead is bounded by real worker capacity (`pkg/app/indexingpipe/files.go`); queue channels are capped (`indexQueueCapacity`).
- **Incomplete legacy discovery cannot authorize stale cleanup.** `ProcessFiles` returns encountered directory-walk errors after accepted workers drain; `CountFiles` returns those errors instead of a partial total. Code-index and code-anchor command adapters propagate the failure before reporting successful note ingestion. Deliberate subtree exclusions, missing/non-directory selected roots, and legacy individual-file read/build tolerance retain their existing behavior. Explicit ownership-routed candidate error policy is unchanged.
- **Watcher shutdown drains owned work.** `watchhub.Close` stops admission, cancels its loops and backend retries, waits for admitted subscriber callbacks and watch installation, discards pending debounce events, then closes its final backend. Subscribers may unsubscribe themselves but must not synchronously close their hub. Repeated close is safe; start is single-use. The fsnotify event pump stays alive through the drain because Windows watch installation and event delivery share a native reader. Cancellation is checked between filesystem operations; an in-flight OS call must return before shutdown can complete.
- **New directory trees become recursively visible.** On nonrecursive backends, a created or moved-in directory enters the bounded installation queue. The existing cancellation-aware walker applies the most specific matching root's hidden-directory policy to each directory and the shared ignore rules, including traversal for exact `CONTEXT.md` under ordinary user excludes. Registered descendant roots are also revisited independently so an outer root's hidden pruning cannot suppress their visibility. Removal or rename clears watch and walk tracking for the old subtree, permitting root recreation. Installation requests a non-coalesced resync after watches are active so consumers discover files written during the discovery-to-watch gap. Overlapping roots and repeated directory events share watch deduplication.
- **Readiness covers queue handoff.** Directory-installation work is counted before enqueueing and remains counted until installation completes. Admission to a full queue rolls back its count and signals overflow, preserving bounded backpressure without a false-ready interval after dequeue.
- **Vault-root-relative paths only** in indexes and watch events (`pkg/paths`, `watchhub` doc comment).
- **System-note discovery is route-invariant.** Full, rebuild, semantic/code note ingest, validation discovery, cache resync, and incremental updates select exact `CONTEXT.md` outside ordinary `notes.includes`/`notes.excludes`; hard ignore, infrastructure, containment, and read-error boundaries still apply. Candidate counting and ingest must use the same dual-policy traversal.
- **Writer priority is a scheduling hint, not a barrier**: code-hot deferral of semantic writeback has a `semanticUrgent` escape hatch so backlog stays bounded.
- **Truthful timing labels**: every queue submit/flush is attributed to phase+op via `indexingperf`; deferred flushes report `node.write.deferred`, not fake enqueue blocking.
- **Stable timing presentation is descriptor-driven**: repeated writeback metric namespaces, output prefixes, and presentation order live in the immutable descriptor tables in `pkg/indexingperf/writeback_metrics.go`; window and cumulative renderers must consume the same descriptors.
- **Agent-start diagnostics are stable and availability-aware.** `pkg/indexingperf/agent_start.go` owns the ordered phase/operation descriptors consumed by `agent start --timings`. A zero count means measured zero only when `available` is true; omitted capabilities and uninstrumented boundaries must not masquerade as measured work. SQLite transaction counters cover named instrumented startup boundaries, not every driver read, pragma, or implicit transaction.
- **Validation projection is scoped indexing, not full indexing.** `RefreshValidationProjection` owns the normal index-lock lifecycle, validates one canonical vault-root authority, discovers only note dirtiness (or consumes strict exact typed note paths), publishes one metadata/link/fragment-target delta through `indexwriter.Writer`, drains that source barrier, then derives and drains ontology from the already-published source. A non-nil empty exact set is a true no-op. Live mode uses the shared DB; scratch mode owns a process-local temporary DB and cleanup. Ordinary live/scratch refresh marks metadata, links, fragment targets, and available ontology fresh while leaving code, code anchors, chunks, embeddings, and graph scores untouched. The post-apply held-lease adapter is the narrow exception: for committed code-anchor repairs or note-path ownership changes, it extracts anchor declarations from only the exact changed note snapshots and publishes an anchor-only batch through the queued note-work lane, then marks `code_anchors` fresh so prepared postchecks see the committed selector. Unrelated content repairs do not reparse pre-existing anchor frontmatter or claim that domain fresh. Code-anchor evidence combines the project-code anchor count/generation with a deterministic hash over note selector fields, globs, and ownership; same-count selector rewrites therefore invalidate freshness. That hash scans only note-anchor declaration tables, never the full code index. The adapter does not advance note-intel metadata or semantic rows, enumerate project code, or call an embedding provider. Untouched evidence carries persisted count/hash/generation; `unavailable` means no persisted prerequisite exists.
- **Semantic-query diagnostics use a request-scoped filtered collector.** `pkg/indexingperf/semantic_query.go` owns stable phase/operation descriptors for one-shot bootstrap, provider, indexed retrieval, shaping, and session work. Disabled instrumentation must remain a near-zero-cost no-op; enabled counters distinguish unavailable work from measured zero and must include bounded materialization reads rather than only discovery reads.
- **Validation projection is scoped indexing, not full indexing.** `RefreshValidationProjection` owns the normal index-lock lifecycle, validates one canonical vault-root authority, discovers only note dirtiness (or consumes strict exact typed note paths), publishes one metadata/link/Markdown-target delta through `indexwriter.Writer`, drains that source barrier, then derives and drains ontology from the already-published source. A non-nil empty exact set is a true no-op. Live mode uses the shared DB; scratch mode owns a process-local temporary DB and cleanup. Ordinary live/scratch refresh marks metadata, links, Markdown targets, and available ontology fresh while leaving code, code anchors, chunks, embeddings, and graph scores untouched. The post-apply held-lease adapter is the narrow exception: for committed code-anchor repairs or note-path ownership changes, it extracts anchor declarations from only the exact changed note snapshots and publishes an anchor-only batch through the queued note-work lane, then marks `code_anchors` fresh so prepared postchecks see the committed selector. Unrelated content repairs do not reparse pre-existing anchor frontmatter or claim that domain fresh. Code-anchor evidence combines the project-code anchor count/generation with a deterministic hash over note selector fields, globs, and ownership; same-count selector rewrites therefore invalidate freshness. That hash scans only note-anchor declaration tables, never the full code index. The adapter does not advance note-intel metadata or semantic rows, enumerate project code, or call an embedding provider. Untouched evidence carries persisted count/hash/generation; `unavailable` means no persisted prerequisite exists.
- **Validation ontology catalog writes preserve semantic prerequisites.** Validation projection uses `ReplaceOntologyNodeReadModelPreservingSemantic`: ontology catalog/field rows converge, but ontology-owned chunks, embeddings, and embedding sidecars survive full and incremental validation refreshes. Full indexing retains the ordinary cleanup path and owns semantic convergence.
- **Held-lock integration stays token-exact.** The lock-already-held core is package-private. `ValidationProjectionPostApplyRefresher` accepts EFF-0047's opaque `pkg/validate.IndexLockLease`, proves it belongs to the same canonical vault root, and enters that core without acquiring, releasing, or replacing the consumer-owned lease. Rename destinations join the changed set and rename sources join the deleted set before strict typed-path normalization. Changed note anchor declarations re-enter through `notemeta.NoteSourceSnapshot` plus `indexwriter.Writer`; deleted metadata paths retain the store's transactional cascade cleanup.
- **Exact affected paths are broader than note-source intake.** Validation projection retains every exact changed/deleted path in coverage and ontology dependency work, while the configured provider registry and existing ownership selector admit source reads. Exact `CONTEXT.md` retains the system-note include/exclude exemption and hard visibility boundaries used by note discovery. A changed path outside note ownership retires prior metadata through the same queued delta. Selected non-Markdown providers retain their metadata and fragment targets; only selected Markdown sources enter the anchor declaration adapter. An empty selected anchor set skips snapshot loading because the snapshot loader's empty input means all current note sources. Read and projection errors for selected sources remain failures.
- **Projection result owns one runtime lifetime.** Consumers run checks directly against `ValidationProjectionResult.Runtime`, then call the idempotent `Close`; they must not call `EnsureFreshRuntime` and trigger a second index pass. The post-apply adapter transfers that same runtime and its result owner through `validate.NewPostApplyRefreshResult`, so the repair engine closes it after its in-lease prepared postcheck. No lease type or release ownership lives here.
- **Ordinary validation establishes its journal barrier before projection mutation.** `validationproduct.RunWithProjection` preflights pending repair journals before calling `RefreshValidationProjection`, then installs `BeforeMutation` so the same check runs again while the canonical index lock is held and before any live or scratch projection store opens. Interrupted repair evidence yields blocked outcomes and a recovery command without projection mutation. Lease-held recovery/post-apply refresh remains the separate repair path.
- **Persisted prerequisites are evidence, not freshness claims.** Local code-backed checks inspect stored capability/row/version/scope/count/timestamp facts without walking roots or invoking providers. The stored timestamp does not prove live-worktree freshness; an unusable local snapshot names `rzm index`. Isolated scratch CI never consumes that live index, so unsupported code checks instead direct users to run the check locally or remove it from the configured CI suite.
- **The advertised code-index preparation command must satisfy its evidence contract.** A successful unified run persists the current indexer version and authoritative `LocalConfig.ScopeConfigHash` while preserving configured code enablement. Missing or stale scope evidence keeps code-backed validation blocked even when code rows exist.
- **Consumers do not invent time-based freshness.** Persisted timestamps are observability evidence, not proof that a live worktree is stale. Read-only startup context classifies freshness from durable schema, indexer/scope, and ontology materialization proofs and directs repair back to `rzm index`.

- **Ensure-link convergence uses the same projection writer.** `ApplyNodeLinkTargets` owns the canonical lock across source-only block-ID edits and exact metadata/ontology refresh. Its live store is opened before source mutation and retained by the held projection core. The explicit metadata indexer and expected schema are validated before editing; a postcommit refresh failure reports incomplete convergence and a repeated apply repairs the same exact paths. This scoped operation does not publish a complete read generation or refresh semantic/graph-score domains.

## Persistent diagnostic coverage

Every unique runtime lane admission owns a bounded `indexingperf` collector and a diagnostic operation independent of the submitting client's cancellation. Joiners emit a correlation event and reuse that operation. The terminal report follows actual job return and required drains, including queued cancellation, shutdown drops, preflight failure, priority yield, and explicit preemption. Queue wait, index-lock wait, and execution have separate measurements. Report publication is attempted before the terminal subscriber event, so a successful persistence attempt is readable when `rzm index` exits. Publication failure still delivers that terminal event. Explicit and boot indexes use report kind `index`; watcher and validation jobs use `indexing-job` and cannot replace `latest-index`.

In-process index attempts collect and publish without `--timings`. That flag controls rolling console output only. Rebuild attempts begin before runtime-stop coordination, so coordination and metadata-composition failures remain recorded. Reports use safe error categories rather than arbitrary provider response text. The same collector feeds console summaries and immutable report snapshots. `unified_core` includes setup and deferred cleanup; writer flush/close and streaming durability barriers expose their waits separately. Existing writer row, byte, queue, and transaction metrics remain the evidence for persisted throughput.

Watcher reports retain curated trigger counts for stale-hub reasons, event sources, directory installation, rename, cache-recrawl completion, selection reload, and pending reconciliation. Counts describe inputs to each attempt; retries can carry the same inputs into later reports. Drained, pending, deferred-ready, deferred, restored, and destination-path counts distinguish backlog from completed work. Sparse events report batch inputs, restoration, full discovery, ontology rebuild/degradation, and reconciliation acknowledgement. Health epochs remain available through the live API; they no longer append repeated full path lists to `live-epochs.jsonl`. No event is written for each ingested file.

Call-edge diagnostics distinguish full forced batches, incremental batches, and reverse-index backfill fallback. Anchor-scope diagnostics distinguish incremental IDs, global dependencies, dirty-ID overflow, and the live watcher's existing full recompute. These observations do not change fallback, throttling, acknowledgement, or semantic batching behavior.

Shared structural publication is measured in `indexcore`; writer admission, flush, committed rows, control barriers, and close are measured in `indexwriter`. Derived-ticket reports separate preparation, provider computation, durable publication, and exact acknowledgement. Obsolete tickets are skipped, and compute interruptions distinguish explicit indexing from external writer priority. Shared embedding-node physical batches have a bounded runtime-lifetime collector and a separate report after node shutdown; they are not attributed to an individual ticket. Active or crashed runtimes may lack a completed shared physical summary.

Coverage remains bounded: retained-prefix percentiles and interval unions have explicit dropped-detail counts. Reports measure instrumented spans, counters, and barriers, rather than every SQLite statement or filesystem call. A process crash can leave an admitted/started event without a terminal report. Deferred watcher inputs and advisory node-embedding debt remain visible as pending counts and can coexist with a successful lane outcome. Diagnostics failures are advisory and cannot fail indexing.

## Must-dos when changing this subsystem

- Route every new SQLite-backed write through `indexwriter.Writer`; never open a side write path to the same DB. Ordinary payloads add a `Submit*`, handler, and batch type. Ordering-sensitive control operations require a specific typed command, captured barrier, synchronous result, and tests proving prior writes drain first.
- Give ordinary write kinds a batch policy and flush it in both `flushAll` and `flushExpired`; respect the ontology-delta-before-node-read-model ordering. Do not disguise result-bearing ownership fences as idle-flushed batches.
- Attribute new work with `indexingperf.WithPhase`/`ctxWithPhaseOp`; add gauges/latencies for new queues.
- Acquire the index lock (`TryAcquireIndexLock`) for any new one-shot entry point that writes indexes; release via the returned func. Work that runs inside the vault runtime submits a `lane.Request` instead and never acquires the lock itself.
- When refreshing after repair under an existing lease, use the held-lock exact-path API and preserve the returned runtime until prepared postchecks finish. Calling the public lock-acquiring refresh from inside the lease can deadlock.
- Slot incremental/watcher behavior into the same core (`RunUnifiedCore` with dirty paths), not a parallel implementation; `rzm index` is authoritative truth, watcher is an optimization.
- Keep new init in MCP serve path async — nothing may block the stdio handshake (`cmd/serve.go`, AGENTS.md MCP responsiveness rule).
- Add tests beside the change (`pkg/app/indexwriter/write_queue_test.go`, `unified_test.go`, `lock_test.go` patterns); run `go test -race -tags=integration ./...` for pipeline changes.
- Update `CONTEXT.md` in the touched package and the hub/analysis notes when invariants move.

## Review checklist — problems to catch

- DB writes outside the writer lane: direct store calls (`Apply*`, `Upsert*`, `Replace*`) from worker goroutines instead of `q.Submit*`.
- Unbatched per-row queries or autocommit-per-row loops inside flush handlers; N+1 reads where in-memory same-run state already has the answer.
- New "extra pass" added after the pipeline instead of work integrated into an existing stage (look for second walks over all files/notes, fresh full-table scans post-drain).
- Lock not acquired for a new indexing entry point, release func dropped on error paths, or lock file deleted instead of `RequestPriority` for preemption.
- New barriers introduced casually (extra `FlushAndWait` mid-stream serializing overlap) or load-bearing barriers removed (final drain before call-graph/graph work).
- Ontology node read-model writes that can idle-flush or flush before queued deltas (FullRebuild truncate hazard).
- Unbounded channels/goroutine fanout; walk-ahead not backpressured on worker queue.
- Blocking the watcher or MCP handshake with synchronous index/DB/enumeration work.
- Validation/CI accidentally entering project indexing, walking code roots for prerequisite probing, claiming live freshness from persisted metadata, or scratch state escaping process cleanup.
- Post-apply refresh reacquiring a lock already represented by the repair lease, closing the returned runtime before postchecks, or routing postchecks through `EnsureFreshRuntime`.
- Ignoring dirty/incremental paths: full rebuild where scoped sync suffices; rereading SQLite for paths touched this run.
- Absolute or ad hoc `filepath.Abs/Rel` paths entering index rows (must use `pkg/paths` / `VaultPaths`).
- Misattributed or missing `indexingperf` labels; cumulative diagnostics trusted over wall time.
