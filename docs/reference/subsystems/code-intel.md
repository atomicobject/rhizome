# Code intelligence guidance

## Scope

Three directional layers, plus orchestration:

- **`pkg/anchors`** (package `codeanchor`) — **note→code**. Notes declare `code-anchors:` frontmatter targeting symbols/call-sites/decorators/paths; tree-sitter (Python/TS/C#) and go/ast indexers produce `FileSummary` symbols, calls, annotations. Entry point: `Service.NotesForFile(ctx, path)`. Note ingestion boundary: `ExtractAnchorDeclarations(ctx, NoteSource)` — narrow adapter seam only; canonical note facts stay in `notemeta`/orchestration.
- **`pkg/vault/coderefs`** — **code→note**. Scans comments/docstrings for wikilinks, markdown links, and `@mentions`; rewrites them on note rename/move. Entry points: `ScanFile`, `RewriteBatch`. Links share `obsidian.ScanCommentLinks` and precise component spans; canonical resolution uses `NotePathCache`. Mention rewrite boundaries remain stricter than scanning.
- **`pkg/vault/codepatterns`** — default code-file globs shared by coderef scan/rewrite. Deliberately broader than anchor indexing: web/template/style files carry coderefs but never structural anchors. Slices are copy-on-return; don't mutate process-global defaults.
- **`pkg/app/codeintel`** — indexing primitives extracted from `cmd/` (`ResolveRoot`, `IngestNotesWithMatcher`, `IndexRoot`, `ValidateNotes`). All persisted paths are vault-root-relative via `pkg/paths` strict conversion. Explicit code ingest checks content hashes before projection; note ingest retains its source/ownership and mtime/content-hash guards.

## Design constraints

- **Web graph freshness is a persisted revision.** `GraphWebFingerprint` reads the migrated graph-domain incarnation and revision in bounded time. Transactional triggers cover graph structure, endpoint labels/types, and scores, including entering/leaving graph-visible rows in mixed-purpose tables. External-target evidence remains outside the domain. Update triggers are column-scoped where a table mixes graph and indexing metadata: the `notes` trigger fires only for `path`/`title` (Intel v63), so mtime/hash/indexer bookkeeping writes leave the revision alone. Keep the trigger inventory aligned with actual graph reads (see the stores note for the migration rule), and preserve cross-handle invalidation and rollback behavior.

- **Language indexer contract** (`pkg/anchors/indexer.go`): implement `LanguageIndexer` (`IndexFile(content, paths.CodePathRef) (FileSummary, error)`, `Lang()`), optionally `ReverseIndexFallbackProvider` for def-delta rebuilds. Bump `IndexerVersion` when output format/behavior changes significantly — that's the `--rebuild` migration trigger.
- **Deferred rebuild language detection must cover every structural indexer extension.** Targeted same-run rebuilds derive language from the changed path before reading durable refs. Keep that extension map aligned with registered indexers, including PHP, or a full index can persist correct refs while omitting their edges until a later rebuild.
- **Anchor kinds** (`pkg/anchors/types.go`, `frontmatter.go`): `function` (symbol def + call sites), `baseClass`, `annotation` (decorator/attribute), `path`, `glob`. `ref:` shorthand prefixes: `symbol:`/`calls:`/`decorator:`/`glob:`/`dir:`. Per-language coverage varies: Go has struct/interface embedding for `baseClass:` but no annotations; Python has decorators; C# has attributes + syntax-local resolution (no Roslyn semantic model); TS has type annotations. Symbols must be fully qualified.
- **FQN production**: each indexer emits language-shaped FQNs — Go: module path + symbol (`example.com/polyglot/todo.PushUpdates`); Python/TS/C#: dotted module/namespace path (`module.path.Name`). Anchors match on these exact strings; changing FQN shape silently breaks every existing anchor.
- **PHP member identity survives the durable-ref seam.** PHP method and static-member targets use `Class::member`; namespace-level targets use `namespace\\symbol`. Schema 69 persists the typed member bit with the FQN through reverse-index rows, definition deltas, dedupe keys, reopen, and rebuild planning. `ReverseIndexVersion` v1.3.0 forces older materializations to rebuild.
- **Go package analysis honors the active build context.** `GOOS`/`GOARCH` filename constraints and source build tags are applied before `go/types`, including test files selected by the current with-tests variant. Excluded declarations cannot create relationships or duplicate active declarations. Invalid constraints make the package proof incomplete, and analyzer-version changes hide older proof until rebuild.
- **TypeScript/JavaScript source family**: structural indexing and coderef discovery cover `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, and `.cjs`. TypeScript grammar handles `.ts`/`.tsx`/`.mts`/`.cts`; JavaScript grammar handles `.js`/`.jsx`/`.mjs`/`.cjs`. Keep this family centralized rather than adding one-off extension lists.
- **TypeScript/JavaScript module resolution**: resolve repository-local literal specifiers only. NodeNext runtime suffixes probe source counterparts (`.js` → `.ts`/`.tsx`/`.js`, `.jsx` → `.tsx`/`.jsx`, `.mjs` → `.mts`/`.mjs`, `.cjs` → `.cts`/`.cjs`), then local package `exports`/`imports`, nearest `tsconfig.json` or `jsconfig.json` `baseUrl`/`paths`, and explicit barrel re-exports. Resolution is cached, package-manager neutral, root-confined, and ambiguity-preserving.
- **TypeScript/JavaScript relationship boundary**: static imports, side-effect imports, re-exports, literal `import()`/`require()`, import/require bindings, and statically enumerable nullish/logical/conditional callable branches may produce edges. Computed module sources, arbitrary external dependencies, runtime dispatch, unknown instance receivers, and whole-program type flow remain unresolved rather than receiving speculative local edges. See [[typescript-javascript-indexer-coverage]].
- **External target identity is separate from parser identity**: `intel_symbol_ref_targets` remains the normalized, parser-emitted target vocabulary. Canonical external endpoints live in a separate pathless catalog, and an N:1 mapping lets multiple raw spellings converge without creating one endpoint per use. Canonical identity is ecosystem + public module + symbol path + target kind; aliases and declared-version provenance are association evidence, not identity. See [[docs/specs/technical/external-code-reference-targets|SPEC-0081]].
- **External classification is sparse, derived, and local-first**: persist only qualifying import/runtime evidence on symbol-ref associations, plus a separate external-import evidence family rather than widening local `intel_import_refs`. Read/statistics paths derive `local_resolved`, `external_classified`, `runtime_global_builtin`, or `unknown`; a source-backed local resolution always wins, and unresolved workspace/path aliases or unknown receiver members remain unknown.
- **External public identity does not erase binding evidence**: default imports expose the canonical public symbol path `default` while retaining parser/raw binding identity and local aliases as association evidence. Python builtin classification is likewise evidence-bound: local parameters, assignments, imports, and other shadow forms suppress builtin promotion.
- **External reads share one snapshot**: classification, statistics, and dedicated reference projection derive local precedence plus external/runtime evidence from one consistent read snapshot. Do not compose a public result from independently timed store reads.
- **External endpoints are explicitly non-source-backed**: they have no source path or definition claim and must never enter code anchors, source chunks, FTS, embeddings, ontology nodes, general search, default graph projections, Explorer, snippets, or go-to-definition. Only dedicated external-reference and impact surfaces may project them.
- **Code folders are one union with an automatic default.** `obsidian.LoadCodeConfig` (`applyAutomaticCodeScope` in `pkg/vault/obsidian/code_config.go`) is the one place that turns `.rhizome/config.yml` into code folders. When code is on and no language block names folders, every language root is `.` and `Config.AutomaticScope` is set, so code added after setup indexes without rerunning init; a language block without folders also covers the project. When any block names folders, the union of folders limits code indexing and languages without a block stay out. Consumers that walk or watch folders use `Config.CodeRoots()` (deduplicated), never one walk per language, and each file's language comes from its extension (`codeanchor.LangForPath`). Under automatic scope, Python and PHP module naming use the indexers' default source folders (`src`, `lib`, and `app` for PHP), so FQNs do not change shape when roots are absent. `ScopeConfigHash` is computed from the authored config, so automatic scope does not churn it. Under automatic scope `NewCodeAnchorService` leaves out the indexers of languages in `code.disabledLanguages`, which is how a repository excludes a language; with named folders the list keeps its older meaning and only stops init prompts.
- **Never-prompt languages**: `Config.DisabledLanguages` (`pkg/anchors/config.go`, surfaced as `code.disabledLanguages` in `.rhizome/config.yml`) records language IDs (`python`, `go`, `ts`, `cs`) the user never wants init/index flows to prompt about. `rzm init` reruns (`codeDrift` in `pkg/app/cli/init/rerun.go`) must honor it.
- **Index pipeline integration**: live and queued code indexing share preparation and persistence. SQLite writes summaries/meta + refs + external evidence + intel + rationale in one transaction per publication; statement chunks share that transaction so a late failure or cancellation preserves prior artifacts and freshness for retry; when `ApplyCodePersistenceBatch` is available it owns summary/meta durability (don't pre-write or hot tables double-write). Full batch indexing persists anchors/FTS/defines eagerly but defers call/import/type/member edge resolution to the rebuild pass — no per-file resolver lookups on the hot ingest path. Live indexing retains eager resolved edges and old/new dirty-scope invalidation after success, while omitting unused definition-delta reads. Queued preparation retains early shared path hints, while live calls add them once through publication; the writer also supports hand-built work. Generic stores attempt every reverse-index family with joined errors and publish freshness after supported artifacts succeed, without a rollback guarantee. File context invalidation follows attempted publication, including generic partial-error returns, to retire old rows cached by concurrent readers. Cache misses carry a bounded global generation under the existing cache mutex; invalidation advances it even for an empty cache, and a read cannot cache its result after that generation changes. An in-flight read retains its observation, while later reads reload current rows. Doc links retain their separate publication seam. `IndexerVersion` v1.16.0 makes ordinary reindexing repair older live publications that advanced freshness despite later failures or omitted external evidence. Semantic submission stays batched off the file-worker path; code ingest never owns the async submitter drain.
- **Rationale FTS schema is initialization-owned.** Store initialization and migration/reset assembly establish the rationale FTS table, rowid map and index; schema validation checks the exact FTS5 definition, rowid-map columns and required index. A changed validation fingerprint forces older proofs through revalidation; writable opens retain existing derived-domain recovery, while read-only opens refuse unavailable current proofs. Search, replacement and deletion perform no permanent schema DDL. Missing schema after open remains an SQL error, not an operation-time repair. Atomic batch rollback preserves canonical rationale rows, FTS content and rowid mappings together.
- **JS/TS module metadata invalidation**: watcher events for JSON module metadata invalidate cached package/config and derived barrel-resolution state; the next TypeScript/JavaScript source index or explicit rebuild refreshes that state. Failed barrel lookups are not cached because a missing re-export target has no filesystem stamp that can make the negative entry self-invalidating. Metadata invalidation does not by itself reindex previously indexed callers or repair their persisted edges.
- **Canonical note input only**: production note ingestion receives `notemeta.NoteSourceSnapshot` through the narrow `NoteSource` port. Paths are vault-relative and hash/mtime come from the snapshot; do not recreate raw path/content adapters inside anchors.
- **Legacy discovery errors preserve indexed note inventory.** Encountered directory-walk failures propagate through `IngestNotesForVault` before stale cleanup. Code-index and code-anchor commands fail without success wording and can retry once permissions are restored. Legacy individual-file read/build tolerance and deliberate collection/ignore exclusions remain intact; this does not change durable schema or indexer versions.
- **Persisted coderefs have a bounded read seam.** Startup-context consumers use exact-file or directory-boundary-scoped `doc_links` queries with hard limits. Coderef discovery and publication remain indexing-owned; read consumers never rescan or repair. `IndexerVersion` v1.15.0 refreshes unchanged code sources for corrected canonical URL paths and comment examples; `rzm index --rebuild` regenerates derived links explicitly.
- **Existing vector tables are read-first for query consumers.** A read-only `pkg/anchors/sqlite` store probes the exact dimension-specific vec table and caches readiness without executing DDL. Only write-capable indexing/migration ownership may create a missing table; a query-only consumer returns `rzm index` remediation instead of attempting repair.
- **Embedding search is exact prefiltered vec0 KNN.** `SearchEmbeddings` authorizes eligible chunk row IDs through current embedding metadata matching the query dimension, applies existing owner/path/type filters before selection, pushes those IDs into vec0 with `chunk_id IN (...)`, and runs `embedding MATCH ? AND k = ?`. Retained vectors cannot make unembedded replacement chunks or old dimensions searchable; scalar fallback requires the same metadata eligibility. Equal-distance boundaries probe adaptively up to vec0's 4,096-row cap and results use score-desc/chunk-ID-asc order. Do not replace this with fixed global overfetch plus post-filtering; keep the scalar reference parity matrix when adding filters.
- **Changed chunk hashes retire current-vector evidence.** Chunk replacement removes embedding metadata and ontology sidecars before overwriting a changed hash, inside the same transaction. This prevents synthesized context changes from falsely treating old vectors as current after a provider failure. Equal hashes preserve evidence; retained vectors and hash-addressed caches remain reusable. Existing stranded metadata cannot reveal its original content hash and requires explicit `rzm index --rebuild` recovery.
- **Indexed note-prefix lookup is bounded.** Semantic directory seed callers use `NotePathsByPathPrefix` with normalized exact/boundary matching, deterministic path order, and an explicit hard limit; never substitute an unbounded graph-path enumeration for this request path.
- **Coderef pitfalls are by design**: `mentionRegex` (`pkg/vault/coderefs/scanner.go`) rejects emails by requiring a non-word char before `@`; wikilink/mention resolution requires a real vault note so plain strings/unknown names don't become refs. Parsed links own their labels and destinations, including embedded `@` data. Each rename mapping collects link and standalone mention edits from original spans and applies them once; old-path alternatives belong to that same mapping and shared mention spans count once. Separate mappings remain sequential. Reuse a comment block's structured scan across mappings while its text is unchanged; an edit invalidates the scan before the next mapping. Apply disjoint edits in one literal span pass. Comment routing: extension registry maps formats to comment families; web/template files stay coderef-only.

- **Coderef renames must rescan as the canonical destination.** Preserve valid mention/wiki spelling where possible; an unrepresentable wiki path uses a normal Markdown link with a full URL-encoded destination, including when the original was a wiki embed. Authored Markdown images remain excluded from rewrites. Link labels, fragments, and literal dollars survive span edits. Markdown paths decode once for matching/resolution, and emitted paths encode each folder segment; literal `%20` filenames require `%2520`. Explicit wiki and Markdown links inside extracted source-comment code examples are scanned and rewritten, while ordinary note scanning retains protected spans. Sequential mappings and full/extensionless/basename rules stay intact; Markdown gets no new basename inference.

- **Explicit code freshness is content-proven.** Full and code-only indexing read every selected code source and use the existing content-hash/indexer-version/trusted-status guard before parsing. Preserved, same-second and backdated timestamps cannot suppress changed bytes. Unchanged code causes no timestamp-touch writes; configured scope and result-count meanings remain unchanged. Watchers already read their event-selected files before hash checking.

## Must-dos when changing this subsystem

- **New language support follows the polyglot fixture pattern** (`testdata/integration/python-app/vault/`): one vault, multiple languages — add a language subtree (e.g. `vault/go/...`), never a separate fixture. Coderefs: representative files exercising comment/doc extraction + wikilinks + `@mentions` + pitfalls (emails, strings). Codeanchors: dedicated note under `vault/notes/code-anchors/` (see `Go anchor - Task Flow.md`) plus code triggering each supported anchor kind — minimum symbol + calls; annotation/baseClass/dir where applicable. Integration tests live per language under `tests/integration/<lang>/` (build tag `integration`) and must assert anchor matches at **both definition site and call sites** (pattern: `tests/integration/go/file_context_test.go`).
- Run `go test -tags=integration ./...` for any indexer/scanner change; unit tests sit beside implementations (`indexer_*_test.go`, `scanner_test.go`).
- **Rebuild when indexer behavior changes**: bump `IndexerVersion` (or `NoteIndexerVersion`/`ReverseIndexVersion`) and validate against a real repo with `rzm index --rebuild`. Stale-looking matches almost always mean a missed rebuild.
- Debug with `rzm code anchors explain <file>` (why anchors/notes match or don't) and `rzm code symbols <file>` (what FQNs the indexer actually produced) before touching matcher code.
- New config fields: update `Config` in `pkg/anchors/config.go` and init detection and defaults in `pkg/app/cli/init/detect.go` and `configure_code.go` together.

## Review checklist — problems to catch

- **False-positive coderefs**: new comment-family or regex changes that match emails (`user@domain`), `@` inside string literals, or unresolved names; scanner widened without keeping rewriter stricter.
- **Anchor kind not covered by fixture**: indexer claims a kind (decorator, baseClass, embedding) with no fixture code triggering it and no integration assertion on def-site + call-site.
- **FQN format drift**: indexer changes FQN shape (package separators, receiver naming, namespace nesting) without an `IndexerVersion` bump — silently orphans existing anchors.
- **Missing `--rebuild` migration story**: behavior change shipped without version bump; users see stale matches until manual rebuild.
- **JS/TS registry drift**: one of `.mts`, `.cts`, `.mjs`, or `.cjs` works in parser dispatch but is absent from discovery, watching, coderefs, code patterns, or CLI/report classification.
- **Speculative JS/TS resolution**: computed module sources, ambiguous export maps, root-escaping targets, or unknown receivers receive a convenient local edge instead of remaining unresolved.
- **Per-file scans bypassing batch/pipeline**: new code doing synchronous per-file store lookups or semantic submission on the hot ingest path; pre-writing summaries/metas when `ApplyCodePersistenceBatch` owns them; moving `CallFilesByCallees` back under the write lock.
- **Raw/external identity collapse**: treating `intel_symbol_ref_targets` as canonical package/runtime endpoints, including version evidence in canonical handles, or creating a catalog row per use instead of preserving the N:1 mapping.
- **External evidence promotion**: storing a target-wide classification inferred from one strong use, widening local `intel_import_refs` to carry external imports, or classifying before local resolution has had precedence.
- **Ambient external-node leakage**: pathless external catalog rows appearing in ontology/search/anchor/chunk/embedding/default graph/Explorer/definition surfaces rather than only explicit external-reference or impact queries.
- **External writes bypassing the writer lane**: external catalog, mapping, or sparse-evidence persistence that writes outside the unified queued SQLite writer and its batched store transaction.
- **Path discipline**: ad hoc `filepath.Abs/Rel` instead of `pkg/paths` strict-rel conversion; absolute paths leaking into sqlite.
- KNN filter drift: a new owner/path/type predicate exists only in the scalar query, is applied after KNN, or omits adversarial/tie-boundary parity coverage.
- **Note-metadata creep**: new general note metadata ownership added inside `ExtractAnchorDeclarations` instead of consuming `notemeta`.
