# Ontology subsystem guidance

## Scope

The ontology core owns Rhizome's typed note contract: compile GraphQL SDL from `.rhizome/ontology/*.graphql` into a typed-note model, project provider-current authored roots into source-preserving `NodeRef` snapshots, add structural nodes only for Markdown, build the indexed read model (`ontology_nodes` / `ontology_edges` / `ontology_node_field_values`), and replay supported edits as minimal span patches. Entry points: `LoadSchema` (`pkg/ontology/schema.go`), `ProjectNode` / `ProjectNodeFromSnapshot` / `ProjectRootDocumentSnapshot` (`pkg/ontology/projection.go`, `root_projection.go`), `BuildIndexFromNoteSources` / `SyncPaths` (`pkg/ontology/index.go`, `sync.go`), `BuildIntelOntologyNodes` (`pkg/ontology/node_catalog.go`), `NewEditSession` (`pkg/ontology/edit_session.go`), `BuildNodeWorkspace` (`pkg/ontology/node_workspace.go`), `idalloc.Allocate` (`pkg/ontology/idalloc/allocator.go`), `guide.RenderMarkdown` (`pkg/ontology/guide/render.go`).

**Boundary**: the GraphQL query layer (`pkg/ontology/query`, `pushdown`, `queryrecipe`) and the batched read seam (`pkg/ontology/noderead`, `readmodel`) are covered by sibling subsystem notes — this note ends where indexed rows are handed to those consumers.

## Design constraints

- **Presentation and workspace membership are schema declarations.** Type-level `@display(group:, parent:)` organizes navigation. Field-level `@display(role:, importance:, hover:)` controls compact presentation and inherits through implemented interfaces. Field capabilities expose effective importance with NORMAL as the zero-value behavior; `hover: false` applies only to hover previews. These hints do not change membership, queries, or counts. `@workspaceMember` is valid only on explicit concrete-type link fields and identifies owner-selected workspace members; interfaces cannot declare it because navigation resolves the concrete owner's schema. Directory proximity and type presentation never establish instance membership.

- **Section summaries retain structural identity.** A singular heading-backed `@contains` field may declare `@display(role: SUMMARY)`, including importance and hover hints. Typed queries keep the section selection (`summary { content }`); materialization version 14 additionally stores whitespace-normalized body text for compact indexed reads. Section bindings retain their canonical refs and source spans. Missing nullable sections remain retrievable. Native tables/cards expose display text without claiming scalar editing or filtering; edit the section in its workspace.

- **A parent role forms a tree.** `@display(role: PARENT)` is valid on one single-valued `@link` field per file-backed note type, and the link must target the declaring type or an interface it implements. Every type the target admits must be a note type, because the tree and the `parent_cycle` walk cover note records only; a section or embedded declarer, or a target interface with a section or embedded implementor, is a compile error. An interface may declare the role under the same rule, and implementors inherit it like other field roles; any other placement is a schema compile error. `ParentField` reads it. The ontology validation check reports each repeating parent chain once as `parent_cycle` ([[group-views-and-view-platform|SPEC-0111]]).
- **Type documentation reports effective presentation.** `SchemaDocs` reports each enum value's authored `@view` label and order, its tone and collapsed flag when authored or defaulted from a declared stage, and its declared or inferred `stage` with `stageDeclared`. Rank-fallback tones are omitted, so callers can tell stated lifecycle metadata from derived tones ([[group-views-and-view-platform|SPEC-0111]], [[type-collection-views|SPEC-0112]]). It also lists each field's `@requiresWhen` conditions as `requiredWhen` and the type's `summaryField` and `parentField`. `display.role` reports the effective role, so the conventional field named `summary` reports `SUMMARY` unless another field claims that role.
- **View applicability is separate from ontology membership.** `viewconfig.DisplayGroups` owns effective navigation-group discovery using `@display(group:, parent:)`. `type`/`interface` mounts select one collection target or, with `"*"`, every type or every interface (a wildcard never replaces a generated view, and a native view on one draws a `generic_native_mount` warning), `group` selects a named group or `"*"`, and `node` selects individual nodes of a note or embedded-node type (never a section type). `workspace` selects All notes with no subject fields. `mount.group` applies only to group and standalone mounts; type, interface, and node mounts ignore it with a warning, while workspace rejects it. `viewconfig.NavigationMembers` is shared with the ontology summary so group discovery matches the Notes rail. Groups never become implicit query sources. The view catalog resolves compatible choices and exact-before-generic configured defaults, then for workspace the bundled Briefing default and for groups the bundled default chosen by the group's shape ([[group-views-and-view-platform|SPEC-0111]]; `viewconfig.DisplayTree` supplies roots and nesting); types and interfaces offer the bundled Briefing instead of Overview ([[type-collection-views|SPEC-0112]]); authored defaults preserve usable built-in alternatives, and conflicting defaults are a `duplicate_mount_default` warning that keeps every conflicting view usable. A native `type`/`interface` mount with `replaceGenerated: true` takes the generated view's standard Table/Cards/Board slot and default role; elsewhere the field is ignored with a warning, and duplicate replacers warn (`duplicate_replace_generated`) with the first by order, then ID, replacing. Choices beyond the subject's standard presentations carry `custom: true`; for a workspace, the bundled Briefing then Overview are standard presentations with no built-in Overview; for a display group, the bundled group views are standard presentations and the bundled Overview replaces the built-in choice, and for a type or interface, the bundled Briefing is. Arbitrary `configuration` belongs to the definition, while canonical invocation context belongs to the host. [[unified-view-contract|SPEC-0110]] owns that shared boundary.

- **Link-resolution changes invalidate derived ontology state.** Materialization version 8 rebuilds older projections so exact non-Markdown metadata-link targets appear in full and incremental reads. Version 13 repairs projections whose dependency obligations were lost inside metadata-expanded candidate sets, including stale alias resolution and target-type findings. Ordinary freshness refresh triggers this one-time rebuild even when source/schema hashes and completeness witnesses are current. Source metadata remains authoritative; changing resolution without advancing materialization can leave stale edges after upgrade.

- **Compact authoring discovery is a projection.** `reference.Compact` requires one public type and preserves authored bindings, required fields/sections, identifier formats, relationship targets, enum policies and behavioral annotations. It removes expanded prose/UI metadata and points to full guidance. It must not mutate the compiled schema or claim executable query requirements.

- **Schema is the single source of truth for typed contracts.** SDL compiles into the full typed-note model: types, directives (`@node`/`@link`/`@neighbors`/`@contains`/`@identifier`/`@retrieval`/`@traversal`), docstrings, and identifier formats. Nothing downstream may hardcode type names, field shapes, or id formats that the schema already declares (`schema.go`).
- **Scalar field assessment is pure after extraction.** `AssessScalarFieldValues` owns requiredness, singular/list shape, enum/type validation, and derivable-identifier authored-missing exemptions. Indexing extracts source values and presence; staged query selections pass their already-loaded current values to the same rule. It performs no projection or store/source I/O and does not reuse predicate coercion or stale persisted assessment for staged values.
- **Markdown is the source of truth; SQLite rows and primary semantic chunks are read models** that must converge back to the current schema and note fingerprints (`pkg/ontology/doc.go`). Never treat indexed rows as authoritative over file content.
- **Projection freshness includes the materializer algorithm.** `OntologyMaterializationVersion` is persisted with `ontology_schema_state`; an older version forces one full ontology rebuild even when source and schema hashes are unchanged. A newer persisted version fails closed with `ErrFutureOntologyMaterialization` so an older binary cannot downgrade derived state. Increment the constant whenever the same inputs can produce different assessments or read-model rows. v4 materializes `has_issues`/`type_ambiguous` on `ontology_note_assessments` from `FlagsForAssessment`; v5 derives unanchored list-item structural identity from normalized owned content rather than sibling position; v6 persists canonical catalog node counts and identity digests in assessment JSON; v7 binds those witnesses to the projected source content hash. Whole-vault inventory reads trust materialized columns only while the persisted state is ready at the current version (a migrated index that has not rebuilt yet still decodes `assessment_json`), and every assessment row is written through `setAssessmentRow` so the columns and the JSON cannot disagree.
- **Selector recovery is explicit identifier-repair authority.** Assessments preserve selector candidates even when the preferred identifier fails the active grammar, but ordinary projection and `NewEditSession` remain identifier-gated. Only a reviewed whole-pool identifier repair may use `ProjectDocumentNodesFromSnapshotAsSelectorType`, `ProjectNodeFromSnapshotWithSelectorRecovery`, or `NewIdentifierRepairEditSession`; ambiguous candidate sets fail closed.
- **Catalog, structural-edge, and embedded-validation traversal reuse one resolver per operation.** Keep global-source enumeration and child projection inside that resolver. Preserve the supplied catalog root, sorted field traversal, fallback eligibility, semantic parents, and derived-ID allocation. Do not widen traversal to the full source-edit inventory or share a resolver across operations. Per-document derived lookups that a traversal needs for every node (line-start offsets via `lineIndex`, sibling ordinals for structural fingerprints) are built once per traversal or memoized on that resolver, never recomputed per node.
- **Projection is deterministic and source-preserving.** `NodeProjection` carries byte ranges (`ByteRange`) for every field, collection, and body block; edits patch targeted spans, never re-render whole notes (`projection.go`, CONTEXT.md).
- **Unanchored list-item identity follows owned content.** Structural fingerprints include the semantic parent, source shape, markers, and whitespace-normalized authored content owned by the item, excluding child spans. Edits elsewhere in the note do not move the identity; changing the item's text may. Identical unanchored siblings are ambiguous and resolution fails closed instead of selecting by byte offset. Durable links use block IDs.
- **Complete source-edit projection is conservative.** `ProjectDocumentNodesFromSnapshot` returns the note root plus every structural/list/checkbox/source node once in deterministic byte order. `FieldBinding.ValueRangesExact` is the only safe source-edit claim: values and ranges must map 1:1 to identical authored bytes; quoted, escaped, folded, derived, or otherwise approximate values remain readable but are not auto-patchable.
- **Full and incremental builds share canonical source projection.** Production loaders use the injected `notemeta.Indexer` to require provider-current `NoteSourceSnapshot` values. `BuildRootDocumentSnapshot` seals common root identity, source, diagnostics, metadata, and search evidence; only a Markdown source receives a `DocumentSnapshot` structural state from the genuine Markdown parser. Store metadata never substitutes for authored content, and root-only providers never receive fabricated Markdown sections.
- **Node-link reads preserve cancellation.** `NodeLinkService` returns source-reader and snapshot cancellation/deadline errors as operation errors, including a reader child deadline with a healthy caller context. Ordinary source/projection failures remain per-ref diagnostics.
- **NOTE source locators use the bare note path.** Structural fingerprints and catalog node IDs remain canonical identity metadata; they do not become fragment selectors for document roots. Section and embedded locators retain their precise target identity.
- **`NodeRef` is canonical identity** for note roots, structural sections, and embedded nodes. Author-facing locators (`note#Heading`, `note#^block-id`, `nodeId`) are inputs that must be canonicalized; do not collapse a section/embedded ref back to a plain note path after resolution ([[Go anchor - Ontology subsystem]]).
- **Catalog completeness comes from canonical projection output.** Every assessment persists `sourceContentHash`, `catalogNodeCount` and `catalogNodeDigest`, including explicit zero and the empty digest for a projection that emits no nodes. The stable digest covers node IDs, kinds, types, parents, locators, and structural fingerprints, independent of row order. Full and incremental builders count the emitted catalog, including fallback roots for blank notes. Readiness requires a current assessment, matching source path, nonnegative count, matching current catalog count and digest, plus existing field checks. Missing evidence forces repair; stored emptiness alone never proves completeness. Explicit incremental sync also checks stored catalog witnesses and timestamps, promoting incomplete untouched paths for repair.
- **Sync owns the indexed rows and writes through one durable lane.** The assessment/edge delta carries its `ontology_nodes` catalog in `OntologyDelta.ReadModels` through `deltaWriteQueue`, and the store publishes both in one transaction so producers parallelize without stepping on each other (SPEC-0040 "Replacement Boundary", `sync.go`). Incremental sync promotes current paths with missing, stale, or corrupt assessment/state rows into its forced recompute set before loading projection inputs; partial read models therefore self-heal without widening every edit to a full rebuild. Field-value rows are replaced atomically with catalog rows for touched paths; don't write them through a side door.
- **Dependency obligations are independent of load candidates.** Metadata may expand changed paths to unchanged sources after alias/path topology changes. Graph/relation endpoints and typed-link dependency sources remain forced recomputation paths even when present in that candidate set: a source fingerprint cannot witness its target's current alias or type. Unchanged direct sources with no dependency obligation still skip by fingerprint, and deleted paths stay excluded from load work. Assessments, relation edges, field targets, global findings, and published readiness must converge with a fresh build.
- **Published-source sync does not rediscover metadata.** `SyncPublishedPaths` is for coordinators that already published and acknowledged the note-metadata delta. It trusts that durable source barrier, including for an empty dirty set, while retaining schema-change/full-ontology convergence; it does not invoke metadata `Ensure` or republish metadata. General callers use `SyncPaths`, which still owns metadata freshness discovery. Both require explicit `notemeta.Indexer` composition; ontology never selects a provider.
- **Ontology work requires projectable metadata.** `ProjectableMetadataPaths` selects current rows only when their registered format has an executable projector. Use it for ontology materialization checks and all ontology body-embedding rebuild or follow-up work. Descriptor-only HTML can keep durable source identity, but it must not enter the Markdown projector, ontology read model, or ontology semantic work.
- **Type membership comes from selectors, explicit default, not frontmatter trust.** `type:` is an author hint; actual matching uses `@node(paths:/matches:)`. A single concrete file-backed type may declare `@node(default: true)` with no selectors and resolves only otherwise-untyped notes after selector/frontmatter resolution fails. Ambiguity resolves only via strict specificity dominance (`type_specificity.go: mostSpecificCandidate`); ties stay ambiguous rather than picking arbitrarily. Type compatibility goes through `typeMatchesOrImplements` (`type_match.go`), which understands interfaces and the `Note`/`Section` roots.
- **`interface Note` is authorable and universal for file-backed notes.** Shared general note fields belong on `interface Note` and must be nullable. The compiler injects those fields into every file-backed note type, and the GraphQL query layer exposes them through `NoteNode` for typed and otherwise-untyped note reads. Concrete `type Note` stays reserved; `Note` itself has no `@node` selector semantics. Domain-specific interfaces remain explicit opt-in.
- **Section admission uses the complete SDL ancestry.** Type roles, embedded prerequisites, file-backed prohibitions, synthetic interface fields, and relation-target checks share one cycle-safe classifier over the complete parsed schema, never the partially compiled runtime model. Renaming or reordering declarations cannot admit a Section-derived `@link` or `@neighbors` target. `@contains` still accepts concrete Section-derived types and the built-in `Section`; `@link` retains its universal `Note` exception, and `@reverse` may still name embedded source types.
- **Identifier strategy and rendered namespace live in schema; allocation orchestration lives in idalloc.** `@identifier(preferred: true, strategy:, prefix:, pad:, separator:)` selects the sole compiled strategy contract through `IdentifierFormat.StrategyContract`. That pure contract owns request validation, allocation, parse/format, reservation-family, and replacement semantics while sequential `Format`/`Parse` remain compatibility wrappers. `SEQUENTIAL` retains numeric `pad`; `DATETIME` owns calendar-valid local-minute syntax and canonical `-N` collision families while rejecting explicit `pad`. Types sharing `<prefix><separator>` must compile to one compatible strategy/format. `idalloc.Request` carries sequential count or ordered prospective paths; shared orchestration resolves types and pools frozen reservation inventory by rendered namespace before delegating to the contract. File-backed roots retain raw preferred-source and frontmatter alias inventory. Nonderived embedded owners enter the same pool through existing canonical node and field APIs, matching their own declared field names and DATETIME alias fields. Reservation dedupe and owner counts retain full node identity; diagnostic owners use canonical source locators while root owners remain bare paths. Derived fields do not allocate independently, and inventory failures propagate rather than returning an apparently free value.
- **Fallback types are internal evidence, not authored semantics.** `_FallbackNote`/`_FallbackSection` (`fallback_projection.go`) give unresolved content node identity for search/catalog; public type reads must respect `OntologyTypeVisibility` boundaries. Authored fallback behavior uses a concrete `@node(default: true)` type instead.
- **Structural (`@link`) and ambient (`@neighbors`) relations are distinct signals** — never merged in read models. An opt-in `@reverse(field: "sourceField")` list reads inbound structural edges with that authored source field name and requires no reciprocal field; its source may be a file-backed note or an embedded node, and embedded source identity stays distinct even when several live in one note. `@link(inverse:)` still validates reciprocal authored links. Reverse fields are computed and create no indexed edges. `@traversal` overrides compile into `TypePolicy` (`policy.go`); intent-specific overrides win over the empty-intent fallback.
- **Edit replay rebases through unrelated drift but must conflict** on missing nodes, collection drift, duplicate-heading ambiguity, same-parent reorder drift, and span ownership violations (`edit_session.go` `ConflictKind*`, SPEC-0046). `PreviewWithRefLineage` may recover a changed field-edit identity only for a ref resolved against the same locked session preview and one uniquely surviving staged origin. Deletion, replacement, and ambiguous structural identity invalidate that authority rather than transferring it to later content. A note root is addressed by its path: replay never compares a note root's structure fingerprint, which hashes section byte offsets and moves with any earlier staged edit to the same note (`validateResolvedProjectionRef`).
- **Section insertion is schema-ordered and parent-aware.** `EditSession.AddSectionField` resolves the exact structural parent, derives sibling order from the compiled schema, and inserts before the next ordered sibling or at the owning section boundary. Repair builders must not append headings at EOF or flatten nested fields.
- **List replay preserves authored YAML style.** `EditSession.SetScalarListField` validates a declared scalar-list target, while `SetRawFrontmatterList` is the narrow adapter seam for sealed undeclared alias fields. Both replace only the owned frontmatter value and preserve flow-vs-block sequence style; they never authorize caller-supplied raw ranges.
- **Identifier field rewrites preserve logical identity and physical alias authority.** `IdentifierRewrite.AliasesField` owns the replacement mirror; `AdditionalAliasesFields` owns only retiring-value removals. The planner removes matching values from every authorized collection and emits at most one preferred replacement and mirror append per canonical transition. Duplicate logical rewrites still fail closed, and the validate-owned discovery seals the normalized complete field authority separately from the resulting edits.
- **Edit publication shares the vault writer boundary.** Browser edit commits recover interrupted edit journals before reading mutation inputs, then hold `.rhizome/index.lock` plus sorted canonical path leases through final fingerprint checks and publication. The journal binds note replacements and the durable request receipt into one outcome, so a lost HTTP response cannot replay an already-published edit. Receipts retain only compact replay metadata; never persist source bases, workspaces, diffs, or updated-content previews in them.
- **Ordinary edits respect pending native namespaces.** After recognizing or acquiring the canonical global writer lease, ontology checks the validate-owned read-only namespace admission envelope before per-note locks, edit recovery, or publication. Prepared, malformed, unsupported and unsettled native evidence blocks direct edit sessions, heading edits and held-lease node-link callers. Native application asks ontology for its own pending-content-journal check under the borrowed lease, without taking another lease.
- **Recovery is a startup barrier.** `pkg/app/cli/serve` completes journal recovery after resolving the vault and before the Cobra adapter constructs its live runtime. Direct web-server construction runs the same recovery unless the caller supplies explicit evidence that the barrier already completed.
- **Committed edit journals authorize cleanup only.** Ontology edit recovery preserves later note bytes, modes, replacements, and deletion once the journal is durably committed. Before deleting any evidence, it verifies canonical confined paths, direct parents, nonoverlapping artifact names, and surviving regular-file content witnesses. Missing committed source directories make their original artifact paths absent; recovery never follows moved artifacts or replaced parent aliases. Recorded completion receipts must remain present and unchanged and are retained. Prepared journals still require old/new source witnesses and verified rollback backups; complete publication is durably marked committed before artifact cleanup. Cleanup removes the journal last and retries tolerate already-removed artifacts. Repair journals retain their separate refresh and postcheck obligations.
- **Save readiness is published after read refresh.** A warning-free browser save emits `node.changed` only after its prepared projection, note cache, and touched workspaces are ready. Its payload carries the exact repair refresh `paths` and fresh `domains`; semantic completion remains `index.changed`. A committed save also hints its touched paths to the watcher so cache refresh cannot consume its background semantic work. Receipt replay does not republish readiness.
- **Committed field references retain verified lineage.** `PreviewCurrentWithRefLineage` captures original-to-preview refs during the existing current-source commit replay. Browser saves publish that mapping after the exact source plan commits; compact receipts preserve it for retries. Refresh warnings suppress readiness events, but do not invalidate references to committed bytes. Clients may use exact strong-ref matches scoped to the retained read snapshot that produced an edit, or to queued edits captured before that commit, while retaining expected-field witnesses. Canonical adoption retires reader mappings; clients must not translate fresh references using workspace-wide alias history. Missing or ambiguous lineage never authorizes guessing an item from its byte offset.
- **Relations are checked at replay time.** Stage-time canonicalization gives early feedback, while restored preview and commit revalidate changed assignments against the final overlay plus current external targets. A saved operation cannot retain write authority after its target disappears, becomes ambiguous, or changes to an incompatible type.
- **Typed field replay preserves authored meaning.** Expected, current, and proposed field values carry `unset`, `scalar`, or `list` identity. Frontmatter writes patch only the owned value span, encode YAML safely, and fail closed when the existing source shape cannot be preserved.
- **Enum value `@view` is presentation and lifecycle metadata, validated at compile time.** `@view(label, order, collapsed, tone, stage)` on an enum value feeds configured-view grouping, board columns, and status marks through the compiled model only. `tone` accepts exactly `neutral`, `info`, `progress`, `success`, `warning`, `risk`, or `muted`; `stage` accepts exactly `open`, `active`, `done`, or `dropped`; any other value is a fatal schema error. An enum declares stages on every value or none, and a partial enum fails compilation naming the missing values. `EnumType.Tones()` resolves authored tone, else the declared stage's default (`open` neutral, `active` progress, `done` success, `dropped` muted), else the rank fallback; `CollapsedDefaults()` resolves authored `collapsed`, else declared stage `dropped`. `Stages()` returns declared stages or, for enums without them, stages inferred from authored tone (`progress` active, `success` done, `muted` dropped, other tones open) and untoned `collapsed: true` (dropped), and nil when no value authors tone or `collapsed`; inferred stages never change tone or collapse. Behavior reads stages, never tone ([[type-collection-views|SPEC-0112]]). Because `@view` never changes what an author writes in a note, the note-authoring guide does not render its arguments; a directive that changes authored content still must render there.
- **Type profiles derive from the compiled schema alone.** `DeriveTypeProfile` (`type_profile.go`) picks lifecycle, ordered, category, summary, primary date, people, key text, relation, reverse, and gap fields and the shape for a type or interface from directives and stages, never field names (except the conventional `summary`). Callers pass the core identity type. `SchemaDocs` fills `TypeDoc.Profile` for every type and interface with `identity.CurrentUserType` (a leaf package of constants and per-vault user state), so web, CLI, agent, and reference renderings all report the same profile. An interface field is required for gap purposes when every implementing type requires it or makes it conditionally required.
- **Primary semantic chunks stay source-owned.** Ontology projection supplies canonical node identity, selected scalar/enum fields, and bounded ancestor context to `node_body` synthesis; search never interprets SDL or creates a parallel generated source. `ProjectNoteSourceSnapshot` shares structural indexing source assembly with semantic consumers, keeping syntax and capability selection inside ontology.

## Must-dos when changing this subsystem

- New directive or schema field: compile + validate it in `schema.go` (with docstring capture), thread it through projection/catalog only via the compiled model, and update `guide/render.go` so the authoring guide renders it.
- New projected field/collection shape: emit byte ranges, prove determinism with a derive test (`projection_derive_test.go` pattern), and confirm `node_catalog.go` rows round-trip it.
- Touching sync: keep all row writes on the `deltaWriteQueue` lane; preserve atomic replace-by-touched-paths semantics; update `SyncResult` counts if convergence behavior changes (`sync_queue_test.go`).
- Touching sections: change `sectionparse/sections.go` (span parser: fence exclusion, block-ID capture incl. malformed IDs) and keep `sections.go` a thin converter.
- Identifier changes: keep each `StrategyContract` parse/format/replacement behavior symmetric, preserve the sequential compatibility wrappers (pad is a minimum, not a cap), reject incompatible rendered namespaces, and verify `idalloc` strategy dispatch plus shared-pool tests (`identifier_format_test.go`, `idalloc/allocator_test.go`).
- Run `go test ./pkg/ontology/...` plus `go test -tags=integration ./...` when sync/catalog row shapes change.
- Update `pkg/ontology/CONTEXT.md` and the relevant `docs/code-anchors/Go anchor - Ontology *.md` note when entry points or invariants move.

## Review checklist — problems to catch

- **Projection drift**: catalog/field-value rows built from anything other than `NodeProjection.Fields`, or non-deterministic projection output (map iteration order, time-dependent IDs outside the `now` parameter).
- **Approximate edit spans**: treating a readable projected value as patchable when `ValueRangesExact` is false, or omitting structural/source nodes from a complete discovery pass.
- **Hand-rolled frontmatter parsing**: code reading `type:`/field values directly from YAML instead of going through the compiled schema + projection — bypasses property-case rules, field sources, and span tracking.
- **Type matching ambiguity**: direct string comparison of type names instead of `typeMatchesOrImplements`; specificity logic that "picks a winner" on non-dominating clause sets.
- **Id allocation outside idalloc**: any max-id scan, regex over note titles, or skill-prose id math; allocation that scans one type when siblings share the prefix.
- **Edit-session/workspace invariant breaks**: replay that silently rebases through collection drift or duplicate headings; whole-note re-render instead of span patch; workspace views that collapse embedded/section `NodeRef`s to note paths.
- **Sync lane bypass**: direct SQLite writes to `ontology_nodes`/`ontology_edges`/`ontology_node_field_values` outside `SyncPaths` + queue; partial replaces that strand stale rows for touched paths.
- **Retrieval-context bloat**: unbounded ancestry/fields, relation/body inclusion in primary chunks, or runtime SDL interpretation in search.
- **Fallback leakage**: `_Fallback*` types appearing in public type lists or authored-schema surfaces.
- **Structural/ambient merge**: ambient backlink evidence written into `ontology_edges` or surfaced as validated relations.
