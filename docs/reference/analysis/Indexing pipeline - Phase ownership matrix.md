# Indexing pipeline - Phase ownership matrix

## Summary

`rzm index` is owned as a staged pipeline, not a bag of background jobs. `pkg/app/indexing.RunUnifiedCore` owns the batch sequence; `pkg/app/indexingpipe` owns bounded file discovery; `pkg/app/indexing.write_queue` owns the single durable writer lane; `pkg/app/semanticruntime` owns compatible provider lanes; `pkg/search/semantic` owns source-owned primary chunks; `pkg/anchors/sqlite` and the embedding stores own SQLite durability.

Use this matrix when adding, moving, or tuning an indexing phase. It is the ownership map, not the narrative walkthrough: use [[Indexing pipeline - rzm index orchestration]] for ordering detail, [[Embeddings - indexing pipeline]] for chunk-family semantics, [[primary-semantic-chunks-and-noderef-search]] for primary chunk invalidation, and [[Index lock and background coordination runbook]] for contention behavior. The governing constraints are [[indexing-workflow#^SPEC-0036-US1-AC1]], [[indexing-workflow#^SPEC-0036-US1-AC3]], [[indexing-pipeline-architecture#^SPEC-0012-US1-AC1]], [[indexing-pipeline-architecture#^SPEC-0012-US1-AC2]], and [[indexing-pipeline-architecture#^SPEC-0012-US1-AC3]].

## Change Rules

- Add a new high-volume durable write to the queued writer unless it is provably outside the hot indexing path.
- Add provider-backed indexing work through `pkg/app/semanticruntime` compatible lanes when a shared runtime exists.
- Put any cross-file or final-state-dependent work behind an explicit barrier and named timing label.
- Keep typed-note primary body evidence in `ontology_node`, and raw authored-section chunks in `authored_section` only for compatibility/eligible raw paths.
- Preserve `MarkNoteLastSync` as a success-only marker: an interrupted final flush must make the next run retry unfinished semantic work.
- When a phase broadens scope because of schema, primary format/context, or scope-config changes, make that expansion visible through progress/timing labels.
