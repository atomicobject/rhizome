10. 120.0% [doc_section] Scope (docs/reference/subsystems/graphql-query.md)
  120.0% chunk 1 - Scope
      The typed query layer executes read-only GraphQL-shaped queries over the note graph.
      `pkg/ontology/query` compiles the ontology schema into executable SDL and resolves
      roots/selections; `pkg/ontology/pushdown` decides which filters/sorts can be served by
      the indexed SQLite read model versus evaluated residually in memory;
      `pkg/ontology/queryrecipe` loads, validates, binds, and compiles saved deterministic
      recipes that skills and views invoke by id. The ontology core (schema compile, indexing,
      edges) is upstream — see [[ontology]]. Relation scheduling, hydration, batching, and
      limits are owned by `noderead` — see [[noderead]]; this layer compiles selections into
      a `noderead.NodeReadPlan` rather than reading SQLite/files itself.

      Entry points: `query.BuildExecutableSchema`, `query.Prepare` / `PrepareWithVariables`,
      `query.Execute` (`pkg/ontology/query/schema.go`, `prepare.go`, `execute.go`);
      `pushdown.Planner` (`pkg/ontology/pushdown/planner.go`);
      `queryrecipe.LoadDefaultSources` / `Validate` / `BindVariables` / `Compile`
      (`pkg/ontology/queryrecipe/load.go`, `validate.go`, `bind.go`). CLI surfaces: `rzm agent
      ontology-query` / `ontology-query-schema` (`cmd/agent_ontology.go`,
      `cmd/ontology_query.go`) and `rzm query-recipe` / `rzm agent query-recipe`
      (`cmd/query_recipe.go`). MCP: `pkg/app/mcp/tool_ontology.go`. Web/public API:
      `pkg/app/web/ontology.go`, `public_api.go`.

12. 120.0% [doc_section] Must-dos when changing this subsystem (docs/reference/subsystems/graphql-query.md)
  120.0% chunk 3 - Must-dos when changing this subsystem
      - New root, argument, filter op, or field capability: it must appear in the generated
      SDL (`schema.go`), pass `Prepare` validation, survive introspection, and show up in
      `ontology-query-schema` / authoring-guide output. A capability that executes but does
      not introspect is invisible to agents and therefore broken. - Pushdown changes: add
      equivalence coverage proving pushed and residual paths agree (extend
      `pkg/ontology/pushdown/planner_test.go` and the end-to-end cases in
      `pkg/ontology/query/query_test.go`). Check both consumers — views and GraphQL —
      since they share the planner. - Recipe envelope or binding changes: update
      `Validate`/`Compile` so `rzm agent validate query-recipes` catches the new failure mode,
      and migrate or explicitly reject existing recipe files (the apiVersion bump precedent in
      `queryrecipe/types.go` documents the pattern). - New limits or warnings: prefer
      structured warnings over silent narrowing/widening; keep ordinary roots quiet and put
      explanation behind `ontology.queryPlan(...)` diagnostics. - Keep
      `pkg/ontology/query/CONTEXT.md` and [[ontology-graphql-query-contract]] in sync with
      behavior changes; CLI/MCP descriptions (`cmd/agent_ontology.go`,
      `pkg/app/mcp/tool_ontology.go`) follow. - Run `go test ./pkg/ontology/query/...
      ./pkg/ontology/pushdown/... ./pkg/ontology/queryrecipe/...` plus `go test
      -tags=integration ./...` when execution or recipe surfaces change.
