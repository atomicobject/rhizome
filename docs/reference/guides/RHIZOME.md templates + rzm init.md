# RHIZOME.md templates + rzm init

## Summary

The core Rhizome guidance is generated by `rzm init` from embedded Markdown template chunks and injected into managed blocks inside `AGENTS.md` / `CLAUDE.md`. Template edits happen at source, then rerunning init refreshes the generated blocks through the diff/rejection workflow.

## Source of truth

- Core guidance templates: `docs/rhizome-md-templates/*`.
- Loader: `pkg/app/cli/init/agents_templates.go`.
- Renderer: `pkg/app/cli/init/rhizome_md.go`.
- Agent-doc writer: `pkg/app/cli/init/agent_surfaces.go`.
- Template-specific managed block source: `pkg/app/cli/init/templates/starters/agentic-engineering/agents/AGENTS.md`.

## Managed fences

- Core Rhizome block: `<!-- BEGIN RZM INIT RHIZOME BLOCK -->` / `<!-- END RZM INIT RHIZOME BLOCK -->`.
- Workflow template block: `<!-- BEGIN RZM INIT TEMPLATE BLOCK: agentic-engineering -->` / `<!-- END RZM INIT TEMPLATE BLOCK: agentic-engineering -->`.
- Existing `spec-driven` fences are migration input: managed fences normalize to `agentic-engineering`; ejected legacy fences remain preserved as frozen content.
- Legacy fences (`<!--- RHIZOME START -->`, old managed-agent block, and standalone generated `RHIZOME.md` redirect prose) are stripped before current blocks are rendered.
- Repo-specific instructions belong outside managed fences in `AGENTS.md` / `CLAUDE.md`.

## Refresh behavior

- `rzm init` refreshes managed agent-doc blocks on rerun when agent surfaces are enabled.
- Template-doc scaffold files are create-only by default; `--refresh-docs` offers updates to existing starter docs under the same ownership rule.
- A managed block someone edited is kept unless a person in a terminal takes the update; `.rhizome/generated-files.yml` records what Rhizome wrote and any declined version.
