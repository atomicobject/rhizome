## Plan

### Current gap

Measured and read on 2026-11-09 at `8093fc0b3` (SPEC-0136 Summary and R8 cite the lines): a new iframe per subject and per tab, reloaded on every tab return; the Tailwind compiler in every frame and kit assets without validators; no shared cache and no trustworthy generation; no way for a view to fill the sidebar; and query-layer costs that dominate the AO KB views (relation-list SQL off its index above about 150 parents, capability-only `workspace` selections building whole workspaces, per-prefix symlink resolution, silent filter misses and caps).

### Decisions settled

- Experience identity is a views folder with `experience.yml` (Drew, 2026-11-09); the panel is a view with `mount: { kind: panel }`.
- One frame per experience per window in a host frame layer, with pages per tab inside it (council round 1, Opus B1). The tab model does not change.
- The generation is composite and its write counter lives in the store's single write path (Fable B3, Opus B2).
- Folder starts minimised (Drew, 2026-11-09).
- Aggregates and computed-relation pushdown are deferred (council round 1).

- **Ownership:** `pkg/store/ontology_neighborhood.go` and the `VALUES` joins in `intel_query.go` and `ownership_transition_lookup.go`; `pkg/ontology/noderead/neighborhood.go`; `pkg/ontology/query/workspace.go` and the capability path in `pkg/ontology/node_workspace.go`; `pkg/paths/physical.go` (a prefix cache with an exported reset that P2 calls when the generation's `config` part changes); `pkg/ontology/pushdown/planner.go` (unknown and computed-relation filters become errors); truncation reporting in `pkg/ontology/query/execute.go`, `prepare.go`, `roots_graph.go`; a note-reader counter for tests.
