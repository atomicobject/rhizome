## Plan

### Architecture

The views are TSX sources under `web/bundled-views/group/`, so they get the web toolchain's lint, typecheck, and Vitest. The kit build copies them, without test files, into `pkg/app/web/assets/dist/bundled-views/`. The Go server loads that embedded folder as a third catalog source beside authored and generated entries, and serves it through the existing custom-view transform and shell. A development override can serve the folder from disk. A repository view with the same id shadows a bundled one, and `rzm view eject` copies the folder into `.rhizome/views/`.

Data comes only through public surfaces:

| Data | Surface |
| --- | --- |
| Group membership | `GET /api/v1/display-groups` |
| Schema | Type documentation, enriched with enum `@view` metadata, `@requiresWhen`, the effective summary field, and the parent role |
| Records | GraphQL with `updatedAt` and `issueCount` |
| Boundary | GraphQL neighbors |
| Validation | Validation summaries |

Freshness works as follows:
- The host forwards its event stream to hosted frames by `postMessage`, so frames open no event stream of their own.
- The kit invalidates by event class.
- A `views.changed` server event replaces the per-frame folder poll for hosted repository views.

The shared derivations port a throwaway prototype (kept outside the repository) into typed, tested modules.
