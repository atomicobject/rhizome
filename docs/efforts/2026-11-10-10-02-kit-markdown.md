## Plan

### Public API

Basic use:

```tsx
import { Markdown } from "@rhizome/kit";

<Markdown source={record.content} />;
```

`Markdown` takes `source`, optional `className`, `resolveLink`, `skipTitle`, and `mark`. `resolveLink(target)` returns the existing `{ node, view? }` navigation identity. An absent resolver leaves internal links as labels while their data loads. A resolver returning no target shows an explicit unresolved state.

`markdownLinks(source)` returns authored internal links in source order as `{ target, offset }`. An offset is a UTF-16 position in the exact input string. `mark` takes `{ at, label, ref? }`, using that position to mark the innermost rendered block holding the link. Parser trees and parser configuration stay private.

### Design decision

Reuse the host renderer behind a small kit component. One internal Markdown plugin handles note links, and one source-position selector identifies a rendered highlight target. Retain the host's GFM, lazy syntax highlighting and Mermaid support, and share its prose stylesheet with the kit.

The independent comparison found that a tight list drops its paragraph element during Markdown-to-HTML conversion. Selecting the actual rendered block by source offset handles tight lists without a second public block-numbering scheme. The source URL carries the assertion identity, so replacing the recomputed paragraph index requires no URL or persisted-state migration.

Keep the current content rules. Raw HTML remains literal, unsafe URL schemes are inert, and images do not introduce uncontrolled relative or remote loads. Asset rendering needs separate scope. Whole documents are parsed together, including reference definitions, code fences and loose lists spanning blank lines.
