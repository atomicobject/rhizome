# AO KB side-by-side adoption

## Scope

Deliver the whole first milestone of SPEC-0133: Batches 1 through 5. Rhizome reads an existing AO KB repository's knowledge (Markdown) and one selected product's model (YAML, plus referenced generated JSON) without rewriting authored files. AO KB skills keep ingestion, curation, model changes, artifact generation, and publishing. Rhizome adds a Knowledge workspace (Attention, Concepts, Assertions, Trace) and record presentations.

Excluded, as the spec's Non-Goals state: evidence weighting, curation, YAML/JSON writes, editing provenance-sensitive fields, rebuilding AO publishing, a provider plugin SDK, an expression language, a new scheduler, YAML-to-Markdown migration, and inferred links. Simultaneous multi-product browsing is excluded; one selected product per vault is the accepted scope.

## Plan

The plan is SPEC-0133's "Proposed delivery plan", Batches 1 to 5, unchanged. Execution splits each batch into lanes with separate file ownership, run as delegated workers in their own worktrees and merged into this branch by the coordinator. The Batch 1 exit includes the foundation review the plan requests before dependent work builds on the structural model.

Wave 1 lanes: (A) structural facts, read/mutation capability split, and Markdown adapter parity; (B) read-only source ownership and mutation admission; (C) the AO KB starter's knowledge types, recipes, and a synthetic Markdown AO fixture; (D) owner-local nested property paths. Later waves: Knowledge workspace views, YAML/JSON providers, the binding compiler and model bindings, and side-by-side proof.
