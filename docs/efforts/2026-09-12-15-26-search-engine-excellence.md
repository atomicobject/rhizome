### Evaluation protocol used throughout the effort

**Corpus composition.** Start with at least 320 independently judged queries across four corpus families: the Rhizome repository; redistributable polyglot code fixtures using currently supported capabilities; a prose knowledge vault with realistic competing topics; and a fixture vault exercising typed notes, embedded nodes, historical material, and overlapping titles. Allocate 80 queries per corpus and stratify the total into 64 navigation, 64 structural precision, 96 conceptual discovery, 48 multi-facet/task-evidence, and 48 no-answer or ambiguous-target controls. The failure-injection matrix below is additional correctness coverage, not a substitute for relevance judgments. Within controls, include at least 24 truly unanswerable queries.

Split approximately half into development and half into held-out sets by source/topic cluster, then verify that every family and corpus is represented. Near-duplicate questions, the same symbol under a paraphrase, and closely related source clusters stay on one side. Keep the original SQ and audit cases in the openly known regression set; they cannot establish held-out quality. Expand the initial corpus if needed to provide sufficient cases for a metric. Do not lower a target because a small denominator makes it demanding.

**Judgment records.** Each case has an ID, corpus/source revision, query/facets, intended task, expected target/ambiguity, effective controls, required source/role sets, and source relevance grades: 0 irrelevant, 1 tangential, 2 useful supporting evidence, 3 directly answers the need. A grade is source-owned and includes a short evidence rationale and locator. Record the judgment method and any uncertainty. Relevance judgments for a returned source absent from the initial pool must be added through blinded source assessment, not automatically treated as irrelevant. Freeze the assessed pool and rerun both baseline and candidate if it expands. Report unjudged returned sources; a run with material unjudged top results is incomplete. Keep corpus, queries, relevance judgments, and result files separable, following the reproducibility pattern demonstrated by the [BEIR authors' evaluation tooling](https://github.com/beir-cellar/beir); adopting its runtime is not required.

**Metric definitions.** Rank metrics operate on unique canonical source owners, preserving embedded-node distinctions where the task addresses the embedded node. nDCG@10 uses gain `2^grade - 1`, logarithmic discount, and the judged ideal ordering. Compute conceptual macro averages over the defined query families, and also report per-corpus and per-family values and sample sizes. A corpus/family cell with at least ten eligible cases must satisfy the spec's cell floor; smaller cells remain visible and qualified. Required-source recall@20 divides retrieved required eligible sources by the case's judged required eligible sources. Structural purity checks actual requested relationship kind separately from recall.

Navigation success@1/@3 uses eligible unambiguous targets; ambiguous, missing, and unsupported queries remain in their own scored control reports. Must-read precision counts selected grade-2/3 sources over all selected must-read sources; empty selection on an answerable case scores zero usefulness and cannot improve the macro score. Required-role coverage counts roles backed by relevant sources over required roles. High-confidence precision is the fraction of high-confidence cases with a relevant sufficient answer and no falsely claimed exactness; confidence coverage is high-confidence cases over eligible answerable cases. Report source precision, coverage, confidence coverage, and abstention together. Zero high-confidence output is not evidence of excellent calibrated confidence. Retain at least fifty scored high-confidence cases across the combined evaluation set before making a numerical calibration claim; expand the evaluation if needed.

**Semantic evidence.** Maintain deterministic, no-network fixtures for merge, filtering, source identity, exactness, cancellation, and cursor tests. For semantic quality, use a replayable artifact of real document and query embeddings with immutable provider/model/dimension/input fingerprints, or a documented live run. Keep artifact size within repository policy and use an established artifact mechanism if needed; do not invent credentials or depend on an agent's local cache. Record the artifact checksum and retrieval instructions. A changed chunker, corpus, or model invalidates the corresponding embeddings. Test live provider integration separately so replay does not conceal a broken production lane.

**Performance workload.** Freeze a standard manifest with at least 5,000 source owners and 50,000 searchable chunks, representative code/prose proportions, path/type selectivity, graph density, and query distribution. It may include deterministic distractors for scale, but synthetic content is not semantic relevance evidence. Run the same manifest and machine before/after each optimization. Per profile/workload collect at least 200 warm observations after twenty excluded warm-ups, plus thirty cold-start observations. Report cold definition, p50/p95/max, sample size, errors/deadlines, stage durations, provider time/calls, candidates, body reads/bytes, and process memory. Run concurrency one and four with the same query mix; include failed/time-limited requests in failure accounting rather than dropping them from latency claims.

**Tuning discipline.** Use development cases for query analysis, weights, thresholds, graph policy, candidate bounds, and profile defaults. Keep a small experiment log of hypothesis, changed variable, quality effect by family, latency/cost effect, and decision. The held-out run is Phase 9 acceptance. If an inspected held-out failure drives a fix, that case becomes regression/development evidence; collect a fresh uninspected cluster for the next acceptance run. Do not promote a model based solely on the nine original cases, a blended mean, or changed judgments that favor its ranking.
