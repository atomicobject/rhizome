## Original Intended Delivery

From any section, a person opens Chat beside what they are looking at, asks about it without describing it, and the agent reads the page or acts on it, interrupting only for risky actions. The conversation continues on the Agent page.

## Actual Delivered

All four stories are delivered on `t3/context-aware-ai-chat`.

- US1: Chat is a tab of the app's one right pane (`ChatDrawer.tsx`, `NotesRightRail.tsx`, `shellPanes.ts`). The top bar's far-right button, `]`, and ⌥⌘B work in every section; ⌘B toggles the sidebar. Outside a note or record the pane shows only once Chat is chosen, so Home and views keep their width (spec revised to say so). The Agent page has no right pane. Rhizome Desktop has a toolbar toggle that follows the page's `paneCollapsed` report, a View menu Show Chat on ⌥⌘B, and the sidebar accelerator on ⌘B.
- US2: the composer chip names the view by title (`chat/viewContext.ts`); `agentchat` validates the context, stores it on the message (nullable column migration), and prefixes a `[Rhizome view]` block to the turn. The `rhizome_page` MCP server (`rzm agent page-mcp`) posts to a token-authenticated relay that publishes a transient SSE `page-request`; the window showing the chat answers with the section's visible text, skipping the chat, hidden tabs and panels, and hidden frames, and reading `display: contents` wrappers child by child.
- US3: harness permission mode `auto` maps to Claude `--permission-mode auto` and Codex on-request/workspace-write with `approvalsReviewer: auto_review`, and is the chat default; `page_text` is pre-approved for both. The pane's transcript shows commands, edits, tool calls, and page reads as one line each, escalations as Allow/Deny cards that collapse once decided, and Stop while a turn runs.
- US4: the pane's first message creates an Agent session kept across reloads; Open in Agent links `/agent?session=`; New chat starts over; an archived session resets the pane. The Agent page and the pane share `useAgentThread`.

Verification: web unit tests (273 files, 2,238 tests), `make check`, `make web-e2e` (166, 90, and 81 passed across projects), `make desktop-check`, and live Codex sessions in auto mode that answered about a note, a view, and the Atlas, read the page through `page_text`, and raised no approvals.

## Deviations

- Screenshots, shown in the mockup, are a follow-up phase: the web has no capture library, and Rhizome Desktop's web view needs a native snapshot. Page text covers on-demand reads in this effort.
- US1 revised during delivery: outside a note or record the pane shows only once Chat is chosen, instead of opening everywhere.
- US2's requirement on page text narrowed: the relay keeps none, and the tool result is transcript like any tool output.
