Rhizome 0.52 adds **experiences**: a folder of custom views that runs as one site inside the workbench. Two of them come with this release. Agentic Engineering repositories get a **Delivery** experience for shaping specs, choosing work and resuming efforts. The optional AO KB add-on gets a **Knowledge site** for reading an AO knowledge base. Rhizome Desktop now also runs on Linux, repository settings can be changed from the app, and a broad correctness audit fixes trust, data-loss and indexing bugs.

## Experiences

An experience is a folder of custom views with an `experience.yml`. It runs as one site in a long-lived frame per window, so each tab keeps its page as you switch away and back, and it can add a panel at the bottom of the Notes sidebar. Notes that no experience presents get the built-in Folder panel, which starts minimised.

Custom views also gained:

- **Markdown rendering.** `MarkdownDocument` and `markdownLinks` from `@rhizome/kit/markdown` render GitHub-flavored Markdown with highlighted code and Mermaid, resolve note links through the view, and can highlight the block that holds a chosen link.
- **Durable view state.** Workbench tabs keep their view's params, such as filters and selected items, across tab switches, closes and reloads.
- **A better switcher.** Custom views come first in the view switcher, and views that do not fit move into More.
- **Lighter pages.** Kit assets use a build-stamped path with immutable caching, and the kit ships a precompiled stylesheet, so an experience with `tailwind: false` loads no Tailwind compiler. Public GraphQL and view reads are cached per index generation, so panels running the same read share one execution.

## Agentic Engineering Delivery

The Agentic Engineering starter now installs a Delivery experience. Its home page shows a Shape, Build and Settle workflow map with counted groups: Shaping specs, Ready stories, Planned and Active efforts, Delivery history, and Current contracts.

- Select ready stories, individually or by spec, or select efforts, then copy one composed prompt for the installed skills. The prompt keeps exact paths and story locators.
- Spec pages show their acceptance criteria inline. Effort pages give a source-grounded resume brief, with the prompt and checklist beside the narrative.
- A Find and Recent panel provides contextual navigation.

Delivery reads what the repository records. It does not start agents, approve work or change lifecycle states, and missing evidence is never shown as approval or completion.

## AO KB Knowledge site

The optional `ao-kb` add-on reads an existing AO KB repository alongside AO's own skills. Its Knowledge site has:

- a KB overview with a topic map, sources by date and a kind-by-concept matrix;
- record pages for concepts, sources, artifacts and assertions, with bodies rendered as Markdown;
- a Review page for gaps, submissions and curation documents.

KB notes are editable through Rhizome's editors like any other note; YAML and JSON model records stay read-only. Legacy single-product KBs at AO schemaVersion 4 to 7 set up as knowledge-only. `rzm ao-kb check` and `refresh-bindings` report install, binding and index readiness separately.

Two general features support it:

- **Typed YAML and JSON records.** Files named by an include become read-only typed records, declared with `@source(shape: RECORD, ...)`, `@contains` and `@references`. They support keyed, composite or positional identity, nested children, references, GraphQL queries, search and a native record reader.
- **Source ownership.** `.rhizome/source-ownership.yml` marks paths owned by another tool. Rhizome refuses writes to them through every interface and shows the owner's reason in place of edit controls.

`@field(path: "a.b")` and `@link(path: ...)` also read nested frontmatter values.

## Rhizome Desktop

- **Linux.** AppImages for Ubuntu 24.04 GNOME on x64 and Arm64, with Secret Service sign-in (no plaintext fallback), app-owned CLI installation and signed in-app updates. Windows 11 x64 is built in CI but not published until Windows code signing is configured.
- **Repository Settings.** Settings has a tab for the window's repository, opened from the repository menu. It changes a set-up repository's workflow, add-ons, agents and search provider, lists the files each change writes before writing them, and applies them in one step. `rzm init --check --json` and `rzm init --json` report and apply the same settings.
- **Starter setup finishes itself.** Installed starters complete eligible setup and indexing through the runtime. Unfinished setup stays visible, with conflict and dependency reasons, Settings recovery and Retry.
- **No more dead ends.** When a folder's selected Rhizome can't serve it, the app offers to update the pin, use the app's Rhizome or choose another executable. An index written by a newer Rhizome shows "Index unavailable" with the reason instead of preparing forever.

## Agents and sandboxes

Sandboxed agents can now reach the repository's Rhizome runtime. `rzm init` allows loopback network access while commands stay sandboxed: `sandbox.network.allowLocalBinding` for Claude Code on macOS, and a `rhizome` permission profile in `.codex/config.toml` that admits only 127.0.0.1 for trusted Codex projects.

## Fixes

An audit of invariants the code relied on but never checked produced these fixes, among others:

- **Trust.** Repository and module custom views run only in a checkout trusted with `rzm trust`. Actions use the same trust rule as tasks and Desktop, so a subfolder or a forged `.git` file no longer inherits trust. `rzm serve --host` no longer lets a network peer reach the local API with a loopback `Host` header.
- **Data loss.** Property and tag edits refuse a note that changed on disk during the edit. `rzm init` stops when a managed block has no END marker instead of deleting the rest of the file. Settings writes lock and reread `~/.config/rhizome/config.yml`, keeping unknown keys and comments. Edits made during Discard are refused instead of wiped.
- **Index and search.** Index writes no longer commit ahead of writes they depend on, so code chunks and embeddings stay attached to their anchors. Search hits show the section they matched, and a line starting with a tag is no longer treated as a heading.
- **Cancellation and overlap.** Fourteen fixes for interrupted or overlapping work, covering embedding setup, vault refreshes, approvals, chat interrupts, scheduled tasks and stale replies.

`rzm` and the team API gateway also build with Go 1.27.4, which fixes the net/http server crash in GO-2026-6859.

## Upgrading

- **macOS Desktop** updates itself. Homebrew users can run `brew upgrade --cask rhizome-desktop`.
- **Linux Desktop**: download `Rhizome-linux-x64.AppImage` or `Rhizome-linux-arm64.AppImage`, keep it at a writable path such as `~/Applications/Rhizome.AppImage`, and make it executable. Ubuntu 24.04 needs `libfuse2t64`.
- **Rerun `rzm init`** in each repository, after `rzm update` if the repository pins a version, to pick up the sandbox loopback settings, the Delivery experience and the other starter updates.
- **Trust custom views.** If a repository's own views now show a page naming `rzm trust`, run `rzm trust` in that checkout.
- **AO KB users**: run `rzm ao-kb refresh-bindings` to remove the add-on's former read-only declaration from an existing installation.
- **API changes**: the status API's `generation` is now an opaque string instead of an RFC3339 time. GraphQL responses carry `extensions.generation` and, for capped reads, `extensions.truncated`. GraphQL and view filters on unknown fields or computed relations now return errors instead of matching nothing. `frame` is a reserved view param name.
