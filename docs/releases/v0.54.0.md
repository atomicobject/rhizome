Rhizome 0.54 is a small follow-up to 0.53. It fixes a setup failure on Macs when a folder's capitalization differs from what a schema expects, lets the chat agent explain setup failures the app is showing, and tidies the Notes sidebar.

## Fixes

- **Setup no longer fails over folder capitalization.** On a case-insensitive filesystem, the macOS default, AO KB setup failed when its schema selected `MOCs/**/*.md` but the folder on disk was `mocs`. File path selectors and explicit note references now follow the filesystem's casing behavior, and returned paths keep the spelling on disk. Case-sensitive filesystems still keep `MOCs` and `mocs` as distinct files. Ordinary indexing refreshes the affected types; no rebuild is needed.
- **The Knowledge panel fits the sidebar.** A long Recent title or search query no longer makes the AO KB Knowledge panel scroll sideways. Long rows end in an ellipsis.

## Chat explains setup problems

When a starter's setup fails, is blocked, or is waiting on input, the app shows a banner such as "AO Knowledge Base · Setup failed". Chat now sees the same problems: each turn includes the module, its state and its reason while the banner is showing, so the agent can explain the failure and the fix instead of asking you to paste the error. Your message is stored as you wrote it.

## Notes sidebar

- **One bottom panel at a time.** A subject with an experience panel, such as a spec with Delivery, shows that panel in place of Files. Every other subject shows Files with the open note selected. Previously the Files panel stayed for good once opened, and experience panels stacked on top of it.
- **A denser Files tree.** Rows are smaller with a narrower indent, and a note's icon takes the caret slot, so deep paths no longer push file names off the edge.

## Upgrading

- **macOS Desktop** updates itself. Homebrew users can run `brew upgrade --cask rhizome-desktop`.
- **Linux Desktop** updates itself in the app, or you can download the new AppImage.
- **Repositories**: accept the app's "Update to X" offer, or run `rzm update`, and commit the refreshed agent files. No index rebuild or migration is needed.
