# Rhizome v0.51.0

Rhizome now comes as a Mac app. Rhizome Desktop puts your repositories, their worktrees, and the workbench in one native window, and it keeps itself and its bundled `rzm` up to date. This is also the first release published from the public `atomicobject/rhizome` repository, and the first built, signed, notarized, and published entirely by CI from a reviewed release pull request.

It covers three months of work since v0.50.5. The headline is the desktop app, but most of the workbench was redesigned along the way, Atomic Object staff can now sign in instead of managing provider keys, and repositories can run scheduled agent work and learn from past agent sessions.

## Install

On an Apple silicon Mac:

```bash
brew install --cask atomicobject/tap/rhizome-desktop
open -a Rhizome
```

The cask links the app's bundled `rzm` into your PATH. If you already have the CLI-only formula, uninstall it first with `brew uninstall --formula atomicobject/tap/rhizome`.

Without Homebrew, download `Rhizome-macos-arm64.dmg` below, drag Rhizome to Applications, and choose **Rhizome > Settings > Install Command-Line Tool**.

Linux, Intel Mac, and Windows users can keep using the CLI: `brew install --formula atomicobject/tap/rhizome`, or the archives and installer attached to this release.

## Rhizome Desktop

- **One window per repository.** ⌘O switches repository and ⇧⌘O switches worktree. Each worktree shows whether its runtime is running, and a repository's menu can open it in a browser, reveal it in Finder, or stop its runtime.
- **Signed, notarized, and self-updating.** The app is Developer ID signed and notarized by Apple. When an update is ready it offers Restart to Update; Check for Updates is in the app menu.
- **`rzm desktop [path]`** opens the current folder in the app from your terminal.
- Drag and drop, tables, cards, and boards work the same as in a browser.

## A redesigned workbench

The browser workbench and the desktop app share the same redesign.

- Choose a theme (Graphite, Slate, Spruce, Oxblood, or Indigo) and Light, Dark, or Match System appearance.
- One sidebar serves Notes, Ontology, Explorer, and Agent, and it stays where you put it. ⌘P finds notes and code files, tolerates typos, and favors what you opened recently.
- Collection views have a cleaner header with Find in view, Filter, and View menus. Tables keep titles readable and move columns that don't fit into the right pane.
- Every type opens on a **Briefing** that shows what needs attention, what is in motion, and what changed. All notes opens on a Briefing too, so it no longer freezes on a graph of every note.
- **Explorer** shows the whole vault: every note and code file is counted, large folders are grouped instead of cut off, and links between code and notes are drawn.
- Notes read more calmly, pages stop flickering while they load, and large vaults load the ontology and Explorer noticeably faster.

## Sign in instead of managing keys

Atomic Object staff can run `rzm auth login`, or choose **Sign in with Atomic Object** in the desktop app, to use Voyage embeddings and Jev through the team server. No `--server` flag or personal provider keys are needed. Desktop Settings shows which provider each repository actually uses, and you can still bring your own keys or import them from a 1Password Environment.

## Agents that do recurring work and learn from past sessions

- **Scheduled tasks.** Declare periodic agent work in `.rhizome/tasks/*.yml`. Rhizome runs it on each teammate's machine in their own Claude Code or Codex, after a free check decides whether the work is needed. The Tasks page shows each task, its run history, and what each run changed, and **Test once** tries a task before you merge it.
- **Compounding add-on.** `rzm init --add-addon compounding` reviews your past Claude Code and Codex sessions in a repository and proposes fixes, documentation edits, guard rules, and context shards. With `rzm init --hooks on`, approved shards reach agents as they read and edit the files they apply to, and approved guard rules block matching tool calls before they run.
- **Modules.** Each starter now installs as a module under `.rhizome/modules/<name>/` holding its ontology, query recipes, views, tasks, actions, and scripts. `rzm init` moves files from earlier installs into place.

## Search, views, and authoring

- Search finds a note by the words other notes use when they link to it, and ranks title matches for short queries more sensibly.
- Custom views can render live Mermaid diagrams, run module actions, and keep their state in the URL.
- Note interfaces in your ontology get typed GraphQL roots, so a shared collection such as `meeting` can filter, sort, and page across its concrete types.
- `rzm` commands work from any subdirectory of a repository.
- `rzm init` reruns show a change list and ask once, and they only ask about generated files someone has edited.

## Faster and steadier

- Rhizome no longer re-embeds text it has already embedded, and a cold embedding pass on a fresh worktree no longer floods the indexing queue.
- Idle runtimes do much less background work, and an open browser tab or desktop window keeps its runtime alive.
- Open note tabs use much less memory. Recent tabs stay ready, and older ones keep their place and reading position.
- `rzm diagnostics perf` summarizes the last day of runtime and web UI performance offline.

## Upgrading

- **Removed commands.** `rzm code index` and `rzm code index-anchors` are gone; `rzm index` refreshes code and notes together. `rzm note rename-heading` no longer accepts `--upgrade-to-block-id` or `--fallback`, and it never adds block IDs.
- **One-time refresh.** Each repository rebuilds its derived ontology data once on first use after upgrading. Nothing is re-embedded.
- **Rerun `rzm init`** in each repository to move starter files into modules and pick up updated agent skills. Commit the result so teammates share it.
- **Homebrew users** moving to the desktop app should switch from the formula to the cask as shown above.
