# Reconciliation

Reconcile verified implementation reality only when reusable knowledge changed. For an effort, load `query-recipe run --id closure-drift-pack` when equivalent current context is not already available, and refresh sections changed since retrieval. Choose the smallest durable home: governing spec, reference doc, code-adjacent rationale, a `docs/engineering/` concern document when team policy changed, or skill. Keep findings that matter only to this effort in its execution notes.

Consult `docs/engineering/documentation.md` for which surfaces must carry the change. Use `query-recipe run --id frozen-spec-detail-pack` only before editing full requirement or story text. Cite the finding or deviation each edit resolves; do not use a closure note as a dumping ground. When reusable knowledge did not change, create no documentation artifact.

Closed efforts are historical record: append post-closure-prefixed notes rather than rewriting frozen scope, plans, or delivery baselines. Keep original intended delivery intact and reconcile differences in actual-delivered truth.

Separate mechanical clarification from a product or policy change. Record an already-approved change; ask for the accountable decision only when one has not been made. Effort-specific rationale stays in execution notes.
